# SWORD2 — правила репозитория

SWORD2 — архитектурная реорганизация SWORD: движок SWORD, игра SWORD, пекарня (Baker). Все решения, устройство и
этапы — в [ARCHITECTURE_PLAN.md](ARCHITECTURE_PLAN.md). Этот файл — короткие правила; подробные правила подсистем —
во вложенных `AGENTS.md` рядом с их кодом.

## Соглашения

- Все текстовые файлы — CRLF, в том числе новые. Не переводить файлы из CRLF в LF. Скрипты `.ps1` — UTF-8 с BOM
  (так их правильно читает Windows PowerShell 5.1), остальное — UTF-8 без BOM.
- Каждая механика — модуль с md-документом: назначение, настройки, зависимости, ограничения, известные ошибки.
  Документ обновляется при каждом изменении поведения или интерфейса модуля.
- Модуль либо есть, либо нет: без модуля его функции в игре нет, и игра стартует. Кода, который работает только
  в отсутствие модуля, нет (решение 9).
- SWORD — источник идей, а не образец: со SWORD не сравниваем, тесты SWORD не переносим, решения свои; живой рэгдолл
  не переносится.
- SWORD (`D:\Work\Visual Studio\SWORD`, коммит `2eab13b`) заморожен: его не менять.
- Метод, который вызывается раз в тик или кадр и содержит долгий цикл, — тело цикла в отдельный метод (иначе OSR —
  рывок на главном потоке); `AggressiveOptimization` — только тонкому методу из вызовов или примитивному циклу без
  пользы от PGO (подробно — AGENTS.md Runtime).

## Слои

Зависимости только вниз (раздел 4 плана). Движок (`engine/`) не знает игру и инструменты, игра (`game/`) не знает
инструменты (`tools/`). У каждого проекта движка, игры и инструментов в `.csproj` задана сторона `SwordSide`:
`Neutral` видит только нейтральное, `Simulation` не видит клиентское, `Client` видит всё. Проверки:
- сборка — `Directory.Build.targets`, ошибки SWORD001–003;
- полная матрица ссылок — `tests/Sword.Architecture.Tests`; новый проект — строка в `ArchitectureRules.Matrix`
  и в таблице раздела 4.

## Сборка и проверка

```
dotnet build SWORD.slnx
dotnet test SWORD.slnx
powershell -NoProfile -ExecutionPolicy Bypass -File tools/scripts/verify.ps1 [-Json] [-SkipReference] [-Configuration Release] [-Only шаги]
```

`verify.ps1` — сборка, тесты, заготовки запрещённых ссылок, переводы строк, эталонный пак. `-Json` — итог одним
JSON-объектом для агентов. Полный прогон — в Debug (проверки мира ECS есть только в Debug); время бюджетов
проверяется только в Release — там достаточно замеров: `-Configuration Release -Only headless-smoke,app-smoke,features`.

## Пак контента

Контент игры — закреплённый пак `Content.reference.swpak` (вне git, только для чтения). Его целостность —
`tools/scripts/reference.ps1 -Check` (шаг `reference` в `verify.ps1`); описание — `tests/reference/reference.json`.

## Приёмка фичи

## Агентские инструменты

При любом изменении кода — проверить, сможет ли агент увидеть, проверить и отладить изменение имеющимися
инструментами; если нет — добавить вид, инвариант или инструмент в том же изменении (чек-лист — раздел 8 плана).
Итог анализа записывается всегда: в md фичи и в отчёте о приёмке.

Агентский доступ: `.mcp.json` (`sword-headless`, `sword-app`), рецепты — `docs/agent-playbook.md`; новый инструмент —
с тестом и строкой в playbook.

Правки этого файла агент предлагает, человек принимает.
