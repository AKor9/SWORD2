# SWORD2 — правила репозитория

SWORD2 — архитектурная реорганизация SWORD: движок SWORD, игра SWORD, пекарня (Baker). Решения и устройство — в
[ARCHITECTURE_PLAN.md](ARCHITECTURE_PLAN.md). Этот файл — короткие правила; правила подсистем — во вложенных `AGENTS.md`.

## Соглашения

- Все текстовые файлы — CRLF, в том числе новые. Скрипты `.ps1` — UTF-8 с BOM (их так читает Windows PowerShell 5.1),
  остальное — UTF-8 без BOM. `sed -i` и запись файла целиком дают LF — проверять `verify.ps1 -Only line-endings`.
- README модуля или фичи — только текущее состояние, коротко: назначение, настройки, ограничения, «Что проверить в игре».
  История не ведётся по шагам; прошлое, которое стоит сохранить, — в `docs/history/` (перенос, не удаление).
- Вложенный `AGENTS.md` — 10–30 строк: инварианты, команды проверки, типичные ошибки.
- Комментарии в коде — что и почему, коротко; без имён точек, этапов, истории и сравнений со SWORD.
- Модуль либо есть, либо нет: без модуля его функции в игре нет, и игра стартует (решение 9).
- SWORD (`D:\Work\Visual Studio\SWORD`, коммит `2eab13b`) — источник идей, заморожен: его не менять, с ним не сравнивать.
- Метод, который вызывается раз в тик или кадр и содержит долгий цикл, — тело цикла в отдельный метод (иначе OSR —
  рывок на главном потоке); `AggressiveOptimization` — только тонкому методу (подробно — AGENTS.md Runtime).

## Слои

Зависимости только вниз (раздел 4 плана). Движок (`engine/`) не знает игру и инструменты, игра (`game/`) не знает
инструменты (`tools/`). У каждого проекта в `.csproj` задана сторона `SwordSide`: `Neutral` видит только нейтральное,
`Simulation` не видит клиентское, `Client` видит всё. Проверки — сборка (`Directory.Build.targets`, SWORD001–003) и
`tests/Sword.Architecture.Tests`; новый проект — строка в `ArchitectureRules.Matrix` и в таблице раздела 4.

## Сборка и проверка

```
dotnet build SWORD.slnx
dotnet test <проект> --filter …
powershell -NoProfile -ExecutionPolicy Bypass -File tools/scripts/verify.ps1 [-Json] [-SkipReference] [-Configuration Release] [-Only шаги]
```

- В работе — сборка и тесты затронутых проектов (`--filter` по своим классам).
- Изменение поведения симуляции или хеша — ещё `verify.ps1 -Only headless-smoke,replay-smoke`; эталоны
  `tests/reference/replays` перезаписываются, если хеш меняется намеренно (в сообщении — какие участники и с какого тика).
- Полный `verify.ps1` (Debug) — перед крупным коммитом или по просьбе пользователя; замеры времени — Release, один прогон;
  сомнительный результат — вопрос пользователю, не перезамер.
- Команда дольше ~4,5 мин — фоном.

## Пак контента

Пекарня `sword-bake` (`tools/Sword.Bake`) печёт сырые исходники по рецептам `Bake/recipes` в игровые ресурсы `Content/`
по темам (вне git); менеджер ресурсов `sword-assets` (`tools/Sword.Assets`) собирает из них пак игры `Content.swpak`
в корне (вне git; выключенное из пака — `Bake/pak.json`). Путь в паке = путь в `Content/`. Пак читают игра, Headless,
тесты Content и эталонные реплеи; собран ли он из текущего `Content/` — шаг `content` в `verify.ps1`
(`sword-assets check`).
Рабочее дерево агента: `Bake/bake.user.json` — копия из основного дерева, свой `Content/` — `sword-bake --all`, свой
пак — `sword-assets pack`. Пак основного дерева не перезаписывать.

## Ход работы

- Задача → код и тесты свойств, которые проверяют поведение (не форму диагностического вывода) → проверка из раздела
  выше → пользователь проверяет в игре и коммитит сам. Изменения оставлять незакоммиченными, если не попросили.
- Видимые свойства, которых не увидит автоматическая проверка, — вопрос пользователю.
- README и вложенный `AGENTS.md` правятся в том же изменении, если поменялось поведение, настройки или правила.
- Крупная задача (несколько часов или несколько агентов) — до запуска оценка в cost и часах; превышение в 1,5 раза —
  стоп и вопрос пользователю. Workflow или больше двух агентов — только после «да» пользователя.
- Бриф исполнителю: цель, решения пользователя дословно, файлы, «готово, когда», «не делать». На ~250k контекста —
  передача ≤3 КБ и новый агент.

Правки этого файла агент предлагает, человек принимает.
