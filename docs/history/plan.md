## 1. Исходное состояние SWORD

~38 тыс. строк C#, .NET 10, D3D12 (Vortice), 18 проектов.

| проект | строк | что внутри на самом деле |
|---|---|---|
| Sword.Content | 1,1к | пак `.swpak`, `IContentSource` + форматы, **в т. ч. игровые** (`WeaponBloodFile`) |
| Sword.Engine | 2,7к | обёртка D3D12 (устройство, bindless, PSO, шейдеры, профайлер) — это **RHI, а не движок**; плюс `Tuning` |
| Sword.Engine.Ui | 3,1к | immediate UI, шрифты, HarfBuzz; **плюс запекание шрифтов** (`UiFontBaker`) |
| Sword.Engine.Platform.Win32 | 1,5к | окно, ввод, диалоги; **зависит от Ui** |
| Sword.Physics | 0,3к | `RigidBody`, `Xpbd` — **почти вся физика живёт в игре** (`DuelArena`, `Fighter.Joints/Muscles`, `KinematicContacts`) |
| Sword.Anim | 3,5к | клипы, IK, Motion Matching; **плюс игровой `SwordBody`** |
| Sword.Combat | 1,7к | риг, аниматор бойца, окна ударов, оружие, локомоция клипами |
| **Sword.Game** | **18,6к** | всё остальное: цикл, рендер сцены, скиннинг, GPU-заливка тел, бой, рэгдолл, ИИ, модули, HUD, редактор анимаций, бенч |
| Bake / Cli / Studio / Bake.Sword | 11,4к | пекарня — **лучшая часть архитектуры**: плагины, каталог, происхождение, `bake.imports.json` |

### Проблемы

1. **Нет слоя «рантайм движка».** Цикл, фиксированный тик, камера, рендер сцены, скиннинг, кольца констант —
   в `Sword.Game`. `Program.cs` (424 строки) вручную собирает мир, обрабатывает клавиши, крутит цикл, бенч и снимки.
2. **Модули привязаны к арене, а не к движку.** `GameModuleContext` отдаёт всё сразу (Device, Pipelines, Content,
   Scene, Arena, Rig, Characters). Модули подписываются на события `DuelArena` (`TickBegan/TickEnded`, `HitApplied`,
   `LimbDetachCaptured`, `BodiesPlaced`) и подменяют её стратегии (`DetachStrategy`, `Guard`, `BodyPlacer`).
3. **God objects.** `DuelArena` — ~1650 строк в 4 partial-файлах (правила, физика контактов, удары, трассы);
   `Fighter` — ~2040 строк в 6 (кинематика, рэгдолл, мышцы живого, шаги живого, суставы).
4. **Нет рендер-графа и API для GPU-симуляций.** `SceneRenderer` — фиксированные крючки `ISceneOpaque/ISceneComposite`
   с зарезервированными слотами корневых констант 10–12. Кровь и внутренности сами создают буферы, PSO и барьеры.
   Новой GPU-системе (песку) опереться не на что — вероятная причина неудачи.
5. **Зависимости не туда.** Platform → Ui; Bake.Sword (инструмент) → Engine.Ui; Content знает игровые форматы;
   `Sword.Game.Cutting` (контракт расчленения) лежит в игре, но им пользуются ядро арены, кровь и внутренности.
6. **Одна функция — две реализации.** Рельеф — в `Gameplay/Terrain.cs` и `Shaders/sim_common.hlsli`.
7. **Конфигурация — ~70 переменных `SWORD_*`**, прочитанных где попало (`Env.cs`, `Environment.GetEnvironmentVariable`).
8. **Тесты перемешаны.** `Sword.Anim.Tests` ссылается на пекарню и плагин (тесты glTF, пака, текстур, крови оружия);
   `Sword.Game.Tests` — вперемешку контакты физики, правила арены и модули.
9. **Остатки старого** (`OLD_CODE_AUDIT.md`): ветки живого рэгдолла, `tools/ue`, ~20 переменных «ручек» живого рэгдолла.

### Что сохраняем (хорошие решения)

- реестр модулей, «модуль выключается — игра живёт», md-документ у каждого модуля (правила `AGENTS.md`);
- проверка границ модулей сборкой без модуля (`-p:DisableCutting=true`, `-p:DisableTools=true`);
- пекарня целиком: плагины, `IAssetPreview` без знания форматов игры, каталог, происхождение, `strictLayout`;
- `ShaderContract` — константы C#↔HLSL из одного места; `SimLayout.Verify` — проверка раскладки GPU-структур;
- снимок бенча, прибитый к тику (`SWORD_SHOT_PIN`);
- бенч, трасса рэгдолла `RagTrace`, сцены `RagdollScene` (s1–s6, s8), ручки `TuningGroup` с сохранением в json;
- bindless, D3D12 Agility SDK app-local, версия в одном месте.
