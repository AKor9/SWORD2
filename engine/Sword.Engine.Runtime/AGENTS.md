# Sword.Engine.Runtime — правила

Симуляция без окна (раздел 7 ARCHITECTURE_PLAN.md), v0: `Simulation` — мир ECS со стадиями, фиксированный тик,
команды тика, ядро и статические модули, конфиг, экспорт тика.

- Стадии мира — служебная `runtime.commands`, стадии игры, служебная `runtime.export` (`Simulation.CommandStage`,
  `ExportStage`); служебные добавляет Runtime, модулям они недоступны (`SimulationBuilder.System` — только стадии игры).
- Всё, что меняет симуляцию на ходу, — команда тика (`Simulation.Enqueue`): в `runtime.commands` своего тика она
  становится событием `Event<T>` (`TickCommands`) — его видят все стадии игры в том же тике. Тип команды регистрирует
  ядро или модуль: `SimulationBuilder.Command<T>()`. Мир снаружи — только `WorldReader` (`Simulation.World`), и у
  владельца тоже: других путей изменить симуляцию нет (тест `OwnerSeesWorldReadOnly`).
- Ядро (принцип 4 плана) — не модуль: `Simulation.Build(config, stages, core, modules)`, регистрации ядра без токена
  модуля, выключить его нельзя (`modules.core` — неизвестная группа).
- Модули — `IModule` (`Id`, `Configure`). `Id` — строчная латиница, цифры и `_`, первой — буква (`IModule.IsValidId`):
  без точки, которая делит путь конфига, и без регистра; не имя секции движка (`sim`, `modules`, клиентские — `input`);
  иное — ошибка сборки симуляции.
  Выключенный (`modules.<id>.enabled=false`) не регистрирует ничего; системы включённого помечены его токеном
  (`World.SetModuleActive` — задел под деактивацию командой).
- Настройки модуля — секция с его `Id` (`SimulationBuilder.Settings<T>()`); у выключенного модуля она пропускается
  (`ConfigSet.Skip`), а не считается неизвестной. Переключатели модулей — секция групп
  (`ConfigSet.Groups<ModuleSettings>`): те же слои и та же строгость (переменная `SWORD_MODULES_<ID>_ENABLED`;
  неизвестный модуль и неизвестный ключ — ошибки). Сырого чтения конфига нет.
- Без модуля нет его компонентов, команд и экспорта: наблюдатели спрашивают `WorldReader.Knows<T>`,
  `Simulation.Accepts<T>`, `TickExport.Exports<T>` (у клиента — `SimulationLink`); команда без модуля — исключение.
- `SimulationBuilder` действует только до сборки мира: регистрация из `OnWorldBuilt` и позже — исключение.
- Конфиг — `ConfigSet`: код → `sword.json` → `sword.user.json` → `SWORD_<СЕКЦИЯ>_<КЛЮЧ>` → `--set`. Вложенные объекты
  сливаются ключ за ключом (`--set секция.объект.ключ`, `SWORD_СЕКЦИЯ_ОБЪЕКТ_КЛЮЧ`); ключ — только записываемое
  свойство; регистр имён не важен ни в одном слое (тот же ключ в другом регистре — тот же, действует последний); ключ
  дважды в одном файле, `null` или число вместо объекта — ошибки с путём к файлу. Неизвестные секции проверяет exe в
  конце композиции — `ConfigSet.Complete()` (секции читают и симуляция, и клиент); после него конфиг заморожен.
  Секции клиента движка — `ConfigSet.ClientSections` (`input`); exe без клиента (Headless) пропускает их
  `SkipClientSections()` — общий `sword.json` один на оба exe, а клиентских сборок Headless не видит. Итог —
  `Effective`, источники без повторов — `Sources`.
- Время тика — ресурс `SimTime`: номер, шаг, время — как `DuelArena.Time` SWORD (`+= dt` во float в начале тика). Шаг —
  `sim.tickRate` (по умолчанию 120, как `FastTick` SWORD).
- Экспорт тика (`TickExport`, стадия `runtime.export` — после барьера последней стадии игры): объявленные срабатывания
  (`SimulationBuilder.Export<T>`) копируются с номером своего тика в очередь кадра. Кадр начинает `BeginFrame()`
  (клиент — `SimulationClock`, Headless — каждый тик), записи кадра — `Frame<T>()`. Кто делает тики без
  `BeginFrame`, у того очередь растёт.
- Исполнять тики может только владелец `Simulation` (exe, клиент движка); клиентской части игры доступен узкий
  `SimulationLink` (Engine.Client).

Ограничения: переменная `SWORD_*` с опечаткой не находится (переменные ищутся по известным ключам, а общий префикс
`SWORD_` занят и переменными SWORD) — опечатки ловят файлы и `--set`. Группы `modules` знают только модули симуляции:
чисто клиентский модуль (раздел 7) потребует своего списка групп.

Не сделано: ГСЧ, реплеи и хеш состояния, `ObservationHistory` для агента (этап 3), деактивация модуля командой тика.

Проверка: `tests/Sword.Engine.Runtime.Tests` (конфиг по слоям и его строгость, модули, ядро, команды, края тика:
команда в первой стадии игры и событие последней стадии в экспорте своего тика, кадры с 0 и 3 тиками, время тика),
`tests/Sword.Engine.Client.Tests` (кадры через клиент), `verify.ps1` шаг `headless-smoke` (каждый модуль по очереди
выключен — 10 с игрового времени; опечатка в конфиге и выключение ядра — ошибки).
