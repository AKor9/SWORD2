# Sword.Engine.Introspection — правила

Общая основа агента и (позже) DevTools, без протокола: точка обслуживания (`ServiceQueue`, `ServiceContext`),
управление временем (`TimeControl`), разбор данных по полям (`FieldCodec`), имена данных мира (`Catalog`), запросы к
миру (`WorldQuery`), карта архитектуры (`ArchitectureMap`), имена сущностей игры (`IEntityNames`). Раздел 8 плана.

- К миру — только в точке обслуживания, на потоке симуляции, между тиками: запрос копирует данные
  (`WorldReader.Copy`) и может поставить команду на будущий тик (`ServiceContext.Enqueue`). Разбор и JSON — на потоке
  агента. Сохранять `ServiceContext` нельзя.
- Имена данных — стабильные (полное имя типа); короткое имя — удобство, неоднозначное — ошибка с перечнем.
- `FieldCodec` разбирает значение через упакованную копию (раскладку считает среда): поля в порядке объявления,
  автосвойство — именем свойства, `Entity` — `12v3`, нечисла — строками, перечисление — точным именем (не «A,B»)
  или объявленным числом; `[Flags]` — списком «A, C» или числом только из объявленных битов. Необъявленное значение
  из мира разбор показывает числом (записать его обратно нельзя — намеренно: запись только объявленных значений).
  float вне диапазона float — ошибка, а не бесконечность (бесконечность — только явной строкой `Infinity`). Ключ ручки
  (`Runtime.TuningKey`, 6е) — именем ручки «секция.ключ» (без учёта регистра; незаведённое имя — ошибка с перечнем ручек процесса;
  число — как есть), схема — перечень ручек. Ручки симуляции — `Catalog.Tuning` (`new Catalog(simulation)`): `world.types` показывает их у
  ресурса и у `TuningCommand`.
  `[InlineArray]` и `fixed`-буфер — массив всех элементов. Путь поля проекции — `FieldCodec.CheckPath` до запроса.
- `TimeControl.Stop` — конец симуляции: ожидания отменяются, новое ожидание недостигнутого тика сразу отменено.
  Headless зовёт его в конце `SimulationLoop.Run`, живая игра — при закрытии окна (вместе с `ServiceQueue.CancelAll`).
- Связи карты архитектуры — те же, что производители срабатываний в ECS (`Registration.Produces`): `Changed` даёт
  `Set`; `Add` — возможный производитель (при отключённых проверках ошибочный `Add` существующего тоже даёт `Changed`;
  штатно он запрещён).
- Произвольного кода нет: только копии и разбор.
- Язык условий (этап 3в) — `ObservationPredicate`: JSON-дерево из белого списка узлов (`Syntax`), компилируется в точке
  обслуживания (имена сущностей разрешаются один раз) в узлы, читающие листья полей по `FieldLayout`; три области —
  мир, сущность, запись журнала. Условие на сущность наверху — «есть такая сущность»; `for` — только в условии мира,
  его серия обновляется в `Evaluate` до корня (у всех окон, изнутри наружу): `all`/`any` не пропускают окно.
  Собранный в памяти JSON проходит через текст (int читается как число). Ошибка — `ArgumentException` с путём в условии.
- `ObservationHistory` — кольцо тиков с записями журналов, снятыми после тика по возрасту записей (1…число стадий) без
  своего курсора: мир и хеш от неё не зависят; событие без потребителя журнала не имеет и не видно. `ObservationHub`
  (наблюдатель `ISimulationObserver`) — история, наблюдения `Watch`, одно условие остановки: после тика или после
  барьера стадии (`BreakHandler` хозяина цикла — только Headless); попадание — `TimeControl.Halt` на этом тике.
  `Attach` к новой симуляции очищает историю, перепривязывает наблюдения, снимает условие. Поле наблюдения может быть
  вычисляемым полем игры (`ObservationHub.Fields` — `IEntityFields`, 5г): лист `F64` с компонентом −1, NaN — нет значения.
- `WorldSnapshot` — копии байтов в точке обслуживания, плоский вид (`12v3/Transform/Position.X`) — на потоке агента;
  `SnapshotDiff` — по ключам, числа с разницей и допуском. `ReplayObservation` — прогон реплея с наблюдением (события,
  наблюдение, условие; нарушения инвариантов — сводка и строки `InvariantViolation`) в отдельной симуляции.
- Инварианты (этап 3г): нарушения тика узел получает `OnViolation` (до `AfterStage` барьера) и кладёт в историю
  (`AddViolation` → слот тика в `Capture`; посреди тика — `Pending`). Остановка на нарушении — `ArmInvariant` (то же
  одно условие остановки): с `BreakHandler` — посреди тика после нарушившего барьера, без него — после тика.
  `AgentInvariant` — инвариант агента условием (`condition` мира или `must` на каждую сущность под `where`), владелец
  `agent`; узел хранит определения и включения (`SetInvariantEnabled`) и переносит их в новую симуляцию в `Attach`.
  `ServiceContext.Invariants` — реестр симуляции в точке обслуживания.
- Приёмка фич (этап 3д): `FeatureManifest` — `feature.json` рядом с md фичи, разбор строгий (неизвестный ключ, тип,
  ссылка на несуществующий сценарий — `InvalidDataException` с путём); `FeatureVerifier.Verify` — сценарии (реплей из
  репозитория или команды по тикам на конфиге из кода, всегда с записью) в отдельных симуляциях построителя
  `FeatureEnvironment.Build`: проверки — условия `ObservationPredicate` после каждого тика (`always`, `never`,
  `eventually`, `atEnd`), хеши реплея, нарушения любых включённых инвариантов — провал; инварианты манифеста включаются
  явно; метрики — `FieldProbe` (поле сущности, несколько листьев — длина вектора; путь, который понимают вычисляемые поля
  игры `IEntityFields` — `FeatureEnvironment.Fields`, `AgentHost.Fields`, 5б: тела бойца вне ECS, — читают они) после тика
  или статистика окна, ряд против трассы (`trace`, в float); 6ж — поле ресурса мира (`resource` вместо `entity`/`field`:
  `FieldProbe.OfResource`, путь — как у условия `{resource:…}`); бюджеты — отдельные прогоны без инвариантов, записи и сверки хешей (`Replay.Head(…,
  hashes: false)`), медиана повторов `SimulationMeasure` (мс на тик, мс стадий `StageTimer`, байты на тик), время — только
  при `Optimized`; кадр App (`budgets[].frame`, точка 4д) — делегат exe `MeasureFrame` над записью сценария (бенч,
  хеши App сверяются; 5г: `frame.overlays` — оверлеи игры на весь замер, разбор — как у видов), пределы — только при
  `Optimized`, без видов не меряется; виды — делегат exe `CaptureView` над
  записью сценария (5в: `views[].overlays` — отладочные оверлеи игры поверх кадра, строгий разбор имён, App — `--overlay`). Вердикт — список провалов словами, отчёт — `report.json`.
- Эксперименты (этап 3д) — `Experiments`: `Fork` (база и ветки параллельно, каждая — своя симуляция; сравнение записей
  `ReplayDiff`), `Compare` (и листья описаний разошедшихся участников на первом разошедшемся хеше), `Sweep` (круг прогрева —
  каждая комбинация по разу без замера, затем повторы по кругу комбинаций: JIT свежего процесса, 4д; детерминизм
  итогового хеша, первое резкое ухудшение масштабирования; реплей — без сверки хешей, как бюджеты). 6ж: перед повторами перебора и
  бюджета — прогрев до затишья JIT (`Diagnostics.JitWarmup`: сценарий без замера по кругу, ≤ 3 с; бюджет — `jitWarmup` в отчёте).

- Время систем (этап П, точка Па): `SimulationMeasure.Run(…, profile: true)` — прогон с профайлером CPU, `Systems` — мс
  зон `метка@стадия` на тик после прогрева. Бюджет фичи — после повторов ещё один такой прогон (`budgets[].systems`,
  `budgets[].profiled`; байты — тот же предел), перебор — круг после повторов (`SweepRow.Systems`, `systems: false` —
  без него): медианы и пределы — по-прежнему без профайлера (`StageTimer`).
- Машина (точка Пб): `SimulationMeasure.Machine` — снимки на границах замера (первый тик после прогрева и конец, вне времени
  и байтов тиков), счётный поток (доля CPU — критерий вердикта); бюджет — сумма повторов (`budgets[].machine`, `runs`), перебор —
  `SweepRow.Machine`; прогон с профайлером — `budgets[].profiled.runtime`. Вердикт не меняет пределы: провал времени бюджета
  дописывает его словами (« — машина: …», « — среда: JIT во время замера …»); кадр App — `FrameResult.Machine` из итога
  Sword.exe, так же.

- Причинность (6д) — `CausalityQuery`: в точке обслуживания по журналу причинности мира (`WorldReader.Causality`) — последние
  изменения поля сущности (записи `Add/Set/Remove` компонента; `Set`, не менявший листья поля, пропускается — по значениям до и
  после), цепочка каждого по родителям до корня (`Complete`) или до обрыва со словами (`Stop`: родитель вытеснен, глубже предела),
  регистрации, писавшие столбец на месте (`Writers` — грубо), объявленные производители из плана мира (`Producers` — и без режима).
  Только копии записей и значений; разбор в JSON — на потоке агента (`state.why`, `events.history`). `CausalityQuery.Source` —
  путь от папки репозитория и строка.

Проверка: `tests/Sword.Engine.Introspection.Tests`; причинность — `Sword.Game.Tests/CausalityTests` (нужна игра: бой).
