# Агентский доступ (точка 1е)

ИИ-агент (Claude Code, Codex, любой MCP-клиент) подключается к SWORD как к серверу MCP и сам принимает прототип:
двигает время, читает мир, отправляет команды, снимает кадр, разбирает устройство тика. Две точки входа:

- `Sword.Headless --agent` — симуляция без окна, MCP на stdio: клиент сам запускает процесс
  (`tools/scripts/agent-headless.cmd` собирает Headless в новый каталог `artifacts/agent-bin/headless/<запуск>` —
  работающий агент не держит ни обычный `bin/` (`dotnet build` не падает), ни каталог следующего сеанса; сборка не
  удалась — отказ, старая сборка не запускается (агент не проверяет не тот код); каталоги закончившихся сеансов
  убираются; `.mcp.json` → `sword-headless`). Стартует на паузе, время двигает агент.
- `Sword.exe --agent [--agent-port N]` — живая игра, MCP по HTTP на `http://127.0.0.1:47813/mcp`
  (`.mcp.json` → `sword-app`). Игра идёт как обычно; агент ставит паузу, шаги, команды и снимает кадр.

Код: `engine/Sword.Engine.Introspection/` (точка обслуживания, время, разбор полей, каталог имён, запросы, карта
архитектуры), `engine/Sword.Engine.Agent/` (хост: сеанс, инструменты, квитанции, MCP, транспорты, цикл Headless),
`engine/Sword.Engine.Agent.Client/` (агент в кадре клиента, `capture.bundle`, `render.graph`),
`game/Sword.Game.Agent/` (имена сущностей игры), композиция — `AgentMode.cs` в `Game.Headless` и `Game.App` (в сборке
`-p:WithoutAgent=true` их нет). Рецепты для агентов — [docs/agent-playbook.md](../../docs/agent-playbook.md).

## Устройство (раздел 8 плана)

- **Потоковая модель.** Протокол — на своём потоке; к миру он не прикасается. Запрос к миру ставится в очередь
  (`ServiceQueue`) и исполняется на потоке симуляции в **точке обслуживания**: Headless — после каждого тика и на паузе
  (`SimulationLoop`), App — раз в кадр после тиков кадра, и на паузе, и при свёрнутом окне, и пока тянут рамку
  (`ClientAgent.Serve` через `IClientTool`). В точке данные только копируются (`WorldReader.Copy`); разбор в JSON — на
  потоке агента. Исключение — пакет наблюдения: его JSON и файлы пишет поток кадра на границе кадра (снимок — вне
  бюджета точки). Бюджет точки: 50 мс на тик (Headless), 4 мс на кадр (App). Запрос, которого не дождались (таймаут,
  отмена), не исполняется вовсе — команда, на которую агент получил ошибку, не пройдёт позже.
- **Время.** `TimeControl`: пауза, запас шагов (`time.step`), цель (`time.runUntil`), ожидание тика; решение «пауза
  ли и сколько тиков» — атомарно (`Gate`). Headless играет столько тиков, сколько разрешено; клиент спрашивает ворота
  тиков (`ITickGate`): на паузе часы стоят, кадр показывает ровно последний тик (доля тика 1), шаги — не больше
  `sim.maxTicksPerFrame` за кадр. После каждого тика кадра клиент спрашивает `ITickGate.StopAfterTick`: пауза и
  условие наблюдения встают на своём тике, остальные тики кадра не играются; `time.pause` отвечает тиком, на котором
  симуляция встала. Снятие паузы сбрасывает запас шагов. Свёрнутое окно живой игры обслуживается, но тиков не
  играет — `time.step` ждёт, пока окно развернут.
- **Команды.** Только на будущий тик и не дальше 1 000 000 тиков вперёд — весь диапазон `repeat`, до постановки первой
  (`Simulation.EnqueueRaw`, байты по полям — `FieldCodec`: дробное в целое поле, неизвестное поле, не то значение
  перечисления — ошибка с путём поля; число перечисления — только объявленное, у `[Flags]` — только объявленные
  биты). В тике
  команды инструмента выдаются после команд клиента того же типа: где действует последняя команда тика
  (`PlayerCommand`), в живой игре агент перебивает ввод клавиатуры того же тика. `repeat` — одной постановкой:
  очередь команд по тику с курсором (`TickCommands`), тик берёт свои записи с головы — 100 000 тиков линейно.
- **Квитанция в каждом ответе:** `buildId` (exe, версия с коммитом, MVID), `contentHash` (оглавление пака), `sessionId`,
  `tickId` (сыграно тиков; посреди тика — номер идущего), `stage` (стадия останова `time.break`, иначе null), `frameId` (кадр клиента; у ответа о мире —
  вместе с тиком из точки обслуживания, `ServiceContext.Point`, а не текущий кадр), `complete`,
  `truncated`, `continuationToken` (`skip=N`, `after=N`), `artifactId`. `world.query` с `take` 0 (только число) —
  полный ответ без продолжения; пути `fields` проверяются по схеме полей до запроса (`Transform.Positoin.X` — ошибка с
  перечнем полей, а не пустой ответ). `ecs.explainSystem` связывает `Changed<T>` с `Set<T>` и, как возможного
  производителя, с `Add<T>` (как `Registration.Produces` в ECS: штатно `Add` существующего запрещён проверками, но при
  отключённых проверках ошибочный `Add` существующего заменяет значение и даёт `Changed<T>`); когда связь видна (`when`, `why`) — по стадии и виду: прямая запись
  колонки — системе позже по порядку, в том числе в той же стадии; команды (`Add`, `Set`, `Remove`, `Emit`, ресурсы) —
  на барьере после стадии производителя, в том же тике только для более поздней стадии (как проверка `NextTickOk`). `render.graph` — граф, размер, `frameId` и `tickId` одного показанного кадра (снимаются
  при показе, а не в точке обслуживания следующего кадра — та уже после его тиков).
- **Артефакты** — `artifacts/agent/<сеанс>/` в корне репозитория: `capture-<кадр>-<метка>.color.png`, `.depth.png`,
  `.bundle.json`.
- **Протокол** — свой минимальный JSON-RPC по спецификации MCP (решение точки 1е: официальный SDK тянет хостинг и
  внедрение зависимостей в exe игры): `initialize` (версии 2025-11-25, 2025-06-18, 2025-03-26, 2024-11-05; незнакомая —
  последняя своя), `ping`, `tools/list`, `tools/call`, уведомления `initialized` и `cancelled` (отменённый вызов —
  без ответа; отмена — в пределах своего сеанса транспорта; отмена, обогнавшая свой запрос — stdio исполняет строки
  параллельно, — запоминается на 10 с и отменяет вызов при его регистрации), пакеты (массив сообщений). На каждый запрос — ответ, в том
  числе при внутренней ошибке (-32603); `id` — строка или число (null — -32600); повтор ключа в объекте — не JSON
  (-32700); `jsonrpc` — ровно `"2.0"` (иначе -32600 с `id: null` и без `id` у сообщения: такое сообщение — не
  уведомление, а неверный запрос, JSON-RPC 2.0 отвечает на него); `params` и `arguments` — объект или ничего (иначе -32602).
  Аргументы проверяются до действия: неизвестный — ошибка (опечатка не превращается в значение по умолчанию), явный
  `null` — ошибка (не «не задан»), обязательный — задан. Ошибка инструмента — результат с `isError` и квитанцией; ошибка протокола —
  ошибка JSON-RPC. Ответ — `structuredContent` и тот же JSON текстом.
- **Транспорты.** stdio — сообщение на строку, ответы параллельных вызовов не перемешиваются; конец входа — вызовы,
  не закончившиеся за 2 с, отменяются. HTTP (Streamable HTTP без потока событий): `POST /mcp` с
  `Content-Type: application/json` (иначе 415 — страница браузера не пошлёт такой запрос без предварительного) →
  `application/json`, уведомление и ответ клиента → 202, `GET` → 405 (`HEAD` → 405 без тела), чужой `Origin` → 403, неизвестная
  `MCP-Protocol-Version` → 400, `Expect: 100-continue` → 100; сеанс — `Mcp-Session-Id`: выдаётся
  на успешный `initialize` (новый клиент получает свой; отвергнутый `initialize` номера не получает и места в реестре
  не занимает), DELETE его завершает и отменяет его вызовы (вызов сеанса с приёма идёт
  под токеном его завершения — отменяется и принятый до регистрации; завершённый не оживает), завершённый или незнакомый
  номер → 404 (клиент начинает заново), запрос без номера — разовый (curl, PowerShell), сеансов не больше 64;
  испорченный запрос → 400, простой соединения 2 мин, чтение запроса — не дольше 30 с, исполнение вызова — не дольше
  35 с (дольше — ошибка вызова `TimeoutException`; заказанное время — шаги, цель — остаётся, ожидание снимается);
  поэтому в живой игре `timeoutSeconds` у `time.*` и `capture.bundle` — не больше 30 с (`HttpTransport.MaxWait` →
  `AgentHostOptions.MaxWait`, схема инструментов показывает этот предел; Headless — 600 с). Закрытие окна отменяет
  ожидающие запросы и ожидания тиков — агент сразу получает ошибку, а не ждёт таймаут. Только
  127.0.0.1; свой HTTP/1.1 на
  `TcpListener` (http.sys без прав администратора резервирует не всякий адрес).

## Инструменты

| группа | инструменты |
|---|---|
| сеанс | `session.status`, `session.stop`; `session.start(replay, set)` — новая симуляция на тике 0 из конфига запуска или реплея (только Headless; запись прежней — в артефакты) |
| время | `time.pause`, `time.resume`, `time.step(ticks)`, `time.runUntil(tick | condition, maxTicks)` — с условием встаёт на паузу ровно на тике выполнения (и в живой игре); `time.break(stage, condition)` — останов посреди тика после барьера стадии (квитанция со `stage`, команды — на следующий тик; только Headless); `time.seek(tick)` — вперёд тиками, назад пересборкой и повтором таймлайна (прежнее будущее повторяется, команды агента на несыгранные тики сбрасываются; таймаут — ошибка с достигнутым тиком; только Headless) |
| реплеи | `replay.status` — запись сеанса (с тика 0) и воспроизведение (сверено, первое расхождение с участниками); `replay.save(name)` — запись в артефакты; `replay.check(path, set)` — реплей целиком в отдельной симуляции (Headless); `replay.diff(a, b)` — заголовки, первый тик с разными командами, первый разный хеш; вместо пути — `session` |
| мир | `world.types` (компоненты, события, ресурсы, команды и их поля), `world.query(with, without, where, fields, aggregate, skip, take)` — `where` — условие на сущность, `aggregate` — count/min/max/mean/sum числовых полей, `entity.get(entity, components)`; `world.snapshot(id)` — наблюдательный снимок (и файл), `world.diff(a, b, filter, tolerance)` — разница по полям (`now` — снять сейчас) |
| история | `watch.add(entities, where, fields, every, capacity)`, `watch.list`, `watch.remove(id | all)` — наблюдения после каждого тика; `entity.history(entity, fields, from, to, changes)` — значения по `tickId`; `events.history(types, entity, where, from, to)` — события, команды и срабатывания последних 1200 тиков (тик, стадия, поля); `replay.observe(path, from, to, events, watch, condition)` — то же на прогоне реплея в отдельной симуляции, в `.jsonl` (Headless) |
| инварианты | `invariant.list(filter, recent)` — id, чей, когда проверяется, включён, проверок, нарушений, средняя стоимость (мкс), последнее нарушение; `invariant.enable(ids, enabled)` — id, «префикс.*», all (переживает `session.start` и перемотку); `invariant.run(ids)` — проверить сейчас, в том числе посреди тика, выключенные и «по запросу»; `invariant.define(id, condition | must + where, after, every, remove)` — свой инвариант условием; `time.breakOnInvariant(ids, maxTicks)` — встать на нарушении (Headless — посреди тика после нарушившего барьера, живая игра — после тика); нарушения — в `events.history` (тип `InvariantViolation`) |
| состояние | `state.hash` — хеш состояния, итог и по участникам (`ecs`, `animation`…); `state.describe(part, filter, skip, take)` — ровно то, что участник хеширует (у `ecs` — сущности, ресурсы, `slots`, `journal:…`, `system:…`); ответ больше 60 тыс. знаков — в файл артефакта (`artifactId`) |
| команды | `command.send(command, fields, tick | delay, repeat)` — не дальше 1 000 000 тиков вперёд, в очереди агента — не больше 1 000 000 команд одного типа |
| журнал | `log.tail(after, limit, level, category)` — без `after` последние `limit` записей, прошедших фильтр (среди всего кольца, 2048 записей), `last` — номер последней записи кольца; с `after` — вперёд страницами |
| устройство | `architecture.projects`, `ecs.plan`, `ecs.explainSystem(name)`, `ecs.componentUsage(name)`, `module.graph` |
| клиент (App) | `capture.bundle(name)`, `render.graph` |

Сущность — номером `12v3` или именем игры (`player`, `fighter N` — `Game.Agent`). Компоненты и команды — коротким
(`Transform`) или полным именем. Поля — JSON по стабильным именам полей (`world.types` даёт схему).

## Ограничения (до своих этапов)

- Причинности (`state.why`, этап 6) и экспериментов (точка 3д) нет (раздел 8, «По этапам»).
- Живая игра реплей только пишет: `session.start`, `time.seek` (в обе стороны) и `replay.check` — только Headless.
- Останов посреди тика (`time.break`) — только Headless: в живой игре тик идёт внутри кадра рендера, а кадр не ждёт
  агента. Условие `time.runUntil` в живой игре встаёт на своём тике (кадр прерывает тики), но между тиками.
- `capture.bundle` v0: цвет, глубина (8 бит, ближе — светлее, растянуто на диапазон кадра), бойцы с рамками и именами,
  камера, `paused` и `alpha` (доля тика кадра). Нет ID-буфера, нормалей, векторов движения, оверлеев (этапы 5 и
  дальше). Кадр на ходу показывает интерполяцию между тиками (`alpha` < 1): `tickId` — последний сыгранный тик, точное
  состояние — на паузе (`alpha` 1). Глубина — та, что записала сцена в этом кадре.
- `gpu.passes` (время проходов GPU) нет: нет профайлера GPU.
- `IStateContributor.Describe` и манифест фичи `feature.json` — этап 3 (реестр манифестов, `feature.verify`).
- Бюджет точки обслуживания в App соблюдается между запросами, не внутри: один тяжёлый запрос может удлинить кадр.
  Тяжёлых запросов в точке обслуживания в 1е нет (самый тяжёлый — `world.query` на 100 сущностей); `capture.bundle`
  (ожидание GPU и PNG) исполняется на границе кадра и удлиняет свой кадр — он служебный.
- `--bench` и `--agent` вместе не задаются: пауза и снимки агента исказили бы замер.
- `session.start` (запуск Headless из агента с конфигом и модулями) нет: сеанс — это процесс; конфиг и модули —
  ключами запуска.

## Что проверить в игре

1. Claude Code в корне репозитория: `/mcp` — серверы `sword-headless` (запускается сам) и `sword-app` (после
   `Sword.exe --agent`) подключены.
2. Попросить агента: «через sword-headless: покажи состояние сеанса, дай игроку команду бежать по +X 120 тиков, сделай
   120 тиков и скажи, где игрок» — игрок около x = 3,94, скорость 4,2 м/с.
3. «Объясни систему PlayerCommand» — стадия Intent, читает Transform, пишет FighterCommand и GazeTarget, вход —
   команды тика, выход — core.root-steer; место регистрации `game/Sword.Game/GameCore.cs`.
4. `Sword.exe --agent`, затем через sword-app: пауза (Manny замирает, HUD — «тиков сим. 0»), команда движения на
   120 тиков, `time.step` 120 — Manny пробегает и останавливается; `capture.bundle` — картинка кадра, глубина и рамка
   игрока в `artifacts/agent/…`; `time.resume` — игра снова идёт, WASD работает.
5. `session.stop` через sword-app — окно закрывается.

## Агентский доступ

Это и есть агентский доступ; сам он проверяется:
- `verify.ps1` `agent-smoke` — сеансы MCP с `Sword.Headless --agent` (stdio) и `Sword.exe --agent` (HTTP): игрок по
  имени, команда на 120 тиков — игрок ушёл по +X, `ecs.explainSystem`, пауза и шаги живой игры, `capture.bundle` с
  игроком в кадре на тике паузы, `render.graph`, `session.stop` — оба процесса выходят; живая игра — с GPU-валидацией,
  сообщения D3D12 и шейдеров — отказ;
- `tests/Sword.Engine.Agent.Tests` — протокол (версии, ошибки, уведомления, `id: null`, повтор ключа, пакеты, ответы
  клиента, отмена без ответа и только в своём сеансе, неизвестный аргумент, `null` и обязательные аргументы,
  `arguments` не объект, версия `jsonrpc`, завершение сеанса DELETE и 404, гонка DELETE с вызовом, кадр квитанции из точки обслуживания, опечатка в пути `fields`, проверка аргументов до действия, `take` 0 без продолжения, горизонт всего
  диапазона `repeat`, предел исполнения HTTP-вызова),
  инструменты над симуляцией под циклом Headless (команды на будущий тик, страницы с продолжением, пауза, таймаут
  точки обслуживания — команда потом не проходит), stdio (конец входа отменяет долгие вызовы) и HTTP (202, 405, 403 за
  чужой Origin, 415, 400 за версию протокола и испорченные запросы, сеанс на клиента, `Expect: 100-continue`), рамка
  на экране;
- `tests/Sword.Engine.Introspection.Tests` — разбор полей (все виды, `[Flags]`, `nint`, дробное в целое — ошибка,
  только чистые данные, ошибки с путём поля, схема), каталог имён (одинаковые короткие имена), запросы, карта
