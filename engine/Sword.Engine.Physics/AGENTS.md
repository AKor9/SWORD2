# Sword.Engine.Physics — правила

Подсистема физики (раздел 6 плана): тела-капсулы и сочленения за хэндлами; кинематические (этап 5) и на физике (этап 7).
Описание, контракт этапа 7, откуда идеи и ограничения — [README.md](README.md).

- API — интерфейс `IPhysicsWorld`: в одном процессе живут две реализации (эталон и кандидат — дифференциальный прогон,
  раздел 8). Статического изменяемого состояния нет; у каждой симуляции свой экземпляр. Игра и тесты работают через интерфейс.
- Выдача слотов — часть договора: свободные с конца списка, при росте младшие номера первыми, удалённое сочленение
  возвращает тела с конца. Меняя порядок, меняешь хеши эталонов (`physics`) — и у второй реализации он должен быть тем же.
- Хэндл — индекс и поколение, поколение 0 — «нет»; устаревший хэндл — `InvalidOperationException` везде, кроме `IsAlive`.
- Арифметика кинематической постановки (`SetKinematicTarget`), `Place`, концов и `RotationVector` — часть поведения: от
  неё зависят хеши участника `physics` эталонов SWORD2 и удары (этап 6). Меняя — прогнать `PhysicsWorldTests` и эталоны
  (`ReferenceReplaysTests`, `verify.ps1`); разошлись эталоны — это изменение поведения (перезапись — только с доказательством,
  раздел 12 плана). Сверки с трассой SWORD нет (решение 14, снята на 7а).
- Установившийся режим не выделяет памяти (`PhysicsWorldTests.SteadyState_…`, `WorldDynamicsTests.SteadyState_…`): никаких
  коллекций на вызов, массив тел сочленения переиспользуется за слотом; примитивы `Dynamics`/`Xpbd` и запись состояния — 0 Б.
- Подсистема не знает ECS и игры: игровые данные тела (сегмент, владелец, рана, отруб) — у игры; хеш и инварианты
  физики регистрирует игра (`Sword.Game/Bodies`), контракты Runtime отсюда не видны.
- Новое — только с первым потребителем (принцип 9): шаг и `Simulated` — трупы (этап 7), запросы — клинок (этап 6).

## Этап 7: контракт и раскладка (7в, 7г, 7д реализованы и сведены)

- **Контракт** — `IPhysicsWorld.cs` и `Contract.cs` (открытые типы), объявления крючков в `PhysicsWorld.cs`, поля `BodyState`,
  `PhysicsSettings`. Правка — отдельный маленький коммит «контракт: …» с пометкой, его сливает оркестратор (план этапа §3.1,
  §6): физику зовут параллельные точки игры и клиента. Меняя поведение члена — поправить его текст в интерфейсе в том же
  изменении (тексты сведены с реализацией при сведении физики).
- **Файлы областей** (раздел «Раскладка файлов» README): 7в — `PhysicsWorld.Joints.cs`, `Joints.cs`; 7г —
  `PhysicsWorld.Contacts.cs`, `Ground.cs`, `PhysicsWorld.Step.cs`; 7д — `KinematicContacts.cs`, `PhysicsTrace*.cs`. Открытые типы
  — только правкой контракта; внутренние (`internal`/`private`) — в файле своей области, имена членов `PhysicsWorld` — с
  приставкой области (`Joint…`; `Contact…`/`Ground…`/`Step…`; `Kinematic…`/`Trace…`).
- **Тесты гоняют настоящий `Step`** — путей шага только для тестов в продукте нет (временные помощники подшага 7в/7д удалены при
  сведении). Нужен шаг без контактов — мир без земли, стены, колонн и пар; с землёй — тестовая (`ContactsTestKit`); один этап
  подшага отдельно — шаг из одного подшага, где до этапа действует известное (`JointsSolverTests.OneSubstep`,
  `BindAfterIntegration`, `BeforeRelax`). Внутренние подглядывания для тестов (счётчики, бюджеты) — можно
  (`InternalsVisibleTo`), свои помощники тестов — в тестах (`TestBodies`, `ContactsKit`, `JointsRig`, `KinematicScene`).
- **Крючки** — `partial void` без модификатора доступа: у каждого одна реализация (своя точка); без реализации вызов
  исчезает вместе с аргументами. Рост массивов по слотам — `*Grow(articulations, bodies)` (только рост; из конструктора
  тел ещё 0), сброс слота при создании и удалении сочленения — `*Reset(articulation)`. Шаг (7г) зовёт суставы и толчки
  только крючками; крючки трассы — под `if (_trace is not null)`.
- **Порядок обхода в шаге** — по слотам: сочленения по номеру слота, тела — по порядку в сочленении, пары сочленений
  `i < j`; суставы — по порядку описания. Детерминизм: без словарей, хеш-множеств и параллельных проходов.
- **Проекции**: кинематическое тело — только миром (перегрузка без второго тела): у него конечная масса. Примитивы не
  проверяют аргументы (горячий путь) — проверяет мир на входе вызовов API.
- **OSR и память**: шаг зовётся раз в тик, подшаги — циклы: тело долгого цикла (по телам, суставам, парам) — отдельный
  метод (правило корневого `AGENTS.md`); 0 Б на шаг — списки подшага заранее, рост — только при росте слотов.
- **Свой путь** (решение 14): SWORD — источник идей (`artifacts/plans/stage-7/research-*.md`), не образец; со SWORD не
  сравнивать, тесты SWORD не переносить — свои тесты свойств; отличие от SWORD — выбор, записать в README коротко, почему.
- **7г — шаг и контакты** (README «7г»): порядок подшага — только как в описании `Step` (крючки 7в/7д — на своих местах, трассу
  вокруг `PushKinematic` не звать); контакты подшага — заранее выделенный буфер скоростного прохода, касания земли — буфер мира
  (не `stackalloc`); трение покоя о землю — общий бюджет тела `μs·Σλn` после нормали обоих торцов, трение скольжения — в
  скоростном проходе; торцы — всегда в одном порядке (чередование срывает трение). Меняя это — прогнать `Contacts*Tests` и
  `StepTests` (склон держит до 0,95 μ, выход не быстрее `PopSpeed`, 0 Б на тик 33 × 14 тел).

## 7д: толчки живых и трасса

- **Толчки** (`KinematicContacts.cs`): бюджет пары — скаляр на все контакты пары за подшаг, первый берёт сколько может —
  порядок обхода пар в шаге (7г) часть поведения. Всё, от чего зависит следующий тик, читается через интерфейс: проход — `Pass`
  (бюджет открытого прохода — его `Potential`, потрачено — `Potential − Remaining`), отдача — `Reaction`; бюджеты подшага и
  отметки тика между тиками не живут. Меняя предел λ, списание или закрытие прохода — прогнать `KinematicPushTests`,
  `KinematicPassTests` и описать в README «7д».
- **Трасса** (`PhysicsTrace*.cs`): выключенная — одна проверка поля `_trace`, 0 Б; включённая — 0 Б в установившемся режиме
  (массивы — при включении и росте слотов; строки — только `Summary`, `Event.ToString`). Пишут только крючки и API мира; в хеш
  не входит и симуляцию не меняет (`TraceTests.Trace_DoesNotChangeSimulation`). Новое поле трассы — в `Stats.Clear` и
  `Summary`. `Step` зовёт `TraceStepBegin()` после позы начала тика, до подшага 0 (база энергии подшага 0); крючки, которые
  открывают снимки нескольких тел (суставы — все тела сочленения на физике), зовут N `TraceBegin`, затем N `TraceEnd`.

Проверка: `tests/Sword.Engine.Physics.Tests` (236; труп целиком и куча 32 трупов — `CorpseTests`, их замеры — отправные для
порогов инвариантов 7з); хеш, инварианты и хуки тела бойца — `tests/Sword.Game.Tests/BodiesTests`, `GameInvariantTests`.
Меняя шаг, контакты, суставы или толчки — прогнать `CorpseTests` с выводом и сравнить замеры с README «Сведение физики».

## 7в: суставы

- Порядок в суставе — **предел, затем точка**; расслабление — точки (K 3×3), затем срабатывания подшага вместе с точкой (4×4).
  Это решение по замерам (README «7в»: отскок от упора и рост энергии у схемы SWORD); меняя порядок или расслабление — прогнать
  `JointsSolverTests` с выводом (`--logger "console;verbosity=detailed"`) и сравнить замеры: отскок, энергия цепочки и бойца.
- Пределы — одномерная `Xpbd.Angular` (импульс — вдоль градиента меры); трёхмерная угловая проекция проверена дважды и
  отвергнута (энергия растёт — и после поправки вдоль градиента: README «7в»).
- **Каждая поправка предела — вдоль градиента его меры** (ньютоновский шаг `−C·∇C/|∇C|²`): иначе предел совершает работу по
  замкнутому пути — рост энергии в долгом прогоне (так было со скручиванием и наклоном до исправления, README «7в → Исправлено»).
  Новый предел или новая мера — аналитический градиент с проверкой центральными разностями (`JointsTests.Corrections_…`).
  Энергию проверять и долгими прогонами по 10 с (`FreeFighter_10s_…`, `ArmChain_…`), не только 2 с.
- Журнал срабатываний — ёмкость в `SetJoints` (`2 · суставов · Substeps`), рост — только при росте подшагов; 0 Б на шаг —
  `JointsSolverTests.SteadyState_…`. Записи и журнал суставов дерева (тела − 1) — за слотом с создания сочленения (`JointsReserve`,
  7з): первый `SetJoints` посреди игры — 0 Б (`JointsSolverTests.FirstSetJoints_…`).
- Допуски тестов суставов — по замерам (≈ 2× к худшему, числа — в комментариях констант); провал — сначала разобраться, не
  ослаблять.
- Тесты суставов — через `Step` (мир без земли и пар); проход и расслабление по отдельности — шагом из одного подшага
  (`OneSubstep`, `BindAfterIntegration`, `BeforeRelax` в `JointsSolverTests.cs`); заготовки тестов — `JointsRig` (в
  `JointsTests.cs`).
