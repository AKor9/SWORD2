# Sword.Engine.Physics

Подсистема физики движка (раздел 6 плана). Владеет телами-капсулами и сочленениями (наборами тел); наружу — хэндлы. Игра
держит в ECS только хэндл сочленения (`BodyRef` бойца) и заводит его хуком ECS. Сторона Neutral; ссылки — Diagnostics,
Geometry (матрица раздела 4); ни ECS, ни игры подсистема не знает.

## Назначение

**Этап 5 (точка 5а)** — кинематические тела:
- `IPhysicsWorld` — API физики одной симуляции: сочленения (`CreateArticulation`, `DestroyArticulation`, `BodyCount`,
  `Body`), тела (`Get`, `SetShape`, `Place`, `SetKinematicTarget`, `ArticulationOf`), слоты для хеша, инвариантов и
  описания (`ArticulationCapacity/GenerationAt/At`, `FreeArticulations`, `BodyCapacity/GenerationAt/At`, `FreeBodies`,
  счётчики живых).
- `PhysicsWorld` — эталонная реализация (состояния по слотам — AoS).
- `BodyHandle`, `ArticulationHandle` — индекс слота и поколение; поколение 0 — «нет».
- `BodyState` — состояние капсулы (оси вдоль локальной Y); `Axis`, `EndA`, `EndB`.
- `PhysicsMath.RotationVector` — вектор поворота от одного поворота к другому (из него — угловая скорость).

Потребители (5б, игра — `game/Sword.Game/Bodies`): постройка бойца — `SetShape` (форма `Fighter.Build`; с 7ж — с массой, 14 тел
с клинком) и `Place` (капсулы
без скорости по позе постройки), каждый тик — `SetKinematicTarget` (капсулы по позе тика, `KinematicPlacementSystem` в
PrePhysics); наблюдателям — вид игры `IBodyView` поверх `Get`. На 5б–5г побитово сверялось с трассами SWORD толпы и
рельефа — сверка снята на 7а (решение 14, свой путь); регрессию держат эталоны SWORD2 (хеш участника `physics`). Замер (5г, Release, `experiment.sweep` по
`arena.enemies`, без инвариантов): стадия PrePhysics — 0,0009 / 0,0074 / 0,0138 / 0,0270 мс на тик при 1 / 9 / 17 / 33 бойцах
(линейно, ~63 нс на капсулу — 13 вызовов `SetKinematicTarget` через интерфейс и `FromBasis` на капсулу), 0 байт. Приёмка —
фича [«Физика и тела»](../../game/Sword.Game/Features/Bodies/README.md) (этап 5 принят пользователем; эталон SWORD2 —
`tests/reference/replays/bodies.swreplay`).

**Этап 7 («Смерть и рэгдолл»)** — тела на физике (трупы): динамика и решатель XPBD (7б), суставы трупа (7в), контакты с
землёй, стеной, колоннами и между телами, шаг (7г), толчки живых и трасса физики (7д). Точка 7б — ядро динамики и **контракт
всего этапа**: типы и члены `IPhysicsWorld` для 7в/7г/7д зафиксированы заранее, чтобы три точки шли параллельно в своих
файлах (раздел «Этап 7: контракт»). Всё реализовано и сведено (раздел «Сведение физики»): заготовок контракта нет, временных
путей шага для тестов нет, форма тела — только с массой (перегрузка этапа 5 `SetShape(body, radius, halfLength)` удалена: с 7ж
игра её не зовёт). Игра с 7ж строит бойца из 14 тел с массами (клинок — 14-е тело), хеширует все поля тела и профили; шаг трупа,
суставы и толчки игра зовёт с 7з/7к.

## Этап 7: контракт

Зафиксирован на 7б (план этапа — `artifacts/plans/stage-7/PLAN.md` §3.1, вне git). Открытые типы и члены интерфейса
меняются только отдельным маленьким коммитом «контракт: …» (сливает оркестратор). Точки 7в/7г/7д написали реализацию в своих
файлах и заменили заготовки (`NotImplementedException("7x: …")` больше нет); тексты контракта сведены с реализацией при сведении
физики (проход, трасса, удар, форма).

### 7б — динамика тела (реализовано)

- **`BodyState`** + поза начала тика `StartPosition/StartRotation` (для интерполяции клиента: `PrevPosition` у тела на
  физике перезаписывает каждый подшаг; пишут `Place` — та же поза, `SetKinematicTarget` — прошлая постановка, `Step` — у тел
  на физике перед первым подшагом), `Mass`, `InvMass`, `InvInertia` (диагональ в системе тела), `Grounded` (касание земли в
  подшаге), `Profile` (номер профиля динамики, байт), `Source` (`KinematicSource` — чем толкает кинематическое тело).
  Запросы — члены структуры: `ToWorld`, `ToLocal`, `PointVelocity`, `PrevPoint` (где была материальная точка в начале
  подшага), `InvInertiaWorld`, `InvMassAt(r, n)`, `IsFinite` (все положения, повороты и скорости), `KineticEnergy`.
- **`BodyMode.Simulated`** — тело на физике: его двигает шаг, для решателя кинематическое тело — бесконечной массы.
- **`BodyDynamics`** — профиль: `Gravity` 9,81, `LinearDamping` 0,15, `AngularDamping` 0,8, `GroundFriction` 9,
  `GroundAngularFriction` 3, `MaxSpeed` 40, `MaxAngularSpeed` 60 (отправные значения SWORD); `Problem()` — годность.
- **`Dynamics`** — функции над `ref BodyState`: `CapsuleInvInertia`, `SetShape` (с массой), `Rotate` (≤ 0,5 рад за
  вызов), `Correct` (позиционный импульс в точке), `ApplyImpulse` (импульс в скорость в точке), `Integrate` (подшаг: прошлая
  поза, гравитация, положение, поворот, `Grounded = false`), `UpdateVelocity` (скорости из сдвига за подшаг, демпфирование,
  трение о землю при `Grounded`, потолки).
- **`Xpbd`** — проекции, каждая в двух формах: тело — тело и тело — мир (перегрузка без второго тела; мир и кинематическое
  тело — неподвижная сторона): `Along`, `Attach` (свести точки), `Angular` (повернуть на вектор), `Contact` (односторонний,
  предел λ, возвращает λ ≥ 0), `Friction` (трение покоя «всё или ничего» по Кулону). Все возвращают λ.
- **Мир**: `SetShape(body, mass, radius, halfLength)`, `SetMode`, `SetDynamics(body, profile)`, `RegisterDynamics`,
  `ReplaceDynamics`, `GetDynamics`, `DynamicsCount` (профиль 0 — по умолчанию, всего ≤ 256), `Set(body, in BodyState)`
  (запись целиком с проверкой — тесты, команды сцен, переход в труп), `SetKinematicSource`, `Settings`.
- **`PhysicsSettings`** — неизменяемый объект настроек, задаётся при композиции (`new PhysicsWorld(settings: …)`), замена
  на ходу — `world.Settings = s with { … }` (ручки игры, 7з); подсистема конфиг не читает. Поля (отправные значения SWORD) и
  кто читает: `Substeps` 4 (7г), `PopSpeed` 3 м/с (7г, 7д), `StaticFriction` 0,7 (7г), `ContactCompliance` 1e-7 (7г, 7д),
  `JointLimitCompliance` 2e-4 (7в), `PushForce` 800 Н (7д), `PassShare` 0,5 (7д), `KinematicPointSpeedMax` 16 м/с (7д),
  `PassExitTicks` 2 (7д), `HitDvShare` 0,5 (7д).

### 7в — суставы (контракт; реализация — раздел «7в — суставы трупа (реализация)»)

`JointDesc` (фабрики `Hinge`, `SwingTwist`): родитель и ребёнок — номера тел сочленения, точка на ребёнке (система
ребёнка), вид `JointKind`; шарнир — `BendMin/BendMax`, люфт оси `AxisSlack`, знак сгиба `BendSign` (анатомический, из
описания), ось шарнира `HingeAxis` (система ребёнка, фабрика — X); наклон-скручивание — `SwingXMin/SwingXMax/SwingZ/Twist`;
`LimitCompliance` (null — из настроек). Оси — в системе ребёнка: Y — ось капсулы (скручивание), X и Z — наклон. Члены:
`SetJoints(articulation, span)` (порядок = порядок решения, привязка по текущей позе, все включены), `JointCount`, `Joint`,
`RebindJoints`, `SetJointEnabled`/`IsJointEnabled`, `Binding` → `JointBinding(ParentAnchor, Rest)` (привязка — состояние
для хеша), `JointLimitHits` (журнал `JointLimitHit(Joint, Substep, Axis)` за последний шаг), `MeasureJoint` →
`JointMeasure(PointError, Bend, Swing, Twist, Excess)`. Крючки: `JointsGrow`, `JointsReset`, `SolveJoints(h, substep)`,
`RelaxJoints(h, substep)`; трасса — `TraceBegin`/`TraceEnd(…, Joints, h)` вокруг прохода сочленения.

### 7г — статический мир, контакты, шаг, границы (реализовано)

`IGround` (реализация — игра, 7е): `Touches(center, radius, span)` — до `IGround.MaxTouches` = 6 касаний
`GroundTouch(Face, Normal, Depth)` по возрастанию грани, `Depth(center, radius, face, out normal)`. Грань — часть земли с
постоянным номером и непрерывной глубиной от центра сферы: гладкий рельеф — одна грань, ярус пирамиды — одна грань-ящик
(нормаль у верха, подступенка и ребра — из точного расстояния до ящика). Члены: `SetGround` (null — нет), `SetWall(radius)`
(окружность вокруг начала координат в XZ; больше 0, ∞ — нет, по умолчанию), `SetPillars(span of Pillar(X, Z, Radius))` (копия;
ось конечная, радиус больше 0), `Step(dt)` (dt конечный и больше 0; подшаги — из настроек), `Bounds(articulation)` →
`ArticulationBounds(Center, Radius)`. Файлы: `PhysicsWorld.Step.cs` (шаг), `PhysicsWorld.Contacts.cs` (мир, стена, колонны,
пары, скоростной проход, границы), `Ground.cs` (земля по граням, трение покоя).

**Шаг.** Настройки читаются раз на шаг, `h = dt / Substeps`. Начало: у тел на физике поза начала тика ← нынешняя; тел на физике
по сочленениям — сочленения без них шаг не трогает (кинематические тела шаг не двигает и не выталкивает). Подшаг — порядок
контракта: интеграция по профилю тела → `SolveJoints(h, k)` (7в) → `BeginKinematicSubstep(h)` (7д) → мир → пары →
`EndKinematicSubstep()` (7д) → `UpdateVelocity` по профилю тела → скоростной проход → `RelaxJoints(h, k)` (7в) →
`TraceSubstep(h)`. Конец: границы всех живых сочленений → `TraceStep(dt)`. Обход — по слотам: сочленения по номеру слота,
тела — по порядку в сочленении, пары сочленений `i < j`.

**Земля — торцы капсулы** (у шара торец один). Торец: `Touches` → по каждой грани глубина заново в нынешнем положении торца
(прошлые грани и торец уже сдвинули тело), старая — той же грани в прошлой позе торца (начало подшага); касание ставит
`Grounded`; `Xpbd.Contact` с миром (α = 0) на решённую глубину; λ &gt; 0 — в скоростной проход (материальная точка — до
выталкивания). После нормали обоих торцов — трение покоя «всё или ничего» (`Xpbd.Friction`) по касаниям в точке после
выталкивания, с **общим бюджетом тела** `μs · Σλn`: касание держит, если его λt не больше остатка, и тратит его. Торцы короткой
капсулы почти совпадают: второй видит глубину, закрытую первым (λ ≈ 0) — нормаль и бюджет не удваиваются.

**Выход старой глубины** (`ContactsSolvedDepth`, идея — `SolvedDepth`): `clamp(pen − max(0, pen0 − PopSpeed·h), 0, pen)` —
застарелое проникновение (ушёл в землю в позе смерти, трупы легли друг в друга) уходит не быстрее `PopSpeed`, новое (падение,
сустав, толчок) — целиком и без добавки; прошлые позы не двигаются — выталкивание ничего не прячет.

**Стена и колонны — вся капсула.** Стена: оба торца (самая дальняя от оси арены точка оси — конец) — центр торца не дальше
`R − r`, нормаль к оси арены. Колонна: ближайшая к её оси (в XZ) точка оси капсулы — не ближе `Rp + r`, нормаль горизонтальная
от оси колонны; ось капсулы на оси колонны — направление из прошлой позы, иначе +X. Старая глубина — прошлая поза; без трения;
источник трассы — `Wall`.

**Пары** (тело на физике ↔ тело на физике, кинематическое ↔ на физике). Сочленения без тел на физике — пропуск до границ; отсев
по **свежим** границам — пересчёт в каждом подшаге перед проходом пар (поза после интеграции, суставов и мира); внутри пары тела
по порядку, пары тел без тела на физике — пропуск до `SegSeg`; отсев по центрам (`reach`), затем ближайшие точки осей
(`Segments.SegSeg`, первым — более короткий отрезок); нормаль — от b к a (оси пересеклись — перпендикуляр к обеим осям в
сторону a, иначе между центрами, иначе вверх). Оба на физике — `Xpbd.Contact` с `ContactCompliance` на решённую глубину (старая —
глубина пары в прошлых позах), в скоростной проход; одно кинематическое — `PushKinematic` (7д: полная глубина, нормаль — от
кинематического, трассу пишет 7д). Своих тел сочленения не сталкивает.

**Скоростной проход** (идея — `SolveContactVelocities`, Müller и др. 2020 §3.6): контакты подшага с λ &gt; 0 по порядку решения —
нормальная относительная скорость точек гасится в ноль (e = 0), импульс с плечом; у контактов с землёй затем **трение
скольжения** по Кулону: касательная скорость точки гасится импульсом не больше `μs · λn / h`. Один проход (Гаусс — Зейдель).
Буфер — заранее, 4 контакта на слот тела (растёт вместе со слотами); переполнение — удвоение, разово.

**Границы** (идея — `UpdateBounds`): центр — среднее центров тел, радиус — наибольшее `|центр тела − центр| + полудлина + радиус`.
`Bounds` — конец последнего шага; сочленение, созданное после него (и слот после удаления), — пустые.

**Память и OSR.** 0 Б на шаг (`StepTests.SteadyState_…`: 33 сочленения × 14 тел, 16 трупов внахлёст на ступени, стена, колонны);
касания — буфер мира, не `stackalloc`; тела долгих циклов (сочленения, тела, пары, контакты) — отдельные методы. Внутренние члены
— с приставками `Contacts…`, `Ground…`, `Step…`; `ContactsPairChecks`/`ContactsNarrowChecks` — счётчики отсева за последний шаг
(тестам).

**Свои решения 7г (отличия от SWORD — почему):**
- **Бюджет трения покоя — на тело** (`μs · Σλn`), а не по λn каждого касания: одно касание, удержав, гасит сдвиг всего тела, а его
  λn — лишь доля веса, поэтому у SWORD тело на двух торцах держалось на склоне до случайной доли μ (замер: tg 0,2 при μ 0,3 —
  сползало, tg 0,5 при μ 0,7 — держалось). Теперь держит до 0,95 μ и скользит с 1,05 μ (4 и 8 подшагов одинаково).
- **Трение скольжения по Кулону в скоростном проходе** (у SWORD — только демпфирование профиля `GroundFriction`): трение покоя
  «всё или ничего» держит лишь почти неподвижную точку (сдвиг за подшаг ≲ μ·g·h²), и сорвавшееся тело при демпфировании 9/с ползло
  бы по любому склону круче ~1° со скоростью ~g·sin θ / 9. Теперь пущенное вниз по склону 0,5 μ тело встаёт (тормозной путь 0,18 м
  против кулоновых 0,15 без демпфирования профиля), сверх μ скользит с ускорением g(sin θ − μ cos θ); μ скольжения по замеру —
  0,93…0,96 μs. Своей настройки у скольжения нет — тот же `StaticFriction` (предложение контракта — ниже).
- **Стена и колонны — вся капсула** (торцы у стены, ближайшая точка оси у колонны; у SWORD — центр тела, хрупкое место 9): торцы и
  середина лежачей капсулы не входят в колонну, выталкивание — с плечом.
- **Отсев пар — по свежим границам подшага** (у SWORD — прошлого тика, хрупкое место 8); пары без тела на физике — пропуск до
  `SegSeg` (сочленения — до границ, тела — до ближайших точек); `SegSeg` — короткий отрезок первым (у `SegSeg` вырожденный второй
  отрезок даёт начало первого — шар против капсулы мерился не от ближайшей точки).
- **Нормаль пересёкшихся осей** — перпендикуляр к осям (у SWORD — вверх).
- **Земля — только торцы** (контракт `IGround`): середина длинной капсулы над выпуклым ребром ступени может уйти в него (хрупкое
  место 9 для земли остаётся; заметно на ступенях в 7з — добавить сферу середины длинной капсулы).
- **Порядок торцов не чередуется**: чередование по подшагам (чтобы выход из земли не копил наклон) раскачивало торцы — сдвиг точек
  от поворота срывал трение покоя (капсула сползала со склона 0,5 μ), а подскок после выхода вырос до 1,2 см. Оставлен один порядок.

**Ограничения (один проход решателя — решение этапа):** второй торец поворотом вдавливает первый — после удара о землю или стену
остаётся глубина до 2,2e-4 м (решается в следующем подшаге); утопленная на 0,3 м лежачая капсула выходит с наклоном до ~8° и за
16 тиков вместо 12 (скорость при выходе — до 0,21 · `PopSpeed`, подскок после выхода — до 0,5 мм); пара, разошедшаяся из внахлёста,
уносит вращение от выталкивания с плечом (относительная скорость центров — до 0,9 % `PopSpeed`); стены, колонны и пары — без трения.

**Найдено при проверке 7г (риски для 7з):**
- **Зажим в куче накачивает энергию.** Тело, зажатое между двумя телами одного сочленения (они друг друга не сталкивают),
  выталкивается из одного во второе каждый подшаг: остаток глубины меньше `PopSpeed·h` решается целиком, вращение от
  выталкивания с плечом скоростной проход не гасит, трение скольжения о землю переводит его в движение обратно в зажим. Замер
  (8 сочленений × 4 тела без суставов над ступенью, профиль по умолчанию, 10 случайных куч; сумма приростов энергии
  `Σ(½mv² + ½ωIω + mgy)` за тик с 5-й по 30-ю секунду): при 8 подшагах в 4 кучах из 10 — 4…11 Дж (до 0,55 Дж за подшаг), тела и
  через 15…30 с движутся до 0,2…0,7 м/с; с трением покоя, но без трения скольжения — не больше 0,3 Дж, скорости — сотые м/с
  (единичный всплеск); при 4 подшагах больше 1 Дж — в 2 кучах из 10 и с трением скольжения, и без него; без трения вовсе — не
  больше 0,03 Дж (3 кучи). С суставами (7з) зажимы постоянны — ждать нарушений
  `physics.energy`; направление правки — выталкивание старой глубины без остаточной скорости (в том числе угловой), не отказ от
  трения скольжения (без него сорвавшееся тело ползёт по любому склону круче ~1°).
- **Общий бюджет трения даёт касанию больше его μ·λn.** Капсула, опёртая нижним торцом о пол, верхним — о подступенок

### 7д — толчки живых и трасса (реализовано)

`KinematicSource` тела (`Body` — бюджет пары и отдача; `Pass` — ещё и бюджет прохода; `NoReaction` — без отдачи; запись —
`SetKinematicSource`, есть с 7б). Члены: `PreparePass(pusher, strike, mass, speed)`, `PassHit`, `SpendHit`,
`ApplyHit(body, point, impulse, impactSpeed, pusher)`, `Pass` → `PassState`, `Reaction`, `TakeReaction`, `EndKinematicTick`;
трасса — `Trace`, `EnableTrace`, `DisableTrace`, члены `PhysicsTrace`. Крючки: `KinematicGrow`, `KinematicReset`,
`BeginKinematicSubstep`, `PushKinematic`, `EndKinematicSubstep`, `Trace*` (все семь).

**Толчки** (`KinematicContacts.cs`). Состояние пары сочленений «толкающий → цель» — по слотам (`толкающий · ёмкость + цель`,
перекладывается при росте слотов): проход (номер удара, номер прохода, открыт, потенциал, остаток, пустые тики, отметки тика)
и бюджет пары за подшаг (израсходовано + номер подшага: сброс ленивый, без прохода по парам); отдача — по сочленениям.
- `BeginKinematicSubstep(h)`: бюджет пары подшага `PushForce · h²`. `PushKinematic` (внутри — `KinematicPush`, возвращает λ):
  кинематическое тело — неподвижная сторона (`Xpbd.Contact` с миром), податливость `ContactCompliance`, глубина решается
  полная (непогашенная — на следующие подшаги). Предел λ — наименьшее из: остатка бюджета пары (скаляр на все контакты пары:
  **первый берёт сколько может** — порядок обхода шага 7г часть поведения); у `Pass` — остатка прохода · h (проход
  открывается контактом, тик отмечается); **предела скорости** `(clamp(v_kin·n, 0, KinematicPointSpeedMax) + PopSpeed −
  v_now) · h / w` — точка тела вдоль нормали после толчка не быстрее толкающей точки плюс `PopSpeed` (бюджет ограничивает
  силу, а не скорость: 800 Н разгоняют кусок 0,3 кг на 5,6 м/с за подшаг). Одна λ списывается из пары и из прохода; отдача
  `−λn/h` — толкающему, у `NoReaction` — нет. `EndKinematicSubstep`: наибольшая доля бюджета пары и число пар — трассе.
- `PreparePass` — по всем живым целям толкающего: новый номер удара — проход «снаружи» (не открыт, остатка и пустых тиков
  нет, номер прохода прежний); закрытому — потенциал `PassShare · mass · min(speed, KinematicPointSpeedMax)` этого тика;
  **открытому — бюджет растёт до большего потенциала** (остаток — на ту же прибавку). `PassHit` — открыть (остаток ←
  потенциал) и отметить тик; `SpendHit` — `min(J, остаток)`, закрыт или J ≤ 0 (NaN) — 0.
- `ApplyHit`: (1) при `impactSpeed > 0` модуль урезается так, что `J · InvMassAt(r, dir) ≤ HitDvShare · impactSpeed`;
  (2) часть на физике и живой толкающий (другое сочленение) — модуль списывается из прохода (закрыт — импульса нет), отдача
  `−dir · J` — толкающему; (3) `Dynamics.ApplyImpulse` — и кинематической части (тик смерти). Проход `ApplyHit` не открывает.
- `EndKinematicTick`: открытый проход без контакта и попадания `PassExitTicks` тиков подряд закрывается; у закрытых потенциал
  снимается; отметки тика сброшены. `Reaction` — читать, `TakeReaction` — забрать (сырой импульс). `KinematicReset` — пары
  слота в обе стороны и отдача — в ноль (новое сочленение в слоте чужого прохода не наследует).

**Трасса** (`PhysicsTrace.cs` — сторона мира: включение, крючки, `TraceStepBegin`; `PhysicsTrace.Data.cs`,
`PhysicsTrace.Stats.cs` — члены класса). Включает владелец между шагами: `EnableTrace(trace?)` (своя или новая),
`DisableTrace`. Выключенная — поле `_trace` null: одна проверка в крючке, 0 Б. Включённая — массивы по слотам заданы при
включении и при росте слотов; запись — 0 Б (строки — только `Stats.Summary`, `Event.ToString`, по запросу). В хеш не входит,
симуляцию не меняет.
- Три накопителя `PhysicsTrace.Stats`: **`Last`** — последний тик: шаг (закрыт `TraceStep`) и то, что было после него до
  следующего шага, — удары, списание прохода, отдача (инварианты игры 7з/7к читают его после тика); **`Window`** — окно
  сценария (`ClearWindow` прогон не трогает); **`Run`** — с включения (`Clear` — всё).
- В накопителе: по источникам `PhysicsSource` (`Source(s)` → `SourceStats`): поправок, наибольшие сдвиг за подшаг / h, угол /
  h, скрытый сдвиг прошлой позы / h (должен быть 0), псевдоимпульс `Σ m·сдвиг/h` за тик — наибольший и сумма; контактов,
  глубина и отложенная (глубина − решённая); погашено скоростным проходом; точный импульс толчков `Σλ/h`. Скорости тел на
  физике по подшагам — наибольшие (и чья), упоры в потолок профиля (≥ 0,999), нечисловые, гистограммы (0,25 м/с × 256,
  1 рад/с × 128) и перцентили. Толчки — доля бюджета пары (`PairShare`), пар·подшагов, доля бюджета прохода с открытия
  (`PassShare`), выталкивание сверх толкающей точки (`PushPopSpeed`, против `PopSpeed`); забранная отдача. Удары — доля Δv
  точки от скорости удара (`HitDvShare`, против настройки), урезанные потолком и проходом, Δv и Δω тела. Трение покоя
  (держало из). **Рост энергии за подшаг** (кинетическая + `m·g·y`, гравитация профиля тела) — у сочленения, которое живые в
  подшаге не толкали (`EnergyGrowth`, `EnergyArticulation`; инвариант `physics.energy`, 7з), у всех таких вместе
  (`EnergyGrowthTotal`), у толкаемого живыми (`EnergyGrowthPushed`: толчок вправе добавлять энергию). События и 8 самых
  быстрых (`Top`). `Summary(prefix)` — сводка строками для агента (7и).
- `LastContacts` — контакты последнего подшага последнего шага (оверлей `contacts`, 7и): источник, тело, второе тело (мир —
  `None`; у толчка — кинематическое), точка, нормаль, глубина, решённая; вместимость — параметр трассы (1024), лишние —
  `LostContacts`. Последний подшаг, а не все: у 4 подшагов контакт повторился бы 4 раза чуть сдвинутым.
- События: тело на физике быстрее `EventSpeed` (12 м/с) в каком-то подшаге тика → `Event` (номер шага, тело, сочленение,
  масса, v, ω, поправки тика по источникам, Δv удара перед шагом) — в кольцо последних (64, `RecentEvent`) и в счёт и
  «самые быстрые» накопителей.
- Энергия подшага сравнивается с концом прошлого подшага, подшага 0 — с началом шага: **`TraceStepBegin()`** (внутренний
  метод мира) зовёт `Step` под `if (_trace is not null)` после позы начала тика, до подшага 0 (с сведения физики; до него рост
  подшага 0 не мерился) — удары, команды сцен и переход в труп между шагами в рост не попадают

**Решения 7д (свой путь) и почему:**
- **Бюджет прохода растёт до наибольшего потенциала** (хрупкое место 10 SWORD: бюджет задавался раз при открытии — проход,
  открытый медленной частью взмаха, держал малый бюджет весь проход). Бюджет открытого прохода хранится в
  `PassState.Potential`: потрачено = `Potential − Remaining`, скрытого состояния нет (хеш и сравнение двух реализаций видят
  всё); импульс за проход ≤ наибольшего потенциала прохода.
- **Потенциал закрытого прохода — только этого тика**: `EndKinematicTick` его снимает (у SWORD оставался от прошлого удара).
  `PassHit` без `PreparePass` этого тика — проход с бюджетом 0 (игра, 7к, готовит удар до шага каждого тика удара).
- Рост энергии — отдельно для толкаемых живыми: инварианту `physics.energy` нужен рост без внешних сил; база подшага 0 —
  начало шага, а не конец прошлого (удар между шагами — не «скачок за подшаг»).
- Трасса — объект с накопителями и сводкой по запросу, а не строки событий (у SWORD — `Console.WriteLine` и `StringBuilder`
  на событие): 0 Б включённой; имена тел — у игры (физика даёт хэндлы).
- `EndKinematicTick` проходит пары живых слотов (ёмкость²: 64 слота — 4096 пар, микросекунды). При сотнях сочленений
  (обломки, этап 11) — список открытых проходов.
- **Тесты 7д — на настоящем `Step`** (сведение физики): временный помощник подшага `KinematicContacts.TestStep.cs` удалён;
  сцены толчков — без земли, стены и колонн, цели разных сочленений друг друга не касаются (в шаге действуют только толчки);
  земля — тестовая плоскость `FlatGround`. Подглядывания `KinematicPairUsed`/`KinematicPairBudget` (бюджет пары последнего
  подшага — тестам и диагностике) — в `KinematicContacts.cs`. Ожидания выталкивания из земли (`TraceTests.Trace_GroundPushOut_…`)
  переписаны на свойство шага 7г: помощник выталкивал 3 см сразу (сдвиг / h = 14,4 м/с, скорость после тика > 10 м/с), шаг —
  не быстрее `PopSpeed` (сдвиг / h = `PopSpeed` в каждом подшаге, отложено `глубина − PopSpeed·h`, скорость выталкивания
  погашена скоростным проходом, остаток меньше `PopSpeed·h` решается целиком).

### Отличия от плана этапа (решения 7б, почему)

- **Открытые типы 7в/7г/7д — в `Contract.cs` (7б), а не в `Joints.cs`/`Ground.cs`**: `IGround` одновременно реализует игра
  (7е) — тип не может жить в файле, который правит 7г; то же для описаний суставов и прохода. Файлы точек — реализация и
  внутренние типы.
- **`Step(dt)` без числа подшагов**: подшаги — в настройках (`Substeps`), одно место и для ручек; два источника разошлись бы.
- **`KinematicSource` — перечисление физики** (`Body`/`Pass`/`NoReaction`), а не байт со смыслом игры: физике нужно знать,
  тратит ли толчок бюджет прохода и даёт ли отдачу; «корпус, клинок в ударе, за отрубом» игра переводит в эти виды.
- **`PreparePass` — на толкающего, а не на пару**: у SWORD `PrepareBlade` звали для всех пар `j ≠ i` (O(N²) вызовов в тик);
  номер удара и потенциал у всех пар толкающего одни. Потенциал считает физика (`PassShare`, `KinematicPointSpeedMax` — её
  настройки: ручки меняют их в одном объекте).
- **`ApplyHit` целиком в физике** (потолок Δv по `HitDvShare`, списание прохода, отдача): доля Δv — настройка физики; `SpendHit`
  остаётся для наблюдения и тестов.
- **Крючки роста и сброса по точкам** (`JointsGrow/Reset`, `ContactsGrow/Reset`, `KinematicGrow/Reset`): у partial-метода одна
  реализация, а массивы по слотам есть у всех трёх точек; сброс при создании и удалении сочленения — новое сочленение в
  том же слоте не наследует ни суставов, ни прохода (у SWORD состояние пар слота при возрождении не сбрасывалось).
- **`JointDesc.LimitCompliance` — null по умолчанию у наклона-скручивания**: тогда берётся `JointLimitCompliance` настроек, и
  ручка меняет податливость на ходу без пересборки суставов; шарнир — жёсткий (0), как у SWORD.
- **`SolveJoints/RelaxJoints` с номером подшага**: журнал срабатываний — за шаг, подшаг 0 — его начало.
- **Дополнено при проверке 7б** (до старта 7в–7ж, чтобы не править контракт посреди параллельной работы):
  `JointDesc.HingeAxis` — ось шарнира задаётся, а не зашита в X ребёнка: у капсул бойца X — «вправо» бойца, для колена это
  ось сгиба, для локтя в произвольной позе — нет; игра (7з) может задать ось по позе смерти через `SetJoints`.
  `Binding` (`JointBinding`) и `Reaction` — скрытое состояние (привязка суставов, накопленная отдача) влияет на следующий
  шаг и должно читаться: хеш `physics`, `Describe`, сравнение двух реализаций. Крючки трассы `TraceContact` (было
  `TraceDepth`), `TraceFriction`, `TraceVelocity` — с телом, точкой и нормалью: трасса собирает контакты последнего шага
  для оверлея `contacts` (7и) и события по телам. Трассу толчка пишет 7д внутри `PushKinematic` (одно место, без двойного
  снимка). `TraceSubstep` — в конце подшага (после расслабления суставов: итоговые скорости подшага), с энергией
  сочленений для `physics.energy`. `IGround`: грань — не обязательно плоская (ярус — ящик с точным расстоянием), важна
  непрерывность глубины.

## Устройство

- **Слоты.** Тела и сочленения — слоты с поколением: у живого — поколение, у свободного — со знаком минус (от него
  зависит поколение следующего), у ни разу не выданного — 0. Свободные берутся с конца списка; рост — удвоением, новые
  свободные кладутся так, что первыми выдаются младшие номера. Удалённое сочленение возвращает тела с конца: следующее
  того же размера получает те же слоты тем же порядком. Порядок выдачи — часть договора `IPhysicsWorld`: две реализации
  при одних вызовах выдают одни хэндлы, иначе их состояния не сравнить.
- **Устаревший хэндл** — `InvalidOperationException` в любом вызове, кроме `IsAlive`.
- **Память.** Массивы растут только при росте числа слотов; массив тел сочленения остаётся за его слотом и
  переиспользуется. Постановка, создание и удаление сочленений прежних размеров, примитивы динамики и проекции, запись
  состояния — 0 байт. Таблица профилей растёт при регистрации (сборка игры).
- **Две реализации.** Всё состояние — в экземпляре, статического нет: у каждой симуляции свой `PhysicsWorld`, эталон и
  кандидат (SoA, острова — отдельным шагом с микробенчмарком) живут в одном процессе; настройки — неизменяемый объект,
  общий экземпляр безопасен.
- **Проекции XPBD**: одно решение на подшаг, λ не накапливается; податливость — в физических единицах (`α/h²`). Проекция
  ограничения одномерна: у тела с разной инерцией по осям `Angular` поворачивает вдоль оси поправки ровно на угол, а поперёк
  — как импульс момента (`I⁻¹n` не параллелен n); точку на плече `Attach` закрывает вдоль разрыва, поворот уводит её поперёк
  — сходится за подшаги.
- **Точность float**: скорость — разность положений за подшаг, её округление копится; при h = 1/480 свободное падение за 1 с
  отходит от точного решения шага на ~5 % ошибки шага (`BodyDynamicsTests.FreeFall_…`).

## Ограничения

- Шаг, суставы, контакты, толчки и трасса реализованы и сведены; игра пока зовёт только кинематику (постановка тел, клинок
  с 7ж): шаг трупа, суставы и переход в труп — 7з, толчки живых и удары по трупам — 7к, трассу агенту — 7и.
- Хеш и инварианты подсистемы — у игры (`Sword.Game/Bodies`: участник `physics`, `physics.finite`, `physics.bodyRefs`,
  `physics.kinematicPose`, `physics.kinematicSpeed`): контракты `IStateContributor` и `IInvariant` — в Runtime, а физика его
  не видит. Все поля тела (масса, инерция, режим `Simulated`, профиль, `Grounded`, поза начала тика, толчок) участник
  `physics` и вид `physics.bodies` показывают с 7ж; суставы, проходы и отдача — с 7з.
- Один проход решателя (одна итерация Гаусса — Зейделя; решение этапа): остаточные глубины после удара (≤ 2,2e-4 м), выход
  суставов в цепочке (≤ 0,2–0,33 рад), ошибка точки сустава при ударе трупа о землю (≤ 23 мм, в куче — ≤ 37 мм) — «7в», «7г»,
  «Сведение физики».
- **Куча трупов не замирает** (риск 7г «зажимы в куче», замер — «Сведение физики»): энергия кучи убывает, но лёгкие тела (стопы,

- Кинематическое тело передаётся в проекции только миром (его масса конечна — функция его сдвинула бы); проверки аргументов
  у примитивов нет (горячий путь) — проверяет мир.

## 7в — суставы трупа (реализация)

Заготовки контракта 7б заменены: `PhysicsWorld.Joints.cs` — члены `IPhysicsWorld` суставов, крючки `JointsGrow`, `JointsReset`,
`SolveJoints`, `RelaxJoints`; `Joints.cs` (создан 7в) — внутренние `JointRecord` (описание, привязка,
включён) и `Joints` (математика: ось и сгиб шарнира, отклонение от позы покоя, наклон и скручивание, поправки пределов вдоль
градиентов их мер, замер, эффективная масса точки, решение 3×3). Идеи — `Fighter.Joints`, `RebindJoints`, цикл суставов
`SolveConstraints` SWORD (`research-solver-joints.md` §3, §4, §6).
Игра суставы ещё не зовёт (переход в труп — 7з): в игре пока не видно.

### Устройство

- **Хранение** — по слотам сочленений: массив записей суставов (переиспользуется: то же число суставов — без выделения памяти),
  журнал срабатываний за шаг (ёмкость `2 · суставов · Substeps` задаётся в `SetJoints`; растёт только при новых размерах или
  большем числе подшагов — ручкой). `JointsReset` обнуляет число суставов и журнал: слот не наследует суставы.
- **`SetJoints`** проверяет все описания до записи (негодное — `ArgumentException`, прежние суставы и привязка не меняются):
  родитель и ребёнок — разные тела сочленения, тело — ребёнок не больше одного раза, вид из перечисления, все числа конечны,
  податливость ≥ 0 или null; шарнир — `BendMin ≤ BendMax`, люфт ≥ 0, знак ±1, ось единичная (±1e-3 по квадрату длины);
  наклон-скручивание — `SwingXMin ≤ 0 ≤ SwingXMax`, `SwingZ > 0`, `Twist ≥ 0`. Все включены, журнал пуст, привязка — по
  текущей позе.
- **Привязка** (`SetJoints`, `RebindJoints`): точка на родителе — `p.ToLocal(c.ToWorld(ChildAnchor))`, поза покоя —
  `normalize(conj(P) · C)`; сразу после неё ошибка точки и отклонение от позы покоя — 0 (≤ 1e-5 у случайных поз). Флаги
  включения перепривязка не трогает.
- **Проход** (`SolveJoints(h, substep)`, из шага после интеграции): сочленения по слотам; подшаг 0 очищает журнал (и у
  сочленения без тел на физике); сочленение без тел на физике пропускается целиком; суставы — по порядку описания, один проход
  Гаусса — Зейделя; выключенный и сустав между двумя кинематическими — пропускаются; кинематическое тело — неподвижная сторона
  (перегрузки `Xpbd` с миром; кинематический ребёнок — родитель поворачивается на −θ). В суставе — **сначала предел, затем
  точка** (`Xpbd.Attach`, α = 0):
  - **каждая поправка предела — вдоль градиента его меры** (ньютоновский шаг `δ = −C·∇C/|∇C|²` по повороту ребёнка
    относительно родителя): иначе предел — не потенциальная сила и совершает работу по замкнутому пути (рост энергии, см.
    «Исправлено»). Градиенты — аналитические, сверены с центральными разностями (`JointsTests.Corrections_…`);
  - шарнир: ось, которую держит родитель, `ap = (P · Rest) · HingeAxis`; уход оси ребёнка `atan2(|ac × ap|, ac · ap)` сверх
    люфта — поворот на `(уход − люфт)` вдоль `ac × ap` (это и есть градиент ухода); затем (ось родителя — по новой позе) сгиб —
    угол от оси капсулы родителя к оси капсулы ребёнка вокруг `ap` в плоскости, перпендикулярной `ap`, × `BendSign`; вне
    `[BendMin, BendMax]` — поправка вдоль градиента сгиба `BendSign · (ap − (b·ap)·b⊥/|b⊥|²)` (b — ось капсулы ребёнка, b⊥ — её
    часть поперёк `ap`; при b ⟂ `ap` — ровно вокруг `ap`);
  - наклон-скручивание: отклонение `q = conj(P · Rest) · C` (система покоя) = наклон · скручивание; скручивание
    τ = 2·atan2(q.Y, q.W), наклон — вектор поворота без Y. Две поправки по очереди, левым поворотом δ в системе покоя (в мир —
    `P · Rest`): наклон вне эллипса (`X ∈ [SwingXMin, SwingXMax]`, `Z ∈ ±SwingZ`) — вдоль градиента `C = √E − 1`
    (`E = (sv.X/lx)² + (sv.Z/lz)²`); в базисе плоскости наклона (u — ось, v ⟂ u в XZ, φ — угол) `d(sv) = u·(u·δ) +
    φ·v·(ctg φ·(v·δ) − δ_Y)`, откуда `∇C = (G·u)·u + (G·v)·φ·ctg φ·v − (G·v)·φ·Y`, G = ∇_sv C; затем (по новой позе)
    скручивание за `±Twist` — вдоль `g = (xy − wz, w² + y², wx + yz)/(w² + y²)` (|g| = 1/cos(наклон/2));
  - поправка предела — `Xpbd.Angular` вдоль направления δ (импульс — вдоль градиента) с податливостью описания (null —
    `Settings.JointLimitCompliance`, читается на каждом проходе: ручка действует сразу; податливость — к повороту до границы,
    `C/|∇C|`); применённая (λ > 0) — в журнал `JointLimitHit(сустав, подшаг, ось δ)` (до двух на сустав за подшаг);
  - трасса: `TraceBegin` всех тел сочленения на физике — проход — `TraceEnd(…, PhysicsSource.Joints, h)`, под `_trace is not null`.
- **Расслабление** (`RelaxJoints(h, substep)`, из шага после скоростного прохода контактов): (1) у включённых суставов
  относительная скорость точек гасится целиком импульсом в точку — `K j = −Δv`, K — полная 3×3 (решение по Крамеру); (2)
  срабатывания этого подшага (хвост журнала), по порядку: если `u = (ω_c − ω_p) · n > 0` («от предела»), `u` и относительная
  скорость точек гасятся **вместе** — система 4×4 `[K B; Bᵀ w]·[j; λ] = −[Δv; u]` через дополнение Шура. Каждый импульс —
  проекция в метрике масс: энергии не добавляет.
- **Замер** (`MeasureJoint`, и у выключенного): ошибка точки; шарнир — сгиб со знаком, «наклон» = уход оси шарнира, скручивание 0,
  выход — наибольший из выхода сгиба и ухода оси сверх люфта; наклон-скручивание — сгиб 0, длина наклона, скручивание со знаком,
  выход — наибольший из выхода наклона (вдоль луча) и скручивания.
- **Тесты — через `Step`** (с сведения физики; до него — внутренние помощники `JointsSolvePass`, `JointsRelaxPass`,
  `JointsStepWithoutContacts`, удалены): мир без земли, стены, колонн и пар — в подшаге только интеграция, суставы, скорости и
  расслабление; проход и расслабление по отдельности — шагом из одного подшага (`JointsSolverTests.OneSubstep`,
  `BindAfterIntegration`, `BeforeRelax`; «Сведение физики»).
- **OSR и память**: тела циклов по сочленениям, суставам, срабатываниям и телам — свои методы; 0 Б на шаг
  (`JointsSolverTests.SteadyState_…`: 33 бойца × 13 суставов, половина на физике, `SetJoints` тех же размеров, перепривязка,
  выключение сустава, замер, журнал — 200 тиков, 0 Б).

### Свой путь: отличия от SWORD и почему

| SWORD | SWORD2 | почему |
|---|---|---|
| знак сгиба `_hingeSign` — по знаку сгиба в позе смерти | `BendSign` описания (анатомический) | почти прямое колено в позе смерти сгибалось «назад»; тест: переразогнутое на 0,02 колено возвращается к прямому, назад не сгибается |
| в суставе: точка, затем предел | **предел, затем точка** (порядок Мюллера и др., 2020) | поворот предела вокруг центра масс уводит точку, и её сводил только следующий подшаг — сведение становилось скоростью. Замер: ошибка точки у пары с неподвижным родителем 7e-6 м против 1,9e-3, у случайных пар 4–8e-4 против 3,5e-3 (шарнир) и 5,7e-3 (наклон-скручивание); цена — заход за жёсткий упор ≤ 0,008 рад (6 рад/с), гаснет за 2–3 тика |
| отскок от предела: гасится только угловая скорость | угловая «от предела» и скорость точек — вместе (4×4) | у тела на точке сустава оставалась скорость центра, следующий подшаг возвращал её вращением вокруг точки. Замер схемы SWORD: колено от упора при 6 рад/с отскакивает до 0,95 рад; падающий боец (случайные толчки, пределы по умолчанию) набирает **28 %** энергии за 2 с. Своя: отскока нет (откат от упора < 1e-5 рад), рост энергии за 2 с — 0 (в долгом прогоне обе схемы набирали энергию из-за направления поправки наклона и скручивания — «Исправлено») |
| скручивание — поворот вокруг оси ребёнка; наклон — одним поворотом к «допустимой» ориентации (наклон сжат к центру эллипса вдоль луча) | наклон, затем скручивание — отдельными поправками **вдоль градиентов своих мер**; сгиб шарнира — тоже вдоль градиента | поправка не вдоль градиента — не потенциальная сила: предел совершает работу по замкнутому пути (коническое движение руки). Замер (10 с, без земли и гравитации): рост энергии бойца в 4 из 20 прогонов до ×13,4, руки «плечо — локоть — клинок» — в 16 из 20 до ×9,6, выход до 1,01 рад; после — 0 из 20 (и 0 из 200 при толчках до 30 рад/с, α = 2e-4 и 0), выход ≤ 0,18 рад |
| сгиб — `atan2((a×b)·n, a·b)`; уход оси — `asin|ac×ap|`; сгиб вокруг оси до поправки оси | проекция на плоскость ⟂ оси; `atan2`; ось — после поправки | составляющие вдоль оси искажали угол, когда кость родителя не перпендикулярна оси; `asin` неверен за 90° |
| ось шарнира — X ребёнка | `HingeAxis` описания | контракт 7б: у локтя в произвольной позе X — не ось сгиба |
| податливость: у трупа не-шарнир — константа 2e-4 | описание или `JointLimitCompliance` настроек | ручка меняет на ходу, шарнир — жёсткий по умолчанию (фабрика) |
| `PointMass` + `Matrix4x4.Invert` | Крамер 3×3 | то же, без матрицы 4×4 |
| журнал на 28 записей | растёт, ёмкость по подшагам | 16 подшагов ручкой — все срабатывания в журнале |
| — | кинематический ребёнок при родителе на физике | у SWORD труп целиком на физике — случая не было; здесь — родитель поворачивается на −θ |

Проверено и отвергнуто: трёхмерная угловая проекция предела `P = (I_c⁻¹ + I_p⁻¹ + α/h²·E)⁻¹ θ` (относительный поворот ровно θ при
любой анизотропии капсулы). Предел — одна скалярная мера: по XPBD импульс поправки идёт вдоль её градиента (так делает
одномерная `Xpbd.Angular`), а трёхмерная проекция добавляет ограничение «поперёк — ноль», которого в модели нет, и её импульс
уже не градиент. Первый замер (до поправки вдоль градиента): цепочки шарниров и падающий боец набирали энергию, до 9 % за 2 с.
Перемерено после поправки (10 с, толчки как у тестов): рост в 2 из 20 (+34 %) у бойца, 7 из 20 (+28 %) у руки, 11 из 20 (×4,1)
при α = 0 и ≤ 30 рад/с, висящая цепочка шарниров +16 Дж; с одномерной — 0 везде. Отказ подтверждён.

Сгиб шарнира вдоль градиента (свой шаг сверх находки проверки) против поворота вокруг оси шарнира: те же замеры не различаются
(энергия 0 у обоих, выход цепочки шарниров ±0,3 — 0,089 против 0,100 рад); оставлен ради единого правила «поправка — вдоль
градиента меры».

### Ограничения

- **Одна итерация Гаусса — Зейделя**: в цепочке поправки ниже по цепочке возмущают суставы у корня. Висящая цепочка из 4 капсул
  с жёсткими узкими пределами (±0,3) и тяжёлым концом: выход ≤ 0,089 рад, ошибка точки ≤ 10 мм; с широкими (±2,5): ≤ 0,017 рад,
  ≤ 2 мм. Падающий боец с пределами по умолчанию (наклон-скручивание мягкий, 2e-4): выход ≤ 0,13 рад за 2 с, ≤ 0,18 рад за 10 с
  при толчках до 30 рад/с (мягкость задумана: у SWORD на стенде — до 24°), ошибка точки ≤ 5 мм. Рука «плечо — локоть — клинок»
  отдельно (прочие суставы выключены), 10 с, замер каждый тик (повторная проверка, 40 прогонов): ≤ 15 рад/с — выход ≤ 0,2 рад,
  ≤ 25 рад/с — ≤ 0,33 рад, ошибка точки ≤ 6,4 мм — к допускам инварианта `physics.joints` (7з).
- Поправка предела — один ньютоновский шаг по линеаризации меры: у наклона далеко за эллипсом (`√E − 1 ≥ 1,8`, наклон почти втрое
  больше предела) шаг может не уменьшить меру (до ×1,66); при `√E − 1 < 0,5` мера после шага — не больше 0,33 прежней, при < 1 —
  0,53 (повторная проверка, 3800 случайных отклонений). В работе выход за подшаг — сотые доли, такого выхода не бывает.
- **Жёсткие пределы у всех суставов** (α = 0 и у наклона-скручивания): рост энергии до 2 % за 2 с был следствием поправки не
  вдоль градиента; после — 0 из 200 прогонов по 10 с (толчки до 30 рад/с). Податливость 2e-4 у наклона-скручивания трупа SWORD
  ввёл против раскачки жёсткого предела о жёсткую землю — это проверяется с землёй (7г/7з); ручку `JointLimitCompliance` = 0
  трупу не ставить без стенда с землёй.
- Заход за жёсткий упор: ≤ 0,008 рад при подходе 6 рад/с по одной оси, ≤ 0,024 — ось шарнира без люфта при подходе по двум
  осям; гаснет до 1e-7 за 2–3 тика.
- Вырожденные настройки: ось капсулы родителя вдоль оси шарнира — сгиб не определён; уход оси шарнира ровно на π — направления
  поправки нет (поправки нет).
- Сгиб — в (−π, π]: заход за `BendMax` дальше π (у колена — больше 0,64 рад) переходит через π и обрезается к `BendMin`, хотя
  ближе `BendMax` (пока заход меньше половины запрещённой дуги, у колена 1,9 рад) — поправка идёт к дальней границе. На деле
  заход — сотые доли радиана; опасна только привязка по позе, где сустав уже далеко за пределом (неверный знак сгиба в описании).
- Одномерная `Xpbd.Angular` у анизотропной капсулы (вокруг оси инерция в разы меньше) поворачивает вдоль оси поправки ровно на
  угол, поперёк — как импульс момента: совместное нарушение наклона и скручивания сходится за несколько подшагов.

### Исправлено (найдено проверкой 7в)

- **Рост энергии в долгом прогоне.** Боец без земли, гравитации и демпфирования, случайные толчки (≤ 3 м/с, ≤ 15 рад/с), 10 с:
  энергия росла в 4 из 20 прогонов, до ×13,4; с демпфированием профиля по умолчанию и толчками до 25 рад/с — в 1 из 20, +88 %;
  рука «плечо — локоть — клинок» — в 16 из 20, до ×9,6 (у проверки — 29 из 40); выход за пределы — до 0,95–1,01 рад. Схема
  SWORD («точка, затем предел», расслабление только угловой) — так же: порядок и расслабление 7в ни при чём; без пределов (только
  точки) роста не было.
- **Причина** — направление поправки предела наклона-скручивания не совпадало с градиентом его меры (предел — не потенциальная
  сила и совершает работу по замкнутому пути, например при коническом движении руки):
  - скручивание τ = 2·atan2(q.Y, q.W) поправлялось поворотом вокруг оси ребёнка, а градиент τ по левому повороту в системе покоя
    — `g = (xy − wz, w² + y², wx + yz)/(w² + y²)`, |g| = 1/cos(наклон/2): при наклоне плеча 2,6 рад он отклонён от оси ребёнка
    на 75° — главный источник;
  - наклон сжимался к центру эллипса вдоль луча — у неокружного эллипса это не нормаль (слабее).
- **Исправление**: наклон, затем скручивание — отдельными ньютоновскими шагами вдоль аналитических градиентов своих мер (левый
  поворот в системе покоя, в мир — `P · Rest`); сгиб шарнира — тоже вдоль градиента. Градиенты сверены с центральными разностями
  (`JointsTests.Corrections_…`: расхождение — доля ≤ 1,6e-4). **После** (10 с): боец — 0 из 20 (энергия не выше начальной,
  наибольшее −0,4 %), с демпфированием и до 25 рад/с — 0 из 20, рука — 0 из 20; 200 прогонов при толчках до 30 рад/с — 0 (α = 2e-4
  и α = 0; с демпфированием — 0 из 100 и 0 из 100); выход ≤ 0,18 рад (было до 1,01), ошибка точки ≤ 5 мм. Тесты
  `FreeFighter_10s_…` (оба) и `ArmChain_…` — без пропуска.
