# Sword.Engine.Fluid3D — правила

Ядро 3D-газа (дым в мире): сетка по осям мира, окно едет за целью целыми ячейками, стадии шага, CPU-эталон, статистика, срезы.
Устройство, параметры, отступления от Epic Niagara Fluids — [README.md](README.md).

Инварианты:
- Формула меняется в двух местах сразу: `Shaders/fluid3d/fluid3d.hlsl` и `Fluid3DReference` — те же выражения и порядок операций float
  (явные mul/add, без dot/lerp/mad); числа шага — только в `Fluid3DConstants.Build` (раскладка = `GasConstants` HLSL, `_Static_assert`).
- Окно сдвигается только целыми ячейками с переносом бит в бит; мир → индексы считает CPU в double, шейдер видит только индексы окна.
- Детерминизм: без атомиков и часов кадра; SOR — red-black на месте (ячейка читает только соседей другого цвета); редукции — по порядку.
- Кадр — 0 Б: делегат прохода один, аргументы проходов — массив сима по порядку регистрации.
- Эффект — параметры `Fluid3DParams`, а не код; формулы Epic — своими словами, текст UE не копировать.

Проверка: `dotnet test tests/Sword.Engine.Fluid3D.Tests` (GPU со слоем отладки и GPU-валидацией); GPU-время —
`--filter FullyQualifiedName~Timing` (без валидации).

Типичные ошибки: правка шейдера без эталона (тесты стадий — ≤ 2 ULP half); сверка шага целиком в ULP (расхождение растёт через адвекцию —
сверять по стадиям); тёплый старт давления при (ω − 1)^(полупроходов/2) > ⅓ — вес по формуле, 1.7 при 4 полупроходах (раскачка); забыть
`Fluid3DSim.Contribute` в контракте рендера; читать поля посреди кадра; ожидать нулевую дивергенцию после проекции (коллокированная сетка —
остаток ≈⅓ на гладком поле, ≈70 % в установившемся факеле).
