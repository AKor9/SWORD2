# Sword.Engine.Ui — правила

Интерфейс без GPU (раздел 6 плана, «Ui»): виджеты немедленного режима (`UiContext`, ввод `UiInput`, правка строки
`UiTextEdit` — раздел «Виджеты» ниже), список квадов за кадр (`UiDrawList`), нарезка прямоугольников (`UiRect`),
палитра (`UiTheme`), шрифты (`UiFonts`: склейка ролей `UiFontTables`, shaping HarfBuzz `UiTextShaper`, метрики).
Отрисовка — UI-проход рендера (`Sword.Engine.Render/UiPass.cs`, `Shaders/common/ui.hlsl`); файл шрифта —
`Sword.Engine.Formats/UiVectorFontFormat.cs`. Логика — SWORD 2eab13b (`Sword.Engine.Ui`).

- Ui не знает GPU, контент и платформу: файлы шрифтов читает вызывающий (`UiFontFile.Read` — рендер из пака, тест из
  пака или памяти), ввод виджетов — данные `UiInput`: их заполняет клиент (адаптер окна) или тест.
- `UiQuad` — запись для шейдера (68 Б): поля, их порядок и `UiMode` меняются только вместе с `ui.hlsl`; размер сверяет
  `_Static_assert(sizeof(UiQuad) == UI_QUAD_SIZE)`, номера режимов приходят в шейдер из контракта (`UiPass.Contribute`).
- Горячий путь без выделений: строки — `ReadOnlySpan<char>` (форматирование на стеке), буфер shaping и массив квадов
  переиспользуются. Проверка — тесты «кадр без выделений» (Ui и HUD игры).
- Цвета — только из `UiTheme`; размеры — логические пиксели, масштаб даёт вызывающий.
- Список без шрифтов (`new UiDrawList()`) рисует фигуры; текст в нём — `InvalidOperationException`. `Append` списка с
  другими шрифтами — `ArgumentException`: номера glyph'ов в квадах — таблиц своих шрифтов.
- Шрифт из памяти (`UiFontFile`) склейка проверяет так же, как чтение (`UiFontFile.Validate`): в видеопамять не уходят
  ссылки за границы таблиц. Роль — точное имя `UiFace` (список «A,B» — не роль).
- Публичный API Ui несёт типы Formats (`UiFontFile`, записи шрифта в `UiFontTables`): Ui зависит от Formats по матрице.
  Игра их не использует — ссылку собранной игры на Formats поймал бы `CompiledAssemblies_FollowArchitecture`.
- Вызовы рисования — `UiDrawList.Split`: подряд квады одного конвейера под одной обрезкой, scissor в пределах цели.
- Текст режется и мерится по символам, а не по половинкам пар UTF-16: `TextFit` не отрезает половину эмодзи, каретка
  `CaretX` внутри пары стоит перед ней (в SWORD половинка давала .notdef).

## Виджеты (`Widgets/`, часть точки 6е)

Перенос `Widgets/*` SWORD 2eab13b. `UiContext` — кадр: `BeginFrame(input, width, height, scale)` → виджеты →
`EndFrame` → `Output` (основной слой, поверх — всплывающие окна и подсказка) в UI-проход. ID — FNV-1a подписи в стеке
`PushId`/`PopId` (`Id(int)` — строки и вкладки); состояние виджета — `State<T>(id)`; захват мыши — `ActiveId`, фокус
клавиатуры — `FocusId` (`WantsKeyboard`: горячие клавиши приложения молчат); курсор кадра — `Cursor`; окну, рисующему по
событиям, — `WakeIn` (каретка, подсказка, неопределённый прогресс).

- Оформление: `Panel`, `Label` (не влезает — «…»), `Paragraph` (перенос по словам, остаток — «…»), `InfoRow` (подпись — значение;
  длинное значение теснит подпись), `SectionHeader`, `Separator`,
  `Arrow`, `StatusDot`.
- `Button` (щелчок — отпускание над ней), `Toggle`; `Slider` (float, `log` — логарифмическая шкала; при min ≤ 0 —
  линейная), `Splitter`, `ProgressBar` (доля < 0 — неопределённый).
- `TextField` (каретка, выделение, слова, Ctrl+A/C/X/V через `UiInput.Get/SetClipboard`, Enter/Escape),
  `NumberField` (Enter или щелчок мимо — принять, не число — прежнее, вне диапазона — прижать; Escape — отмена).
- `BeginScroll`/`EndScroll`, `ScrollIntoView`, `BeginList`/`EndList` (`UiListRows` — видимые строки), `VirtualList`,
  `Selectable`; `Tabs` (не влезли — полоса прокручивается и сама подводится к выбранной), `TabList` (вкладки столбцом,
  выбранная — подсветка и полоса акцента), `Combo`, `TreeNode`.
- Всплывающие окна: `BeginPopup`/`EndPopup`, `BeginModal`/`EndModal` (затемнение, мышь не проходит); под окном прошлого
  кадра виджеты нижних слоёв мышь не видят. `Tooltip` — через 0,5 с под мышью, рисуется последней в `EndFrame`.

Правила:
- Прямоугольник виджета даёт вызывающий (нарезка `UiRect`), цвета и размеры — `Theme`, пиксели темы → экран — `S()`.
- Подписи и значения — `ReadOnlySpan<char>`: число форматируется на стеке. Строка — только то, что живёт дольше
  вызова: текст `Tooltip` (рисуется в `EndFrame`), `ref string` поля ввода, элементы `Combo` и `Tabs`.
- Кадр без выделений (после первого кадра виджета: в нём заводится его состояние): список — `BeginList` без делегата
  (`VirtualList` с замыканием выделяет на вызов), ID строк — `PushId(i)`/`Id(i)`, а не склейка строк. Выделяют только
  события: набранный текст, правка строки поля, щелчок, дающий фокус числовому полю.
- Колесо забирает прокрутка под мышью (`UiInput.Wheel = 0`). «Мышь над панелью не бьёт» решает панель (её прямоугольник,
  `ActiveId`), как в SWORD.
- Незакрытые `PushId`/`BeginScroll` — исключение в `EndFrame`; `BeginFrame` стеки чистит: исключение в виджете не
  ломает следующие кадры.

Отличия от SWORD:
- `UiContext(UiFonts? fonts = null)`: без шрифтов виджеты с пустыми подписями рисуют одни фигуры (логика — в тестах без
  пака); текст — `InvalidOperationException`, как у `UiDrawList`. Поля ввода меряют строку всегда — только со шрифтами.
- Ошибка SWORD: `NumberField` держал своё состояние под ID поля правки рядом с его `UiTextEdit`, и `State<T>` каждый кадр
  заменял одно другим — правка числа не доживала до следующего кадра. Состояние числа — под своим ID
  (`Id(label + "#value")`); одно состояние — один ID, разные типы под одним ID не живут.
- `NumberField`: ID поля правки тот же (`Id(label + "#edit")`), но без склейки строк; вне правки число рисуется со стека
  (SWORD каждый кадр форматировал строку и клеил ID). `Combo` — без замыкания `VirtualList`.
- `UiTextEdit`: каретка не встаёт внутрь пары UTF-16; ←/→, Backspace и Delete проходят пару целиком.
- `InfoRow` — новое: оформление строки `TuningInfo` панели ручек SWORD (`TuningPanel.DrawItem`).

Не перенесено сюда: панель инвентаря — игры (6е: `Sword.Game.Client/Hud/InventoryPanel`, панель клиента на этих виджетах); `UiRenderer`
(его место занял UI-проход рендера); растровые шрифты `UiFontRaster` и
запекание `UiFontBaker` (пекарня, этап 3). Адаптер окна → `UiInput` (`UiInputWin32` SWORD) — `Engine.Client/UiInputSource`
(весь набор `UiKey` SWORD), панель ручек F3 — `Engine.DevTools/TuningPanel` (обе — часть точки 6е).

Как проверить (раздел 8 плана): виджеты — библиотека без своего экрана; их проверяют тесты без видеокарты — тест
заполняет `UiInput` (помощник `UiDriver` в тестах), смотрит возвращаемые значения, `ActiveId`, `FocusId`,
`WantsKeyboard`, `WakeIn`, квады и обрезки `Output`. На экране — панели (F3) снимком кадра `Sword.exe --shot`; нового
инструмента для самих виджетов не нужно.

Проверка: `tests/Sword.Engine.Ui.Tests` (без видеокарты; на шрифтах пака — категория Content): `UiLayoutTests`,
`UiFontMergeTests`, `UiContextTests` (логика виджетов на фигурах, кадр без выделений), `UiTextEditTests`, Content —
`UiTextTests`, `UiWidgetTextTests` (поля ввода, числовое поле, подсказка, кадр панели с текстом без выделений).
