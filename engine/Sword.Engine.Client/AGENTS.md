# Sword.Engine.Client — правила

Клиент движка (раздел 7 ARCHITECTURE_PLAN.md): окно → ввод → тики симуляции → мир представления → кадр → показ.
Создаёт `Renderer` сам, окно и `Simulation` получает от exe; клиентской части игры (`IClientGame`) отдаёт только
`Renderer` и `SimulationLink`.

- `SimulationLink` — мир только для чтения (`WorldReader`), `Accepts<T>`, команды на ближайший тик, время тика; создаёт
  его только клиент движка. Из его публичных сигнатур не должен быть достижим ни `World`, ни `Simulation`, ни запись
  колонок, а обобщённые параметры его методов — только `unmanaged`
  (`PublicSurfaceTests.SimulationLink_ReachesOnlyReadOnlyWorld`).
- Тики кадра — `SimulationClock` (без окна и GPU): начинает очередь кадра экспорта тика, затем тики — накопитель по
  часам (`Program.cs` SWORD: шаг кадра до 0,25 с, не больше `sim.maxTicksPerFrame`, после упора остаток срезается до
  одного тика) или ровно `ClientOptions.TicksPerFrame` (проверочные прогоны, снимки). Отрицательный и нечисловой шаг
  кадра — ноль.
- Очередь кадра — `SimulationLink.Frame<T>()`: записи экспортированных срабатываний всех тиков кадра с номерами тиков;
  кадр без тиков (в том числе перерисовка при перетаскивании рамки) — пусто. Проверка —
  `tests/Sword.Engine.Client.Tests` (кадры с 0 и 3 тиками через клиент).
- Кадр игры (`IClientGame`): `Input(FrameInput)` — до тиков (камера, намерения кадра) → тики, перед каждым
  `BeforeTick` — команды на этот тик (удерживаемое — в каждый тик) → `Extract(FrameView)` — мир представления с долей
  тика `Alpha` (`SimulationClock.Alpha`: `accumulator / dt`; при заданных тиках — 1) → `BuildFrame` — только из мира
  представления. Кадр из перетаскивания рамки — без `Input` и тиков, с `Extract` на прежней доле тика.
- Ввод — действия (`InputAction`: имя — ключ конфига, клавиша по умолчанию), не клавиши: игра не видит Platform.
  Привязки — `InputBindings.Resolve(actions, config)`, секция `input` по общим слоям (`ConfigSet.Strings`); exe
  разрешает их до `ConfigSet.Complete`. Неизвестное действие или клавиша — ошибка запуска. Привязки пишутся в журнал.
- `ClientOptions.FrameSeconds` (`--fps N` у Sword.exe) — шаг кадра задан, а не по часам: тики и доля тика повторяются
  (накопитель — в точном шаге `1/tickRate`: заданный шаг даёт ровно свои тики); вместе с `TicksPerFrame` не задаётся.
  Шаг кадра для представления (`FrameInput.Seconds`) — сырой, как `frameDt` камеры SWORD (заданный или по часам); при
  заданных тиках — их время. `ClientOptions.MaxFps` (`--max-fps`) — ограничитель кадров.
- `ClientOptions.HeldActions` (`--hold`) — действия удерживаются весь прогон: действия, а не клавиши (привязки не
  участвуют), в первом кадре ещё и нажаты. Привязка действия к Escape при `CloseOnEscape` — ошибка запуска. Имя клавиши
  в привязке — точное (`Enum.TryParse` сложил бы «A,B» в третью клавишу).
- Кадр, нарисованный из цикла перетаскивания рамки, симуляцию не двигает; его исключение бросается главным циклом.
- Итог прогона (`ClientRunReport`, `--json` у Sword.exe): кадры, служебные кадры, тики симуляции, доля тика последнего
  кадра, бюджет обычного кадра, числа кадра (`Stats`), проходы рендера, снимки, бенч. Перетаскивание окна за
  заголовок служебным кадром не считается — такой кадр попадает в бюджет.
- Числа кадра для HUD — `FrameStatsMeter` (`Program.cs` SWORD: FPS сглажен 0,08 с 60, худший шаг — окнами по 60
  кадров, CPU — без ожидания GPU и показа) → `FrameView.Stats`: числа прошлого кадра.
- Действия клиента движка — `ClientHost.Actions` (сейчас `screenshot`, F4): привязываются вместе с действиями игры
  (`InputBindings.Resolve([.. game.Actions, .. ClientHost.Actions], config)`), имя не должно совпасть с действием
  игры. Снимок по действию — в `ClientOptions.ScreenshotDirectory`, служебный кадр; не записался (`CaptureException`
  рендера) — ошибка в журнал, прогон идёт дальше. Снимок `ScreenshotPath` не записался — ошибка прогона.
- Бенч кадра — `FrameBench` (`BenchRecorder` SWORD: игровое время, прогрев 4 с, перцентили), `ClientOptions.BenchSeconds`:
  vsync выключен, F4 не действует, с `MaxFps` не задаётся, выход `bench`, итог в `ClientRunReport.Bench`;
  `ScreenshotPath` — последний кадр замера, его шаг в замер не идёт (как в SWORD).
- `Dispose` освобождает игру и рендер, даже если ожидание GPU упало (потеря устройства).

- Фронты действий в команды (раздел 7): `InputEdges` копит нажатия и отпускания с кадров, `SimulationClock` отдаёт их
  первому тику после кадра (`BeforeTick(link, TickInput)`) и сразу забирает — кадр без тиков их не теряет, кадр из
  нескольких тиков не повторяет. Удерживаемое — из `Input`, в каждый тик кадра. `FrameInput.WasPressed/WasReleased`
  — фронты кадра для представления (камера, интерфейс), не для команд. `TickInput` — снимок (битовые маски, до 64
  действий): его можно хранить; в нём и уровень по последнему кадру — по нему тик восстанавливает порядок фронтов. Два
  нажатия одного действия между тиками (быстрее 1/120 с) сливаются. Потеря фокуса окна даёт отпускание всего
  удерживаемого (платформа), фронты кадра до неё сохраняются. Проверка — `InputEdgesTests`, `InputStateTests`.

- Инструменты кадра (агент, позже DevTools; точка 1е) — общие контракты, об агенте клиент не знает: `IClientTool`
  (`Serve` — точка обслуживания после тиков кадра, и на паузе, и при свёрнутом окне; `Capture` — снимок инструмента в
  кадре без своего снимка; `Presented` — итог кадра), `ITickGate` (`SimulationClock.Gate`: пауза и шаги вместо часов —
  накопитель обнуляется, доля тика 1; `StopAfterTick` после каждого тика кадра — пауза и условие встают на своём тике,
  остальные тики кадра не играются, накопитель обнуляется), `IClientObservable` (камера и видимые сущности игры), `RequestClose` (с любого
  потока, выход `closed-by-tool`). Подключаются до `Run` (`AddTool`, `TickGate`). Итог снимка (`Presented`) получает
  с данными только заказавший его инструмент. `IClientObservable` (5в) — ещё оверлеи игры (`Overlays`) и значение кода
  ID-буфера (`DescribeId`); заказ снимка игра видит в `RenderFrame.Capture` и регистрирует диагностические проходы (ID,
  слои) только в кадре снимка. Инструмент получает симуляцию владельца (для точки обслуживания) —
  подключает его только exe, игре и модулям он не доступен. Проверка ворот — `SimulationClockTests`.

Не сделано: GPU-время кадра в числах кадра и бенче (профайлер GPU).
Проверка чисел кадра и бенча — `FrameToolsTests`; F4 и бенч вживую — `verify.ps1` `app-smoke`.
