# Sword.Engine.Render — рендер движка

Рендер-граф v0 на D3D12 (одна graphics-очередь), фазы кадра, HDR-сцена с экспозицией, bloom и тонмапом Filmic, точечный свет
с light function, прозрачное (в том числе в ½ разрешения), текстуры пака, скинированные меши, UI-проход, отладочное рисование,
снимок кадра и GPU-время проходов. Устройство — раздел 6 плана («Render»), правила — [AGENTS.md](AGENTS.md), история —
[docs/history/stage-r.md](../../docs/history/stage-r.md) (ядро рендера: HDR, bloom, свет, прозрачное, текстуры) и
[docs/history/profiler.md](../../docs/history/profiler.md) (GPU-время, 0 Б на кадр). Логика прототипа — из SWORD (`Sword.Engine/Graphics`,
`Sword.Game/Render`); тонмап, bloom и свет — по UE 5.8 (формулы и числа, текст UE не переписан).

## Устройство

**API.** Публичный API — без типов нижних слоёв (Vortice, Rhi, Formats, Content): устройство D3D12 создаёт и держит `Renderer`
(`RendererOptions`: окно, размер, отладочный слой, GPU-валидация, шейдеры), наружу — размер, `Resize`, `WaitForIdle`, имя адаптера.
Игра строит кадр через `RenderGraph.AddPass`, `RenderPassContext` (`SetPipeline`, `SetConstant`, `SetScissor`, `Draw`, `DrawIndexed`),
данные `GpuData`, `GpuIndices`, `FrameData<T>`, UI-проход (`Renderer.Ui`) и пути ассетов. Сверяют `PublicSurfaceTests` (все публичные
и защищённые сигнатуры Render и Engine.Client) и `CompiledAssemblies_FollowArchitecture`.

**Граф.** Проход — графический (`AddPass`) или вычислительный (`AddComputePass`, dispatch на той же очереди); объявляет цели (`Color`,
`Depth`), чтения (`Read`) и записи UAV (`Write`) текстур и буферов. Переходы состояний, барьеры UAV (пачкой на проход), привязку целей,
очистку, область вывода, корневую сигнатуру и константы кадра ставит граф. Инварианты проверяются для всего кадра до первой команды:
проход не читает ресурс, который в кадре никто не записал (кроме хранилищ), не пишет и не читает один ресурс, у графического прохода
есть цели, у вычислительного — нет. Нарушение — исключение с именами прохода и ресурса; кадр бросается (`GraphicsDevice.AbandonFrame`),
следующий начинается чисто. Кадр графа — 0 Б: массивы и списки — поля, растут удвоением; отчёт прохода строится по запросу
(`LastFrame` — при первом запросе после кадра), каждый кадр — только `LastFrameDraws` и `LastFramePasses`.

**Фазы кадра** (`FramePhase`): Simulation → Opaque → Composite → Transparent → Post → Ui → Debug. Граф устойчиво сортирует проходы по
фазе (вставками, без выделений), внутри фазы — порядок регистрации; отчёт, барьеры и инварианты — в порядке исполнения. `AddPass(name)`
без фазы — Opaque, UI-проход — Ui, отладочное рисование — Debug. Так модуль ставит проход в своё место кадра, не зная остальных.
Строящийся кадр виден в порядке регистрации — `Registered`, `RegisteredPass(i)` (имя, фаза): хост клиентских модулей проверяет, что вызов
модуля добавил проходы только своей фазы.

**Ресурсы.** Импортированные (задний буфер, цели сцены, хранилища `GpuStorage`) и временные (`CreateTexture`, `CreateBuffer`) из пула:
запись пула — на один запрос в кадре, без алиасинга памяти; не выданная `TransientPool.KeepFrames` кадров подряд освобождается (после
смены размера окна старых целей нет). Индексы для шейдера — `SrvOf`/`UavOf`. Цель цвета и глубина создаются с оптимальным значением
очистки (`TextureDesc.ClearColor`/`ClearDepth`) и чистятся только им — другой цвет — исключение графа. Хранилище
(`Renderer.CreateStorage`) переживает кадр; `Renderer.ReadStorage` читает его на CPU с ожиданием GPU — для тестов и снимков.
Асинхронное чтение — `Renderer.CreateReadback(storage, bytes, handler)` (`GpuReadback`, представление и диагностика GPU-симуляций): последней
командой каждого кадра копия в буфер чтения слота кольца кадров, данные кадра N — в начале кадра N + `GpuReadback.Latency` (3), без ожидания
GPU, по порядку кадров; брошенный кадр данных не даёт; смена размера (`Renderer.Resize`: слоты кадров — с нуля) отдаёт ждущие данные сразу,
по порядку. Проверка — `ReadbackGpuTests`.

### HDR, экспозиция, тонмап

`Renderer.Hdr` (по умолчанию выключен — инструменты и тесты рисуют прямо в задний буфер; игра включает в `Initialize`): сцена пишет
линейный цвет в `RenderFrame.SceneColor` (RGBA16F, очистка — только `Renderer.SceneColorClear`); до фазы Post задний буфер не пишет
никто — исключение графа. Рендер сам добавляет в Post bloom и последним — `post.tonemap`: (сцена + bloom) × `Renderer.Exposure` →
Filmic → sRGB в задний буфер. Постобработка модуля — его проход фазы Post (идёт до bloom). UI и отладка — после тонмапа (LDR).

Цепочка тонмапа (`FilmicTonemap` — CPU-эталон, `common/post.hlsl`), как Filmic UE 5.8: Rec.709 → AP1 (адаптация Брэдфорда D65 → D60),
ExpandGamut 1, синяя коррекция 0.6, glow и red modifier ACES, десатурации 0.96 / 0.93, S-кривая в log10 (Slope 0.88, Toe 0.55,
Shoulder 0.26, BlackClip 0, WhiteClip 0.04), обратно в Rec.709, кодирование sRGB. Своё: матрицы посчитаны из цветностей (числами UE —
только таблицы синей коррекции), вход зажат в предел half, NaN → чёрный; числа (в том числе ACES и sRGB) — в `Contribute`, кривая —
корневыми константами. Рендер рисует кривой по умолчанию; `FilmicCurve` с другими числами — только CPU-эталону, вырожденная (наклон или
масштаб участка ≤ 0, носок не проводит 0.18) — `ArgumentException`.

Экспозиция по умолчанию `Renderer.DefaultExposure` = 0.99: средний серый 0.18 выходит байтом 117, как прежний вывод `pow(c, 1/2.2)`
(при 1.0 — 118); белый 1.0 → 0.7232 (байт 221). `FilmicTonemap.SceneFor(цвет на экране, экспозиция)` — обратная задача: линейный цвет,
который тонмап выведет заданным (очистка сцены и туман игры).

### Bloom

`Renderer.Bloom` (`BloomSettings`: вкл, интенсивность 10, порог 1 — уровень LIVE-2 с факелом), «сумма гауссиан» UE 5.8, ядро и
CPU-эталон — `BloomKernel`, проходы — `BloomChain`: 18 проходов `post.bloom.*` в Post перед тонмапом (после постобработки модулей).
Порог на ½ после среднего 4×4: saturate((L × экспозиция − порог) × 0.5); цепочка ½…1/64 — среднее блока 4×4 (4 билинейные выборки);
шесть ступеней (0.3 / 1 / 2 / 10 / 30 / 64 % ширины × Size 4) — ступень s на уровне s от широкой к узкой: по x, затем по y × оттенок ×
интенсивность / 6 + сумма более широких (билинейно); веса exp(−16.7 (x/R)²) парами билинейных выборок, нормированы; за краем — чёрный
(сэмплер s3); итог `bloom.y2` (½ экрана) тонмап прибавляет к сцене до экспозиции. Сумма усилений при 10 — 1.325.
Своё: радиус до 127 текселей (UE — 31: с ~1550 px широкие ступени перестали бы расти с экраном), без «fast blur», порог и уменьшение
до ½ — один проход, веса считает шейдер, вход порога и выход ступени зажаты в предел half (NaN → 0); cross, dirt mask и локальной
экспозиции нет. Без HDR или с неактивным bloom (выкл или интенсивность 0) проходов нет. GPU (1280×720, RTX 5070) — 0.053 мс на 18
проходов. Дневная арена ниже порога — кадр с bloom и без байт в байт.

### Точечный свет и light function

`Renderer.Lights` = `RenderFrame.Lights` (`PointLights`): `PointLight` (позиция, линейный цвет, интенсивность, радиус R, `LightFalloff`,
экспонента, дальность показа и полоса угасания, индекс LF) и `LightFunction` (SRV двух текстур — `GpuTexture` пака или `GpuImage`,
слой 0, канал r) — список на кадр (`Add`, `AddFunction`, до `MaxQueued` 256 и `MaxFunctions` 16). После построения кадра
рендер отбирает видимые по дальности от `ViewOrigin` (угасание — множитель на CPU), первые `MaxLights` 64 пишет в буфер кадра `Lights.Srv`
(элемент 0 — число), лишние отбрасывает со счётчиком. Шейдер сцены берёт SRV из своих констант кадра и зовёт `PointLightsDiffuse`
(`common/lights.hlsli`, CPU-эталон — `PointLightMath`) — множитель альбедо.
- Затухание как в UE 5.8: экспонента (1 − saturate(d²/R²))^exp (unitless) или обратный квадрат saturate(1 − (d²/R²)²)² / (d² + 1 см²)
  (канделы); диффуз Ламберта альбедо / π × N·L × цвет × I; за R — 0. Specular нет (у сцены нет шероховатости).
- LF = saturate(A.r + B.r) → к DisabledBrightness 0.5 в последних 20 % FadeDistance (1000 м; 0 — всюду DisabledBrightness); сдвиги по
  времени — на CPU, мип 0; UV — сферические углы направления в осях LF (`LightFunction.Rotation`, по умолчанию — мировые; в буфере —
  обратный кватернион) по осям UE (x, y, z) = SWORD2 (z, −x, y): шов u = 0 | 1 — полуплоскость −Y осей LF, полюса ±Z; только на поверхности
  (не на прозрачном). CPU-эталон выборки — `PointLightMath.LightFunctionSum` по `TextureTexels`.
- `PointLight.VolumetricScattering` (UE `VolumetricScatteringIntensity`, по умолчанию 1) — множитель света для объёмов (дым), без LF; в буфер
  кадра не пишется — его берёт тот, кто рисует объём; в `report.lights` — `volumetricScattering`.
- Пресет `PointLight.Torch` — факел LIVE-2: цвет (1, 0.038, 0), интенсивность 100, экспонента 400, R 20 м, рассеяние в объёмах 0.15, без
  дальности показа.
- GPU `scene.opaque` 1280×720 (RTX 5070): 0 источников — 0.195 мс, 1 — 0.206, 64 — 0.827. Без источников кадр бит в бит прежний.

### Прозрачное и слой ½

Фаза Transparent (только с HDR): `BlendMode.Premultiplied` (One, InvSrcAlpha, альфа так же); проход по сцене —
`Color(SceneColor).Depth(Scene.Depth, DepthAccess.Read).Read(Scene.Depth)` (DEPTH_READ | SRV). Мягкий край — `SceneViewDepth`/`DepthFade`
(`common/gbuffer.hlsli`; k = `TransparencyMath.ViewDepthParams` проекции, конечной и бесконечной). Слой ½ — `RenderFrame.HalfRes`
(`HalfResTransparency`, `common/halfres.hlsl`): `Begin(k)` — проход `transparent.halfres.depth` (глубина ½ D32 — ближайшая в блоке 2×2, цель ½
RGBA16F, очищена нулём), проходы вызывающего в `HalfResTarget.Color`, `Composite()` — `transparent.halfres.composite` в `SceneColor`. Размер
½ = ⌈n/2⌉. Апсемпл — 4 билинейных соседа ½, согласованных по линейной глубине (|Δ| ≤ 5 % глубины пикселя, `DepthTolerance`) с
перенормированными весами; все согласны — ровно билинейный; ни одного — ближайший по глубине. У силуэта это светлый контур в пиксель
вместо ореола. Раз за кадр; `Begin` без `Composite` — исключение; проходы между ними — под слоем, после — поверх. GPU (1280×720):
уменьшение глубины 0.012 мс, композит 0.047 мс. Слой ½ пишет дым модуля огня (проход `fire.smoke`, `game/modules/Sword.Game.Fire.Client`).

### Текстуры и картинки

`Renderer.LoadTexture(path)` (и `(name, Stream)` — файл не из пака) → `GpuTexture`: `.swtex` как есть — R8, RG8, RGBA8, BC1, BC4, BC5, BC7
(`GpuTextureFormat`; sRGB у RGBA8, BC1, BC7 — выборка отдаёт линейное), `Texture2DArray` всех мипов и слоёв в bindless-куче. Заливка
ждёт GPU — на старте модуля, не в кадре; `Dispose` — отложенно, остальные освобождает рендер; живые — `Renderer.Textures`. Нет файла —
`FileNotFoundException`, битый или BCn со стороной не кратной 4 — `InvalidDataException` (с путём). Сэмплеры: s0 clamp, s1 wrap, s3 —
за краем чёрный. BCn железо декодирует не по спецификации D3D (до 6.7/255 от CPU-декода — допуск тестов 1/255 + 3 % размаха опор блока).
Картинки из пикселей (UI, синтетические шумы LF в тестах) — `Renderer.CreateImage` (`GpuImage`: RGBA8, мипы ящичным фильтром или готовой
цепочкой; создание ждёт GPU). Шумы LF берутся и из пака: `LightFunction` принимает и `GpuTexture`, и `GpuImage`.
`Renderer.ReadTexels(path, channel)` / `TextureTexels.Read(поток)` — канал слоя 0, мип 0 несжатой текстуры пака на CPU (линейные, sRGB —
формулой; BCn — ошибка) с билинейной выборкой wrap: CPU-эталоны и отчёты (значение LF кадра у модуля огня).

### Скинированные меши и ассеты

Меш — по пути в паке (`Skinned.LoadMesh(name, path)`), двоичные форматы (`Sword.Engine.Formats`) знает только рендер; пак открывает
рендер при первой загрузке (`ContentLocator`), в журнал (`skin`) — источник и размер. Экземпляр в позе — `Skinned.AddPosed(mesh, model,
world, …)`: модельные матрицы от аниматора, палитру `InverseBind · Model · World` считает рендер; число суставов позы и меша обязано
совпасть. `Add` — палитру заполняет вызывающий (поза привязки). Жёсткое вложение меша без суставов (меч в кисти) — `Skinned.AddRigid(mesh,
world, …)`: палитра из одной матрицы.

### Снимок кадра

`Render(…, FrameCapture)`: цвет (задний буфер), глубина сцены (reversed-Z в 8-битный PNG, ближе — светлее) — итог в `LastCapture`. Кадр
показан, а файл не записался — `CaptureException`. С HDR ещё: `HdrPath` — карта яркости входа тонмапа в ложных цветах (`.hdr.png`) и сырой
half (`.hdr.bin`) → `CaptureResult.Hdr` (экспозиция, максимум, среднее, доля ярче 1, NaN); `BloomPath` — добавка bloom той же шкалой
(`.bloom.png`/`.bin`) → `Hdr.Bloom`; `TransparentPath` — слой ½ до композита (`.transparent.png`/`.bin`, если слой был в кадре) →
`Hdr.Transparent` (размер, яркость, покрытие — средняя альфа); заказанная карта без HDR или bloom в кадре — `CaptureResult.Notes`. Заказ
кадра виден в `RenderFrame.Capture`: модуль кладёт рядом со снимком свои данные (поля огня).
Пиксельные циклы снимка (`Screenshot.Save*`, `Png.Crc32.Update`) — `AggressiveOptimization`: без неё OSR давал 4…5 мс на главном потоке.

### UI-проход и отладочное рисование

UI (`Renderer.Ui`, `UiPass`, `common/ui.hlsl`): создаётся при первом обращении — шрифты `ui/fonts/*.swfont` из пака (или
`RendererOptions.UiFonts` от вызывающего) склеиваются в DEFAULT-кучу; `Add(frame, list, name)` копирует квады `UiDrawList` в кольцо кадра и
регистрирует проход поверх заднего буфера (без очистки) — вызов на отрезок `UiDrawList.Split`, обрезка — `SetScissor`. Проходов — до
`UiPass.MaxPassesPerFrame`; кольцо растёт вдвое, старое освобождается отложенно. Числа для HUD: `LastFenceWaitMs`, `LastRecordMs`,
`Ui.LastQuads`.

Отладка (`Renderer.Debug`, `DebugDraw`, `common/debug.hlsl`): отрезки, капсулы, текст в мире копятся в кольца кадра; `AddPass(frame, target,
viewProj, eye)` рисует накопленное с начала кадра или с отметки (`Mark()` → `AddPass(…, since)`) — у каждого оверлея снимка свой слой;
проходов — до 12 за кадр (слои и экран арены — 7, клиентских модулей — свои), без глубины сцены; текст — UI-проходом по проекции точки. Топология — по конвейеру (`GraphicsPipelineDesc.Lines`).

### Шейдеры и константы

Контракт шейдеров (`ShaderContract`), корневая сигнатура (`RootLayout`) и кеш конвейеров (`PipelineCache`) — здесь, а не в Rhi: их видит игра.
Сигнатура одна: b0 — константы кадра, b1 — вида, b2 — `RootLayout.ConstantCount` корневых констант (меняя число, менять и `pass.hlsli` —
его `#error` это ловит), сэмплеры s0–s3. Непрозрачный конвейер — без смешивания (целочисленные цели его не поддерживают). Ключ конвейера —
описание (`GraphicsPipelineDesc`) и форматы целей прохода (`TargetLayout`, их даёт проход). Корневые константы обнуляются в начале
прохода; слоты внутри прохода — по `ShaderContract.AddSlot`: скин 13–17, сцена арены 8–9, UI 0–8, отладка 0–22, тонмап и bloom — свои
проходы. Константы кадра (`RenderFrame.SetFrameConstants`) проход запоминает при регистрации. Числа, общие для C# и HLSL, объявляются
один раз — в `Contribute` (`#define` того же имени роняет компиляцию); структуры сверяются `ShaderContract.AddSize<T>` и `_Static_assert` в
HLSL, константы кадра — `ConstantBuffer<struct>` с полями строками по 16 байт (иначе `sizeof` не видит упаковку cbuffer). Отказ кадра —
сообщения отладочного слоя D3D12 выводятся сразу (`DrainDebugMessages`). Общие шейдеры — `Shaders/common/`:
`pass.hlsli`, `gbuffer.hlsli` (цели сцены, глубина вида, мягкий край), `lights.hlsli`, `post.hlsl` (bloom, тонмап), `halfres.hlsl`,
`skin.hlsli`, `ui.hlsl`, `debug.hlsl`. Тексты в литералах шейдеров — ASCII (DXC читает ANSI; предупреждение — отказ `verify.ps1`).

### Профайлер и GPU-время

`Renderer.Profiler` (задаёт клиент; по умолчанию `CpuProfiler.Off`): зоны `frame.fenceWait`, `frame.build`, `frame.record` (в ней
`render.<проход>`), `frame.present`, `frame.capture`; ожидания — вида `ProfileZoneKind.GpuWait`. GPU-время: граф ставит таймстемпы вокруг
каждого прохода (с барьерами), кадр — устройство; `Renderer.Gpu` (`GpuFrameTimes`: кадр N − 3, после `WaitForIdle` — последний; 0 Б)
сливается с проходами при выдаче (`GpuFrameTimes.Join` → `RenderPassSummary`); в профайлер — `Renderer.RecordGpu` (зоны `gpu.frame`,
`gpu.<проход>`). Больше 255 проходов в кадре — остальные `Dropped`.

## Настройки

Своих ключей в конфиге нет. Игре — на ходу, со следующего кадра: `Exposure` (0.99) и `Bloom` (вкл, 10, 1) — без пересоздания ресурсов
(выключенный bloom дольше `KeepFrames` кадров освобождает цели пула, включённый снова — создаёт); `Renderer.Hdr` и `SceneColorClear` —
с пересозданием цели `scene.color` (выключенный HDR её освобождает; другое значение очистки — новая цель, прежняя освобождается после
своего кадра). Кривая тонмапа — умолчания UE, не настраивается. В игре — группа F3 «Свет» и
`Sword.exe --tune light.*` (игра, `LightTuning`).

## Зависимости

Rhi (устройство D3D12, DXC), Formats (`.swtex`, меши, шрифты), Content (пак), Ui (списки квадов), Diagnostics (профайлер, журнал).

## Ограничения

- Одна graphics-очередь (GPU-симуляция огня — на ней же): отдельной compute-очереди, межочередных заборов и алиасинга памяти временных
  ресурсов нет.
- Экспозиция фиксированная (без автоэкспозиции и локальной экспозиции); bloom без cross и dirt mask.
- Свет — только диффуз точечных источников (без specular, без теней); LF — мип 0. Игра умножает на ao только рассеянное (небо, контур):
  источники, как и солнце, — прямой свет и на ao не умножаются (как в UE: затенять прямой свет — дело теней), поэтому без теней светят
  и в щели.
- Слой ½ один на кадр (общий для модулей); допуск апсемпла — доля глубины, а не её наклон.
- Материалов секций скина и разрезов нет (Cutting отложен — решение 17); горячей перезагрузки шейдеров нет.
