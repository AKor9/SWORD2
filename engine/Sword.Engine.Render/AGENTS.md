# Sword.Engine.Render — правила

Рендер движка: рендер-граф v0, цели сцены, временные ресурсы, хранилища, скинированные меши, UI-проход, данные для
шейдеров, снимок кадра. Логика — из SWORD (`Sword.Engine/Graphics`, `Sword.Game/Render`), устройство — раздел 6 плана.

- Публичный API — без типов нижних слоёв (Vortice, Rhi, Formats, Content): устройство D3D12 создаёт и держит сам
  `Renderer` (`RendererOptions`: окно, размер, отладочный слой, GPU-валидация, шейдеры), наружу — размер, `Resize`,
  `WaitForIdle`, имя адаптера. Игра строит кадр через `RenderGraph.AddPass`, `RenderPassContext` (`SetPipeline`, `SetConstant`,
  `SetScissor`, `Draw`, `DrawIndexed`), данные `GpuData`, `GpuIndices`, `FrameData<T>`, UI-проход (`Renderer.Ui`) и пути
  ассетов. Проверяет
  `PublicSurfaceTests` (все публичные и защищённые сигнатуры Render и Engine.Client) и
  `CompiledAssemblies_FollowArchitecture` (ссылки собранных сборок).
- Проход — графический (`AddPass`) или вычислительный (`AddComputePass`, dispatch на той же graphics-очереди).
  Он объявляет цели (`Color`, `Depth`), чтения (`Read`) и записи UAV (`Write`) — текстур и буферов; переходы
  состояний и барьеры UAV (одной пачкой на проход), привязку целей, очистку, область вывода, корневую сигнатуру и
  константы кадра ставит граф. Руками их не ставить.
- Ресурсы кадра: импортированные (задний буфер, цели сцены, хранилища `GpuStorage` через `Import`) и временные
  (`CreateTexture`, `CreateBuffer`) из пула: запись пула — на один запрос в кадре, без алиасинга памяти; не выданная
  `TransientPool.KeepFrames` кадров подряд освобождается (после смены размера окна пул не держит старые цели).
  Временный ресурс живёт один кадр; индексы для шейдера — `SrvOf`/`UavOf`.
- Цель цвета и глубина создаются с оптимальным значением очистки (`TextureDesc.ClearColor`/`ClearDepth`, нормали
  сцены — `SceneTargets.NormalClear`, глубина — 0) и чистятся только им: другой цвет — исключение графа, а не
  медленная очистка с предупреждением отладочного слоя.
- Хранилище (`Renderer.CreateStorage`) — буфер, чьё содержимое переживает кадр; `Renderer.ReadStorage` читает его на
  CPU с ожиданием GPU — для тестов, инструментов и агента, не для кадра.
- Экземпляр скинированного меша в позе — `Skinned.AddPosed(mesh, model, world, …)`: модельные матрицы суставов от
  аниматора, палитру `InverseBind · Model · World` считает рендер (обратные bind-матрицы меша наружу не выходят); число
  суставов позы и меша обязано совпасть. `Add` — палитру заполняет вызывающий (поза привязки, статические меши).
- Ассеты представления игра грузит по пути в контенте (`Skinned.LoadMesh(name, path)`), двоичные форматы
  (`Sword.Engine.Formats`) знает только рендер. Пак открывает рендер при первой загрузке (`ContentLocator`); в журнал
  (категория `skin`) — источник и размер меша. Следующий шаг — загрузка по AssetPath/AssetId из общего контента,
  когда его откроет Runtime (точка 1в).
- Порядок проходов — порядок регистрации. Инварианты графа проверяются для всего кадра до первой команды: проход не
  читает ресурс, который в кадре никто не записал (кроме хранилищ), не пишет и не читает один ресурс, у графического
  прохода есть цели, у вычислительного — нет. Нарушение — исключение с именами прохода и ресурса; кадр бросается
  (`GraphicsDevice.AbandonFrame`), следующий начинается чисто.
- Корневые константы обнуляются в начале каждого прохода: слоты разных проходов не пересекаются по построению.
  Внутри прохода слоты делятся по контракту шейдеров (`ShaderContract.AddSlot`): скин — 13–17
  (`SkinnedMeshes`), сцена арены — 8–9 (`ArenaClient`), UI-проход — 0–8 (`UiPass`, свой проход), отладочное рисование —
  0–20 (`DebugDraw`, свой проход: матрица 0–15, глаз 16–18, кольца 19–20).
- UI-проход (`Renderer.Ui`, `UiPass`): создаётся при первом обращении — читает шрифты `ui/fonts/*.swfont` из пака и
  кладёт склеенные таблицы в DEFAULT-кучу; `Add(frame, list, name)` копирует квады `UiDrawList` в кольцо кадра сразу и
  регистрирует проход поверх заднего буфера (без очистки) — вызов на отрезок `UiDrawList.Split`, обрезка —
  `RenderPassContext.SetScissor`. Проходов интерфейса в кадре — до `UiPass.MaxPassesPerFrame`; кольцо растёт вдвое,
  старое освобождается отложенно. Числа кадра для HUD: `LastFenceWaitMs`, `LastRecordMs`, `Ui.LastQuads`.
- Снимок кадра (`Render(…, FrameCapture)`): цвет (задний буфер) и глубина сцены (reversed-Z в 8-битный PNG, ближе —
  светлее; состояние ресурса после копии прежнее) — итог в `LastCapture`. Кадр показан, а файл не записался —
  `CaptureException` (клиент отличает её от ошибки кадра). Диагностический режим (5в): заказ снимка — в
  `RenderFrame.Capture`, игра регистрирует проходы только в этом кадре и отдаёт цели `RenderFrame.CaptureIds` (ID-буфер
  `R32Uint`: PNG для глаз, сырые коды `.bin`, сводка кодов `CaptureResult.Ids` — пикселей и рамка) и
  `RenderFrame.CaptureLayer` (слой `Rgba8`, цвет умножен на альфу — кладётся поверх цвета кадра в свой PNG); не отданное —
  `CaptureResult.Notes`. Код ID-буфера — `SkinnedMeshes.IdOf(владелец, часть)`: владелец — `GpuSkinInstance.Owner`, часть —
  по суставу вершины с наибольшим весом (`SetJointParts`, слот 17, `skin.hlsli` `SkinDominantJoint`/`SkinId`); для точной
  глубины ID-проход рисует тем же вершинным шейдером с тестом «равная проходит» по глубине сцены.
- Отладочное рисование (`Renderer.Debug`, `DebugDraw`, `common/debug.hlsl`, 5в): отрезки, капсулы, текст в мире копятся в
  кольца кадра; `AddPass(frame, target, viewProj, eye)` — проход «всё накопленное поверх цели» (фаза Debug — после сцены и
  интерфейса; цель — задний буфер или слой снимка, `clear` — очистить), до `MaxPassesPerFrame` за кадр; без глубины сцены,
  видимая сторона капсулы — по нормали; текст — UI-проходом по проекции точки. Установившийся кадр — 0 Б.
- Топология — по конвейеру (`GraphicsPipelineDesc.Lines` → список отрезков; граф в начале прохода ставит треугольники).
  Непрозрачный конвейер — без смешивания (целочисленные цели его не поддерживают). Отказ кадра — сообщения отладочного
  слоя D3D12 выводятся сразу (`DrainDebugMessages` в ветке ошибки).
- Контракт шейдеров (`ShaderContract`), корневая сигнатура (`RootLayout`) и кеш конвейеров (`PipelineCache`) — здесь,
  а не в Rhi: их видит игра, а игра видит только Render. Корневая сигнатура одна: b0 — константы кадра, b1 — вида,
  b2 — `RootLayout.ConstantCount` корневых констант, сэмплеры s0–s2; меняя число констант, менять и `pass.hlsli`
  (его `#error` это ловит).
- Ключ конвейера — описание (`GraphicsPipelineDesc`, без типов D3D12) и форматы целей прохода (`TargetLayout`):
  форматы даёт проход, а не вызывающий.
- Константы кадра (`RenderFrame.SetFrameConstants`) запоминает проход при регистрации: проходы до и после вызова
  видят разные константы.
- Общие шейдеры движка — `Shaders/common/` (в выходе `Shaders/common/`): `pass.hlsli` (корневые константы,
  сэмплеры), `gbuffer.hlsli` (чтение целей сцены), `skin.hlsli` (скиннинг, код ID-буфера), `ui.hlsl` (интерфейс: фигуры
  полем расстояний, GPU-векторный текст), `debug.hlsl` (отладочное рисование).
- Числа, которые знают и C#, и HLSL, объявляются один раз — в `Contribute` (C#); `#define` того же имени в HLSL
  роняет компиляцию шейдера.
- Структура, которую читают и C#, и HLSL (вершины, палитры, экземпляры, константы кадра), сверяется с обеих сторон:
  `ShaderContract.AddSize<T>("X_SIZE")` в C# и `_Static_assert(sizeof(X) == X_SIZE, "...")` рядом со структурой
  в HLSL. Константы кадра — `ConstantBuffer<struct>`, поля строками по 16 байт (иначе `sizeof` не видит упаковку
  cbuffer). Тексты в строковых литералах шейдеров — ASCII: DXC получает исходник в ANSI и предупреждает, а любое
  предупреждение шейдера `verify.ps1` считает отказом.

- Профайлер CPU (этап П, точка Па) — `Renderer.Profiler` (задаёт клиент; по умолчанию `CpuProfiler.Off`): зоны
  `frame.fenceWait` (ожидание забора кадра в полёте), `frame.build` (построение кадра игрой), `frame.record` (запись
  графа; в ней `render.<проход>` — номер по имени прохода при первой встрече, словарь без выделений), `frame.present`,
  `frame.capture`. Кадр, брошенный исключением, раскручивает стек до начала `Render` (`Depth`/`UnwindTo`).

Не входит в v0 (раздел 6 плана): отдельная compute-очередь и межочередные заборы (этап 12), алиасинг памяти
временных ресурсов. Ещё не сделано: профайлер GPU по проходам, разрезы и материалы секций скина, горячая перезагрузка
по клавише (`PipelineCache.ReloadStale` есть, вызова нет).

Проверка:
- `tests/Sword.Engine.Render.Tests` (категория Gpu) — граф на настоящем устройстве со слоем отладки и GPU-валидацией:
  цепочка compute → графика → compute через временные текстуры с чтением результата из хранилища, порядок записей UAV,
  пул, инварианты и восстановление после брошенного кадра; любое предупреждение D3D12 — провал. GPU-валидация
  видит ресурс не в том состоянии даже через bindless-кучу: убранный переход в SRV она ловит с именем ресурса.
- `verify.ps1`, шаг `app-smoke` — игра с `--gpu-validation`; итог `--json` содержит `passes` (вид, записи, чтения,
  барьеры, вызовы отрисовки и dispatch каждого прохода), `pipelines`, `pooledResources`; `--shot FILE.png` снимает кадр;
  проход `hud` (UI-проход) нарисовал фигуры и текст. Разбиение UI на вызовы проверяется без GPU
  (`tests/Sword.Engine.Ui.Tests`), сам проход — `UiPassGpuTests` (категории Gpu и Content: нужны видеокарта и пак).
- ID-проход, слой снимка и отладочное рисование капсул — `tests/Sword.Game.Tests/IdBufferGpuTests` (Gpu и Content, GPU-валидация,
  Manny из пака), `verify.ps1` `app-smoke` (`--hold debug_bodies`) и `agent-smoke` (`capture.bundle` с `ids` и `overlays`).
