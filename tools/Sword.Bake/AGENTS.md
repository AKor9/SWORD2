# Пекарня (`Sword.Bake`, `Sword.Bake.Cli`) — правила

Ядро и консоль перенесены из SWORD 2eab13b как есть (раздел 11 плана): логику не менять без решения. Устройство — README.md.

- **Любая ошибка оставляет прежний пак.** Ошибка ассета, отмена, сбой записи — пак не пишется; пак пишется во временный
  файл и подменяет прежний только после успешной записи; ничего не пересобрано — пак не переписывается.
- **Пак — не в корне репозитория.** Пак пекарни SWORD2 — `artifacts/bake/Content.swpak`, временные проекты — во
  временном каталоге: `Content.swpak` в корне или выше exe `ContentLocator` предпочтёт эталонному — игра, тесты Content,
  сценарии фич и реплеи молча получат другой контент.
- Всё, что обработчик читает и пишет, — через `BakeContext` (`InputFile`, `InputDir`, `ContentFile`, `Output`, `OutputDir`):
  иначе актуальность о нём не узнает. Необъявленный выход — ошибка сборки ассета.
- Типы ядра даёт хост: плагин ссылается на `Sword.Bake` с `Private=false` и `ExcludeAssets=runtime`; плагин на другом
  плагине ссылается на него так же и стоит в `plugins` после него (одна копия сборки, один тип у `ctx.Ref<T>`).
- Текстовые файлы проекта (манифесты, `bake.project.json`, `bake.user.json`) пишет `TextFiles`: CRLF у новых, прежние
  окончания у старых.
- Стороны `Neutral`; ссылки — по матрице (`Bake` → Content; `Bake.Cli` → Bake, Content).
- **Ядро форматов не знает** — и в `diff` (новое в SWORD2, Б3): сравнитель формата (`IContentComparer`) живёт в плагине
  формата, ядро выбирает его по расширению. «Равны» — только когда отличаются поля, по устройству незначимые для сверки
  (`.swclip` — `SourceHash`), с пояснением в `note`; остальное должно совпасть точно. Смягчать сверку допусками или
  пропуском полей ради «зелёного» `diff` нельзя — для известных расхождений есть файл ожиданий с причиной.

Проверка: `dotnet test tests/Sword.Bake.Tests`; писатели форматов — `dotnet test tests/Sword.Engine.Formats.Tests --filter
ReferencePakWriters` (нужен эталонный пак); проект — `sword-bake status --json`, `sword-bake pak --verify`; два пака —
`sword-bake diff A B --json` (код 2 — есть неожиданные расхождения); пак проекта `Bake/` с эталоном — `diff
..\Content.reference.swpak ..\artifacts\bake\Content.swpak --expect reference.expect.json` в `Bake/`.

Типичные ошибки:
- «нет сборки …dll — соберите проект плагина (конфигурация X)» — `${config}` в `plugins` — конфигурация exe пекарни;
  собрать плагин той же конфигурации.
- «плагин …: ссылается на плагин X, а стоит в plugins раньше него» — поставить основу раньше надстройки (проект `Bake/`:
  `Sword.Bake.Engine`, затем `Sword.Bake.Game`); «Could not load file or assembly …» — основы нет в `plugins`.
- «ссылка на X: … параметры которого не T» — две копии плагина-основы (ссылка без `Private=false`) или не тот обработчик.
- «список плагинов изменился — откройте проект заново» — плагины грузятся только при открытии проекта.
- «пак не обновлён … прежний пак не тронут» — причина в ассетах: `build --json` → `assets[].error`, `log`.
- `diff`: файлы «отличаются байтами», хотя сравнитель есть, — `diff` запущен вне проекта (`project: null`) или плагин не
  загрузился (`project.problems`); «сравнитель для .X уже есть» — два плагина объявили одно расширение.
