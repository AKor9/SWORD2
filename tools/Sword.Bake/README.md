# Пекарня: ядро `Sword.Bake` и консоль `sword-bake`

Пекарня превращает исходники ассетов в пак `.swpak` (раздел 11 плана). Ядро (`tools/Sword.Bake`) держит проект
(`bake.project.json`), манифесты ассетов (`*.bake.json`), обработчики из плагинов, проверку актуальности и сборку пака со
сведениями о сборке (`.bake/build.json`) и сравнение двух паков (`diff`). Об ассетах игры ядро не знает: встроенный
обработчик — только `file.copy`, обработчики и сравнители форматов движка и игры приходят плагинами
([`Sword.Bake.Engine`](../Sword.Bake.Engine/README.md), затем [`Sword.Bake.Game`](../Sword.Bake.Game/README.md)). Консоль —
`tools/Sword.Bake.Cli` (exe `sword-bake`); проект пекарни SWORD2 — [`Bake/`](../../Bake/README.md); Studio — позже (Б7).

## Устройство ядра

- **Проект** (`BakeProject`) — каталог с `bake.project.json`: `name`, `assets` (каталог манифестов), `pak` (путь пака от
  файла проекта), `roots` (корни исходников `${имя}`), `plugins`, `strictLayout`. Ищется от текущего каталога вверх, в том
  числе в подкаталоге `Bake/`. Корни задаются ещё локально — `bake.user.json` (вне git) и переменные `BAKE_ROOT_ИМЯ`.
- **Манифест** (`AssetManifest`) `<id>.bake.json`: `processor`, `params` (разбор без незнакомых полей — опечатка в имени
  поля — ошибка), `import` (происхождение из `bake.imports.json`), `notes`, `dependsOn`. `ManifestWriter` меняет только
  правленые поля `params` и сохраняет окончания строк файла.
- **Обработчик** (`IAssetProcessor`, база `AssetProcessor<TParams>`): `Id`, `Version`, `ParamsType`, `Parallel`,
  `Incremental`, `CodeAssemblies`, `Process`, `DeclareOutputs`. Ссылка на другую единицу — поле с `[AssetRef]`, чтение —
  `BakeContext.Ref<T>` (тип `T` сверяется с `ParamsType` обработчика цели).
- **Контекст** (`BakeContext`): всё прочитанное — через `InputFile`/`InputDir`/`ContentFile`, всё записанное — через
  `Output`/`OutputDir` во временный каталог сборки; по этим спискам — актуальность и выходы. Необъявленный выход — ошибка.
- **Актуальность** (`Builder.Check`, `CheckPak`) — по `.bake/build.json` текущего пака: отпечаток кода обработчика (ID,
  версия, MVID сборок `CodeAssemblies`), хеш параметров (с корнями и параметрами целей ссылок), входы (размер и время,
  иначе хеш), каталоги-входы (набор файлов), выходы (хеш в оглавлении), зависимости.
- **Сборка** (`Builder.Build`): топологический порядок, по `ядра/2` заданий; актуальные ассеты берутся из прежнего пака;
  пак пишется во временный файл и подменяет прежний только после успешной записи. **Любая ошибка — прежний пак
  нетронут**; ничего не пересобрано — пак не переписывается (игра, держащая его открытым, не получает замену).
- **Каталог контента** (`ContentCatalog`): ассет контента — файлы с общей основой имени или объявленный каталог-набор;
  раскладка (выход в папке своего манифеста, файл — у одной единицы) при `strictLayout` — ошибка ассета.
- **Целостность** (`Builder.Verify`): хеши всех файлов с оглавлением, оглавление против сведений о сборке, ничьих файлов нет.
- **Сравнение паков** (`PakDiff`) — два любых пака, проект не нужен; ниже, «Сравнение паков: `diff`».

## Плагины и их порядок

- `bake.project.json → plugins` — пути сборок от файла проекта; `${config}` — конфигурация хоста (`Debug`/`Release` exe,
  `AssemblyConfiguration`). Плагины грузятся **по порядку списка** в контекст по умолчанию процесса из теневой копии своего
  каталога (`%TEMP%/sword-bake/plugins/<имя>-<хеш>`: исходный каталог свободен, плагин можно пересобрать; копия собирается
  в своём каталоге процесса и переносится на место целиком — параллельные `sword-bake` не пишут в копию, которую другой уже
  читает); обработчики, команды (`IBakeCommand`) и сравнители форматов (`IContentComparer`) находятся рефлексией. Сборку в
  процессе не выгрузить: новый список или пересобранный плагин — при следующем открытии проекта.
- Проект плагина: `EnableDynamicLoading`, выход `bin/<конфигурация>/` без TFM (`AppendTargetFrameworkToOutputPath=false`),
  ссылка на ядро — `Private=false` и `ExcludeAssets=runtime`: типы ядра даёт хост, своей копии у плагина нет.
- **Плагин на другом плагине** (`Sword.Bake.Game` на `Sword.Bake.Engine`) ссылается на него так же, как на ядро, и стоит в
  `plugins` **после** него. Основа к этому времени уже загружена, и ссылка надстройки по имени берёт её из контекста по
  умолчанию: второй копии нет, `ctx.Ref<T>` видит один тип `T`, отпечаток обработчика надстройки включает MVID основы
  (правка основы пересобирает ассеты надстройки). Ядро SWORD так уже работало — загрузчик не менялся; проверка —
  `PluginTests` на тестовых плагинах `tests/Sword.Bake.Tests.PluginA` (основа) и `PluginB` (надстройка: обработчик выведен
  из типа A и читает параметры единицы A).
- **Надстройка раньше основы — ошибка проекта**: плагин, который ссылается на сборку плагина, стоящего в списке позже, не
  регистрирует обработчиков, в `project.problems` — «плагин …B.dll: ссылается на плагин A, а стоит в plugins раньше него —
  поставьте основу раньше надстройки». Проверка по ссылкам сборки, до загрузки типов: надстройка, которая зовёт основу
  только из тел методов, загрузилась бы и в обратном порядке — случайно. Основы нет в списке — «Could not load file or
  assembly '…A…'».

## Консоль `sword-bake`

`sword-bake [--project ПУТЬ] [--json] КОМАНДА …` — проект ищется от `--project` (или текущего каталога) вверх.

| команда | что делает | код выхода |
|---|---|---|
| `init [КАТАЛОГ] [--name ИМЯ]` | создать проект | 0 |
| `build [шаблоны…] [--force] [-j N]` | собрать устаревшие ассеты с зависимостями и записать пак | 0 — пак записан, 1 — нет |
| `status [шаблоны…]` | актуальность ассетов и пака | 0 — пак актуален, 2 — нет |
| `add ID ОБРАБОТЧИК [поле=путь…] [--notes ТЕКСТ]` | манифест нового ассета (исходники не копируются) | 0 |
| `remove ID` | удалить манифест (копия — `.bake/removed/`) | 0 |
| `root ИМЯ ПУТЬ` | локальный корень исходников (`bake.user.json`) | 0 |
| `list [--content]` | проект, корни, плагины, обработчики, команды и сравнители плагинов, ассеты; `--content` — каталог контента | 0 |
| `which ПУТЬ…` | ассет контента по пути в паке: файлы, кто пишет, актуален ли | 0, 1 — не найден |
| `licenses` | импорты по лицензиям | 0 |
| `pak [--verify] [--extract КАТАЛОГ]` | содержимое пака по ассетам; целостность; распаковка | 0, 2 — целостность нарушена |
| `diff A B [--expect ФАЙЛ]` | сравнить два пака (ниже, «Сравнение паков»); проект не нужен | 0 — неожиданных расхождений нет, 2 — есть |
| `КОМАНДА …` | команды плагинов проекта | как у команды |

Шаблон — ID (`anim/1hm_sword`), папка (`anim`), маска (`anim/*_locomotion`), `import:ИМЯ`, `processor:ID` или путь ассета
контента. Ошибка разбора, нет проекта — код 1 и строка `sword-bake: …` в stderr.

**`--json`** (только у `status`, `build` и `diff`; у остальных — ошибка): итог — один JSON-объект одной строкой в stdout,
больше в stdout ничего; коды выхода те же. Общие поля `status` и `build` — `command`, `ok`, `exitCode`, `project` (`name`,
`file`, `assetsDir`, `pak`, `strictLayout`, `plugins[]` с `loaded`, `processors[]`, `problems[]` — плагины, корни, импорты,
`broken[]` — неразобранные манифесты), `pak` (`path`, `status`: `upToDate`/`stale`/`missing`/`error`, `reason`, `details[]`,
`exists`, `bytes`, `builtUtc`).
- `status`: `assets[]` — `id`, `processor`, `status` (`upToDate`, `dirty`, `noSource`, `error`), `reason`; `counts` по статусам;
  `provenance[]` и `layout[]` — замечания (`asset`, `text`).
- `build`: `options`; `assets[]` в порядке очереди — `result` (`built`, `upToDate`, `failed`, `skipped`, `cancelled`), `reason`
  (почему собирался), `error`, `detail`, `seconds`, `warnings[]`, у упавших — `log[]`, у остальных — `logLines`; `summary`;
  `pakWritten`, `pakUnchanged`, `pakFiles`, `pakBytes`; `pak` — актуальность после сборки; `messages[]` — события без ассета
  (`kind`, `text`: запись пака, почему не записан).
- `diff` — ниже, «`diff --json`».
- Ошибка до итога — `{"command":…,"ok":false,"exitCode":1,"error":"…"}`.

## Сравнение паков: `diff`

`sword-bake diff A B [--expect ФАЙЛ] [--json]` (`PakDiff`) — сверка пересобранного пака с эталонным (раздел 11 плана) и
проверка будущих правок обработчиков. Паки не распаковываются и не меняются.

- **Оглавление.** Каждый путь обоих паков — только в A (`onlyA`), только в B (`onlyB`), другой размер (`size`), тот же размер
  и другой хеш (`hash`), одинаковые (`same`). Читаются только файлы с разными хешами, и только когда у их расширения есть
  сравнитель.
- **Сравнители форматов.** Файл с разными хешами идёт сравнителю своего расширения (`IContentComparer` из плагинов
  проекта): «равны по содержимому» (`sameContent`) — не расхождение; «отличаются» — расхождение с его пояснением; сбой
  сравнителя — расхождение с текстом ошибки. Нет сравнителя — «отличаются байтами». Плагины грузит проект: `diff` в проекте
  (`--project` или проект найден от текущего каталога) — сравнители его плагинов; вне проекта — только оглавление и байты.
- **Сведения о сборке** (`.bake/build.json`, когда он есть в обоих паках) — не файлом, а семантически: набор ассетов
  (`asset`) и `processor`; `fingerprint` — только префикс `ID|версия` (сборки и их MVID другие по устройству: деление
  плагинов, Debug ↔ Release); `paramsHash` — сравнивается, с пометкой: в хеш входят корни исходников (`bake.user.json`,
  `BAKE_ROOT_*`), при других корнях он другой и без правки параметров; `inputs` — путь, размер, хеш (время не
  сравнивается); `inputDirs`, `contentInputs` — наборы путей; `outputs` — путь, размер, хеш, а при разных хешах — итог
  сравнения файла (равны по содержимому — не расхождение). `builtUtc`, `bakedUtc` и имя проекта не сравниваются.
  `.bake/build.json` только в одном паке — расхождение файла.
- **Ожидаемые расхождения** — `--expect ФАЙЛ` (ниже): итог делит расхождения на ожидаемые и неожиданные; правило, не
  подошедшее ни к одному расхождению, названо («ожидание не пригодилось», `expectations.unused`) — список устарел.
- **Код выхода:** 0 — неожиданных расхождений нет, 2 — есть, 1 — ошибка (нет пака, пак или сведения о сборке не
  разбираются, ошибка в файле ожиданий, `--project` без проекта).

Пак с самим собой — всё одинаково: `diff Content.reference.swpak Content.reference.swpak` — 1082 файла `same`, сведения о
сборке равны (29 ассетов), код 0, ~0,1 с.

### Сравнитель формата — контракт для плагинов

```csharp
public interface IContentComparer
{
    IReadOnlyList<string> Extensions { get; }   // «.swclip»: с точкой, без учёта регистра
    string Title { get; }                       // «клип: поля без SourceHash» — в итоге diff
    ContentComparison Compare(string path, byte[] a, byte[] b);
}

public readonly record struct ContentComparison(bool Equal, string Detail)
{
    public static ContentComparison Same(string note = "");   // равны: note — что не сравнивалось
    public static ContentComparison Differs(string detail);   // отличаются: первое отличие
}
```

- Реализация — неабстрактный класс с конструктором без параметров в сборке плагина: находится рефлексией при загрузке
  плагина, как обработчики и команды. У расширения — один сравнитель на проект: второй пропущен, причина — в проблемах
  проекта (`project.problems`).
- Вызывается только для файла одного пути с разными хешами оглавления; `a`, `b` — его байты в A и B. Вызовы по одному;
  сравнитель не хранит состояния между вызовами и ничего не пишет.
- `Same(note)` — отличаются только поля, по устройству формата незначимые для сверки (`note` — какие: «без SourceHash»),
  остальное совпало точно; `Differs(detail)` — чем отличаются, первым отличием («повороты: кадр 12, кость 3»). Не
  разбирается — `InvalidDataException`: diff покажет расхождение с текстом ошибки, сравнение остальных файлов идёт дальше.
- Сравнитель `.swclip` (поля клипа без `SourceHash`) — в `Bake.Engine`. Проверка контракта — тестовый сравнитель
  `.skel` плагина `tests/Sword.Bake.Tests.PluginA` (`SkeletonComparer`).

### Файл ожидаемых расхождений

```jsonc
{
  // комментарии и висящие запятые можно
  "expected": [
    { "path": "effects/blood", "expect": "different", "reason": "кровь переделывается (решение 15)" },
    { "path": "anim/*/Old_*.swclip", "expect": "absent", "reason": "…" },
    { "asset": "anim/gasp", "expect": "different", "reason": "…" }
  ]
}
```

- `path` — путь файла пака, `asset` — ID ассета сведений о сборке; ровно одно из двух. Маска — как шаблоны проекта: точный
  путь, папка (всё под ней) или `*` (любые знаки, в том числе `/`); без учёта регистра.
- `expect`: `absent` — только в одном паке (файл; ассет сведений о сборке; у правила `path` — и выход ассета в сведениях о
  сборке); `different` — есть в обоих, но отличается (размер или содержимое файла; у правила `asset` — любое поле записи
  ассета, в том числе вход или выход только в одном паке).
- Выход ассета в сведениях о сборке подходит и под правило `asset` своего ассета, и под правило `path` своего файла.
- `reason` обязательна. Незнакомое поле, оба или ни одного из `path`/`asset`, другое значение `expect` — ошибка разбора
  (код 1). Подходит первое по порядку правило.

### `diff --json`

- `command` = `diff`, `ok` (неожиданных нет), `exitCode`; `a`, `b` — `path`, `files`, `bytes`, `contentHash`, `project` и
  `builtUtc` (из сведений о сборке); `project` — как у `status` (`null` — вне проекта); `comparers[]` — `title`,
  `extensions`, `assembly`; `expectations` — `file`, `rules`, `unused[]` (`null` — без `--expect`).
- `summary` — `same`, `sameContent`, `onlyA`, `onlyB`, `size`, `hash` (файлы, без `.bake/build.json` из обоих паков),
  `buildInfo` (расхождений сведений о сборке), `expected`, `unexpected`.
- Файлы по видам — `onlyA[]`, `onlyB[]`, `size[]`, `hash[]`, `sameContent[]`: `path`, `owner` (ассет по сведениям о сборке
  B, иначе A), `sizeA`, `sizeB`, `hashA`, `hashB`, `comparer`, `detail`, `expected` (причина или `null`). Одинаковые — только
  числом.
- `buildInfo` — `inA`, `inB`, `compared`, `equal`, `assetsA`, `assetsB`, `how`, `differences[]`: `asset`, `field` (`asset`,
  `processor`, `fingerprint`, `paramsHash`, `inputs`, `inputDirs`, `contentInputs`, `outputs`, `version`), `path`, `a`, `b`,
  `detail`, `note`, `expected`.
- `unexpected[]`, `expected[]` — все расхождения одним списком каждое: `source` (`file` | `buildInfo`), `path`, `owner` и
  `kind` у файлов, `asset` и `field` у сведений о сборке, `expect` — вид для правила файла ожиданий, `detail`; у ожидаемых —
  `rule` (`rule` — номер, `path`/`asset`, `expect`, `reason`).

## `.bake/` и где пак

- В каталоге проекта: `.bake/cache.json` — хеши исходников и ошибки последних сборок (только эта машина; потерян —
  пересчитывается), `.bake/removed/` — копии удалённых манифестов. `.bake/` и `bake.user.json` — вне git (`.gitignore`).
- В паке: `.bake/build.json` — `PakBuildInfo` (`engine/Sword.Engine.Content/Pak`), последним файлом: из чего собран именно
  этот пак. Читают пекарня и (позже) редактор F6 (`SingleSourceOf`).
- **Пак пекарни SWORD2 — `artifacts/bake/Content.swpak`, не корень репозитория.** `ContentLocator` предпочитает
  `Content.swpak` эталонному: пак в корне молча подменил бы контент игре, тестам Content, сценариям фич и эталонным
  реплеям. Проект [`Bake/`](../../Bake/README.md) задаёт `"pak": "../artifacts/bake/Content.swpak"`; переключение игры на
  новый пак — отдельным решением. Временные проекты — во временном каталоге.

## Ограничения

- Сравнитель формата есть только у `.swclip` (`Bake.Engine`); остальные форматы в `diff` — побайтно (выпечка на той же
  машине и рантайме детерминирована: полная выпечка `Bake/` совпадает с эталоном байт в байт везде, кроме `SourceHash`
  клипов).
- `diff` сравнивает паки, не каталоги; допуска для float нет (разбор пекарни 3.4: младшие биты могут сдвинуться только
  при смене рантайма — тогда сравнитель формата с допуском).
- У `file.copy` путь в паке по умолчанию — ID ассета без расширения (как в SWORD); другой — полем `to`.
- В выходе плагина лежат копии сборок движка, до которых он достаёт транзитивно (Content, Core, Diagnostics): ядро их
  не берёт — те же сборки хоста загружены раньше.

## Агентский доступ

Итог анализа (раздел 8 плана): пекарня — процесс командной строки, не живой мир, поэтому агентский вид — ключ `--json`,
как у `Sword.Headless --json`; инструмент MCP не нужен. Агент видит и проверяет:
- актуальность — `sword-bake status --json`: что устарело и почему, проблемы проекта и плагинов (загружен ли каждый),
  неразобранные манифесты, происхождение, раскладка, состояние пака;
- сборку — `sword-bake build --json`: что собрано и почему, ошибки ассетов с логом, записан ли пак, актуален ли после;
- пак — `sword-bake pak --verify` (целостность, код 2), `which ПУТЬ` (кто пишет файл), `list --content`;
- два пака — `sword-bake diff A B --json [--expect ФАЙЛ]`: что только в одном, чем отличаются (сравнитель формата или
  байты), сведения о сборке по полям, ожидаемые и неожиданные расхождения, непригодившиеся ожидания; код 2 — есть
  неожиданные;
- писатели форматов — `ReferencePakWritersTests`; сведения о сборке — `PakBuildInfo.Read` на любом паке.

Рецепт — [docs/agent-playbook.md](../../docs/agent-playbook.md), «Пекарня». Сравнитель формата от плагина агент видит в
`diff --json` (`comparers[]`, у файла — `comparer` и `detail`) и в `list`; его тесты — на синтетических паках, как
`DiffTests`.
