# Sword.Game.Cutting — правила

Модуль `cutting` (решение 21), часть симуляции: расчленение. Описание — [README.md](README.md); план —
`artifacts/plans/dismemberment/PLAN.md` (вне git).

- Модуль не видит ядро игры (`Sword.Game`) и другие модули: вход — заявки `SeverRequested` и ресурсы ядра (`TissueProfiles`,
  `IPhysicsWorld` — только чтение), выход — события `LimbDetached`, `PartialCut`. Применяет отделение ядро (`SeverAftermathSystem`):
  модуль тела физики не меняет.
- Решает симуляция, рисует клиент: всё, что меняет исход (отруб, куски, массы), — здесь, в хеше и реплее; меш и крышки —
  `Sword.Game.Cutting.Client` по записям. Номер куска `LimbDetached.Piece` — по кускам бойца и заведённым в тике; ядро не применяет
  событие с чужим номером.
- Физика решений — чистые функции (`SeverPhysics`, `ImpactPhysics`): их проверяют тесты без мира (`SeverTests`).
- Детерминизм: порядок заявок — по `RequestId`, случайное — только `SimRandom`; вытеснение кусков — по `RequestId`, не по
  времени кадра.
- Без модуля игра стартует (решение 9): кода «на случай отсутствия» нет ни в ядре, ни здесь.
- Метод тика с долгим циклом — тело цикла в отдельный метод (OSR).

Проверка: `dotnet build SWORD.slnx`, `dotnet test tests/Sword.Architecture.Tests`, `verify.ps1 -Only without-modules`;
при изменении поведения — `-Only headless-smoke,replay-smoke`.

Типичные ошибки: плоскость отруба в мире, а не в системе тела сегмента (клиент не перестроит меш при перемотке); ответ
на заявку другого тика.
