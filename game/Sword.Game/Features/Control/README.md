# Управление, камера и плавность кадра (точка 1г)

Игрок управляет мечником с клавиатуры и мыши: WASD — ход относительно камеры, Shift — шагом, курсор на земле — куда
смотреть. RTS-камера SWORD: следует за игроком, колесо — зум. Кадр показывает мир между прошлым и последним тиком по
доле тика — движение плавное при любой частоте кадров. Код — `game/Sword.Game.Client/` (`ArenaInput`, `PlayerIntent`,
`Scene/RtsCamera`, `ArenaView`, `ArenaClient`), шаги кадра — `engine/Sword.Engine.Client/` (`FrameInput`,
`InputBindings`, `SimulationClock`, `ClientHost`).

## Откуда логика

SWORD 2eab13b, формулы, константы и порядок те же; отличия отмечены:

| SWORD | SWORD2 |
|---|---|
| `Program.cs`: ввод и камера — до тиков кадра, фокус камеры — таз игрока по `renderAlpha` прошлого кадра (с `Y = 0`); после тиков `renderAlpha = accumulator / TickDt`; камере — сырой `frameDt` | `ClientHost`: `IClientGame.Input` → тики (`SimulationClock`) → `Extract` с `FrameView.Alpha` → `BuildFrame`; камере — сырой шаг кадра. **Отличие:** фокус — корень игрока, показанный прошлым кадром (тел, а с ними таза, ещё нет — этап 5) |
| `RtsCamera.Update`: колесо (без Ctrl) и +/− — `0.88^n` к цели 3…110 м, сглаживание `1 − e^(−12·dt)`; Z/C — 1,8 рад/с; средняя кнопка — поворот 0,006 и наклон 0,004 рад/пиксель, наклон 0,45…1,45; F — за игроком (`1 − e^(−10·dt)`) / свободная; стрелки — панорама `Distance·1,2` м/с в круге 80 м; `SetDistance` — 6…110 м | `Scene/RtsCamera.Update` (управление — `CameraControls` из действий ввода; Ctrl — действие `ui_modifier`); `SetDistance` — для `--camera` |
| `RtsCamera.ScreenToGround`: луч курсора до плоскости y = 0 | `RtsCamera.ScreenToGround` |
| `PlayerController.Think`: WASD по `camera.GroundForward/GroundRight` (камера этого кадра — тики идут после её обновления), Shift — шагом; `HandleInput`: курсор на земле и над окном — точка взгляда, пока не зажата ПКМ (блок) | `PlayerIntent.Command` (направление — в мировых координатах, нормирует симуляция); ПКМ-блока ещё нет |
| `SkinCutPose.DrawnJoints`: `PoseRoot` — `Lerp(prev, cur, α)`, `PoseFacing` — `prev + IEEERemainder(cur − prev, τ)·α`; `DuelArena.KinWorld(root, facing)` — высота `Terrain.Height` под корнем | `ArenaView.Interpolate`, `FighterView.World`, высота — `ArenaTerrain.Height`. Интерполируются корень и курс: `PoseRoot/PoseFacing` SWORD — они же плюс визуальное смещение аниматора, которого ещё нет (этап 2) |
| `Program.Fill`: `Dt` тика, `Time` арены, номер тика (счётчик SWORD начинается с 10), `ActiveUnits`, `Alpha`; `PlayerHpFrac`; тень и кольцо — таз на последнем тике | `ArenaView` снимает шаг, время и номер тика в Extract, `ArenaClient.Constants` — из него. **Отличия:** номер тика — симуляции (с 0), `ActiveUnits` — 0 и `PlayerHpFrac` — 1 (GPU-бойцов и здоровья ещё нет); тень и кольцо — в показанной (интерполированной) точке игрока, иначе кольцо дрожит относительно плавно идущего Manny; игрока нет — кольца нет |

## Устройство

- Действия ввода — `ArenaInput` (имя — ключ конфига, клавиша по умолчанию); привязки — `InputBindings` по секции
  конфига `input`. Игра знает действия, не клавиши (платформа ей не видна по матрице слоёв).
- Кадр: `Input` — камера и команда кадра (`PlayerCommand`); `BeforeTick` — та же команда в каждый тик кадра
  (удерживаемое, раздел 7), нажатия и отпускания — из `TickInput`: ровно в первом тике после кадра, где случились.
- `Extract` — `ArenaView`: бойцы появляются и уходят по экспорту `Added<Fighter>` / `Removed<Fighter>` из очереди кадра — по тикам по порядку, внутри тика уход раньше появления, итог сверяется с миром
  (порядок снятия и добавления в стадиях одного тика двумя очередями не передаётся); их вид — интерполяция корня по доле
  тика; там же снимаются номер тика, время, шаг и корень игрока на тике. `BuildFrame` читает только `ArenaView` и камеру.
- `ArenaView` — мир представления (`RenderWorld` плана) v0: бойцы и их вид. Движкового склада инстансов нет — он
  понадобится, когда появятся другие виды инстансов (тела, обломки, враги своего цвета — этапы 4–5).
- Доля тика: по часам — `accumulator / dt` после тиков кадра (накопитель — в точном шаге `1/tickRate`); при
  `--ticks-per-frame` — 1 (кадр показывает ровно тик); при `--fps N` — повторяемая дробная (шаг кадра задан).

## Настройки

Секция конфига `input` — привязки действий: `move_forward` W, `move_back` S, `move_left` A, `move_right` D, `walk`
Shift, `camera_follow` F, `camera_rotate_left` Z, `camera_rotate_right` C, `camera_zoom_in` Plus, `camera_zoom_out`
Minus, `camera_orbit` MouseMiddle, `camera_pan_up/down/left/right` — стрелки, `ui_modifier` Control (пока удерживается,
колесо не зумит). Значение — точное имя клавиши (`W`, `Shift`, `F1`, `Up`…) или `MouseLeft/MouseRight/MouseMiddle`,
`None` — без привязки. Слои общие: `sword.json`, `sword.user.json`, `SWORD_INPUT_<ДЕЙСТВИЕ>`,
`--set input.<действие>=<клавиша>`; неизвестное действие или клавиша, привязка к Escape (закрывает окно) — ошибка
запуска Sword.exe. Headless секцию пропускает (клиента у него нет), модуль с `Id = input` невозможен.

## Зависимости

`Sword.Engine.Client` (кадр, ввод, `SimulationLink`), `Game.Contracts` (`PlayerCommand`, `Transform`,
`PrevTransform`, `Fighter`, `PlayerTag`), ядро игры (`GameCore` экспортирует `Added/Removed<Fighter>`; прошлый корень
нового бойца равен нынешнему), рельеф (`ArenaTerrain.Height`) — высота тела.

## Ограничения (намеренные, до своих этапов)

- Действий-нажатий в команде игрока ещё нет (WASD, Shift, курсор — уровни; F — камера): защёлка фронтов движка
  (`InputEdges`/`TickInput`, раздел 7 — нажатие ровно одним тиком) готова и проверена, первым её возьмёт удар или
  уклонение (этапы 5–6).
- Высота тела — рельеф под корнем: постановки стоп ещё нет (этап 2).
- Захват курсора ПКМ (блок), панорама краем экрана (в арене SWORD выключена) — со своими фичами. С виджетами
  интерфейса (панели DevTools): в SWORD, пока курсор над окнами интерфейса, ввод игрока не снимается (`HandleInput`
  пропускается), а Ctrl+колесо — масштаб интерфейса. HUD точки 1д окон под курсором не имеет.
- Все бойцы рисуются цветом игрока: других бойцов пока нет (враги и их цвета — этап 4).
- Снимок «прибит» к тику иначе, чем в SWORD (`SWORD_SHOT_PIN`: паркует симуляцию и сажает камеру на цель):
  `--ticks-per-frame` даёт долю тика 1, `--fps` — повторяемую дробную; камера сглаживается по заданному шагу кадра.
- После перетаскивания окна первый кадр догоняет паузу (до 8 тиков, камера — полный шаг), как в SWORD.
- Агентский вид фичи через `IStateContributor.Describe` и манифест `feature.json` — с агентским доступом (точка 1е) и
  реестром манифестов (этап 3).

## Что проверить в игре

Те же пункты — `checklist` в [feature.json](feature.json) (тест `FeatureManifestsTests` сверяет).

1. `Sword.exe` — WASD: Manny бежит относительно камеры (W — от камеры), Shift с WASD — шагом.
2. Курсор над землёй — Manny поворачивается к нему и следит, пока бежит; курсор ушёл с окна — смотрит на прежнюю точку.
3. Колесо — плавный зум ближе/дальше (+/− — то же клавишами; с зажатым Ctrl колесо не зумит); Z/C — поворот камеры,
   WASD идёт за новым поворотом; зажатая средняя кнопка — поворот и наклон мышью.
4. F — камера отпускает игрока, стрелки двигают её; F ещё раз — камера плавно возвращается к игроку.
5. Плавность при любой частоте кадров: `Sword.exe`, `Sword.exe --vsync`, `Sword.exe --max-fps 30`,
   `Sword.exe --max-fps 45` — Manny, кольцо и тень идут ровно, без рывков (при 30 кадрах картинка реже, но не дёргается).

## Агентский доступ

Приёмка (этап 3д) — [feature.json](feature.json): эталон прототипа (запись Sword.exe с клавиатуры) — ввод дал бег, шаг
и взгляд, игрок ушёл из центра; виды — кадры Sword.exe по той же записи (камера SWORD, хеши App совпадают).
`Sword.Headless --feature control` или `feature.verify {"id":"control"}`.

- `Sword.exe --json`: итог — `player` (симуляция на последнем тике; нет игрока — null), `shown` (показанный кадром,
  интерполированный), `camera` (режим, поворот, наклон, дистанция, цель), `input` (привязки), `report.alpha` (доля тика
  последнего кадра).
- `Sword.exe --fps N --frames M --shot F.png` — прогон «как при N кадрах в секунду»: тики и доля тика повторяются;
  снимок с дробной интерполяцией воспроизводим вместе с `--move` (иначе мышь над окном даёт точку взгляда).
- `Sword.exe --hold move_forward,walk …` — действия удерживаются весь прогон (действия, а не клавиши: привязки не
  участвуют; в первом кадре действие ещё и нажато) — управление проверяется без клавиатуры.
- `Sword.exe --max-fps N` — ограничитель кадров: плавность при низкой частоте вживую.
- `verify.ps1` `app-smoke`: прогон с `--hold move_forward` — игрок бежит по `GroundForward` камеры; прогон `--fps 45`
  на 91 кадр — ровно 242 тика, доля тика 2/3, показанный игрок на треть шага тика позади последнего тика.
- Тесты `tests/Sword.Game.Tests/ClientTests.cs`: камера (зум, поворот, орбита, следование, панорама, луч курсора),
  действия → клавиши игрока и управление камерой, WASD по камере, Shift, курсор, бег по W совпадает с направлением
  камеры, интерполяция (корень, курс через ±π, высота), плавность показанного бега при 45, 144 и 37,3 кадрах/с (с
  контролем: без интерполяции — рывки; кольцо — там же, где Manny), бойцы из очереди кадра, порядок их записей в кадре
  из двух тиков (снят и добавлен в разных тиках, на одном барьере, добавлен и снова снят в стадиях одного тика).
  `tests/Sword.Engine.Client.Tests`: привязки по слоям конфига и их ошибки (в том числе «A,B» и «Mouse0»), клавиша по
  умолчанию — ошибка игры, удержание действий, доля тика, заданный шаг кадра — ровно свои тики; фронты до тика
  (`InputEdgesTests`: нажатие в кадре без тиков доходит до первого тика следующего кадра, в кадре из трёх тиков — только
  до первого, тап — нажатие и отпускание одному тику, мышь — так же).

Агент (точка 1е): ввод на ходу — `command.send` (`PlayerCommand` на будущий тик; в тике с командой клавиатуры
побеждает команда агента), пауза и шаги — `time.*`, снимок по запросу — `capture.bundle`; рецепты —
`docs/agent-playbook.md`.
