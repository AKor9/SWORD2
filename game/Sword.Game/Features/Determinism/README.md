# Детерминизм и реплеи (этап 3)

Симуляция воспроизводима: одни команды по тикам дают одно состояние бит в бит. Отсюда реплеи, сверка `Game.App` и
`Game.Headless`, эталоны SWORD2 для регрессий, наблюдение, инварианты, приёмка фич и эксперименты агента (разделы 7, 8 и 12
плана). В игре этап ничего не меняет — проверяется автоматически. Этап сделан (точки 3а–3д); история — точки, перезаписи
эталонов, замеры, анализ по точкам — [docs/history/determinism.md](../../../../docs/history/determinism.md).

## Откуда логика

Новое: в SWORD реплеев и хеша состояния не было. Правила — раздел 7 плана («Детерминизм, реплеи, эталоны»).

## Устройство

### Хеш состояния и ГСЧ

- **Хеш** — `Simulation.HashState(parts)` между тиками, без выделения памяти: хеш каждого участника по Id и итог — хеш
  их хешей. Раунд — как у xxHash64.
- **Участник `ecs`** (Runtime) — всё, что мир переносит из тика в тик: живые сущности по возрастанию индекса (индекс,
  поколение, компоненты по стабильному имени); ресурсы-значения; слоты — поколения свободных и порядок свободных номеров;
  журналы — записи последнего оборота тика с возрастом в барьерах; регистрации систем — включена ли и сколько записей каждого
  журнала не прочла. Номера записей и барьеров не входят: одинаковое состояние после разной истории даёт один хеш. Ресурсы со
  ссылками (пул поз, ассеты) не входят — их состояние у своих участников.
- **Поля, а не байты.** `FieldLayout` один раз на тип строит листья (примитивы, перечисления, `Entity`, встроенные массивы)
  со смещениями, которые считает среда. Хеш и описание идут по одним листьям: padding не участвует, `-0` → `+0`, любой NaN →
  один, bool → 0/1.
- **Участник `animation`** (`Sword.Game.Animation.AnimationState`, регистрирует `GameCore.Configure`): по слотам пула —
  поколение (у свободного — со знаком минус), у живой позы — повороты, смещения и модельные матрицы; порядок свободных слотов,
  задания в очереди. Участник `physics` — фича [«Физика и тела»](../Bodies/README.md).
- **ГСЧ** — ресурс `SimRandom(Seed)`, зерно `sim.seed` (по умолчанию 1): число — чистая функция (зерно, поток, тик,
  сущность, выборка). Потоки игры: `arena.spawn`, `ai.attack`, `combat.hit-react`, `combat.player-pick`.

### Реплеи

- **Реплей** (`Replay`, Runtime) — сборка (версия с коммитом), кто записал, отпечаток пака, частота тиков, зерно, длина,
  итоговый конфиг запуска (`ConfigSet.Effective`), активные и выключенные модули, участники хеша, типы команд с листьями полей
  (`Move.X:f32`), команды по тикам и хеш по участникам на тике 0 и каждые `hashEvery` тиков.
- **Запись** (`Simulation.Record`, только с тика 0) — каждая *выданная* команда тика в `runtime.commands` (из очереди клиента,
  инструментов и реплея, любых зарегистрированных типов). Тики с одинаковым списком команд подряд — один отрезок. Память
  растёт только хешами (8 байт на тик и участника раз в `hashEvery` тиков; куски до 64 КБ). Значения — листьями полей (64 бита
  на лист): файл переживает перестановку полей, поле без значения — ноль и предупреждение.
- **Воспроизведение** (`Simulation.Play`, только с тика 0; симуляция из `Replay.CreateConfig()` — только конфиг записи).
  Команды реплея выдаются в тике первыми, команды клиента и инструментов — после: команда агента перебивает реплей —
  ветвление. Первое расхождение — `ReplayDivergence`: после скольких тиков, последнее совпадение, какие участники.
- **Файл** `.swreplay` — JSON в CRLF: заголовок, по строке на отрезок команд `[первый тик, тиков, [тип, поля…]…]` и на хеш
  `"тик хеш…"`; float — точной записью (`R`), `-0` и не-числа — битами `"0x…"`; запись → чтение → запись — тот же текст. Файл
  без хешей и заголовка — сценарий (хеши ему даёт перезапись).
- **Перемотка** (`time.seek`, `AgentSimulation.Seek`; таймлайн — `Replay.Splice`). Вперёд — тики подряд той же симуляцией
  (таймаут оставляет сыгранное, время сеанса выравнивается). Назад — новая симуляция повторяет таймлайн: запись до прежнего
  тика (с командами агента) и дальше будущее воспроизводимого файла; команды агента на несыгранные тики сбрасываются;
  таймаут назад — сеанс на прежнем тике.
- **Эталоны SWORD2** — `tests/reference/replays/` на эталонном паке, хеш каждый тик: `prototype.swreplay` (бег, диагональ со
  взглядом, шаг, стоп, бег спиной, разворот — 570 тиков), `animation.swreplay` (восемь направлений, бег ↔ шаг, развороты,
  старты и остановки — 750), `enemies.swreplay` (сценарий `crowd-commands` фичи «Враги»: толпа до 32 врагов, команды арены
  по ходу — 3000), `bodies.swreplay` (сценарий `terrain` фичи «Физика и тела»: склон, ступени, ухабы — 2800). Регрессию
  ловит `ReferenceReplaysTests` (тик и участник; все файлы папки). Намеренное изменение поведения — перезапись тех же команд
  `Sword.Headless --replay tests/reference/replays/<файл> --record tests/reference/replays/<файл>` и запись причины в md фичи,
  которая поведение изменила.

Ключи exe:

| exe | ключ | что |
|---|---|---|
| `Sword.exe` | `--record FILE`, `--hash-every K` | записать реплей живой игры (с агентом реплей пишется всегда — `replay.save`) |
| `Sword.exe` | `--replay FILE` | живая игра играет реплей: конфиг реплея (`--set` поверх), команды игрока — его (`ArenaClient(playerCommands: false)`), камера управляется; хеши сверяются (`--json` → `replay`); с `--move/--walk/--gaze/--hold` — ошибка |
| `Sword.Headless` | `--record FILE`, `--hash-every K` | записать прогон |
| `Sword.Headless` | `--replay FILE [--ticks N] [--set …]` | воспроизвести: итог (`--json` → `replay`) — совпал ли, сверено хешей, первое расхождение с участниками; код выхода 3 при расхождении; `--set` поверх — эксперимент (предупреждение) |
| `Sword.Headless` | `--replay A --record B` | перезапись: те же команды, новые хеши (эталон после намеренного изменения; хеши сценария) |

Перед воспроизведением Headless проверяет: модули реплея есть в сборке, пак тот же (иначе — ошибка); другая сборка —
предупреждение (хеши скажут, изменилась ли логика).

### Наблюдение

- **Язык условий** (`ObservationPredicate`, Introspection) — свой типизированный JSON. Узлы: `all/any/not`; сущность —
  `component`, `entity`, `field` + сравнения; мир — `resource`, `sim` (`ticks`, `time`), `stage`, `event` (тип, `where`,
  `atLeast`, `within`), `exists/none/count`, агрегаты `min/max/sum/mean`, `for` (держится N тиков подряд — и внутри `all`/`any`
  при любом порядке узлов). Сравнения: `equals`, `notEquals`, `lessThan`, `lessOrEqual`, `greaterThan`, `greaterOrEqual`,
  `between`, `isFinite`, `isNaN`; перечисление — именем, сущность — `12v3` или именем игры. Компиляция — в точке обслуживания,
  в дерево узлов, читающих листья по смещениям `FieldLayout`; ошибка — с путём в условии; `cost` — узлы и перебор сущностей.
- **Наблюдатели симуляции** (`Simulation.Observe`) — после барьера каждой стадии и после тика; только владелец, только
  чтение, в хеш и реплей не входят. Посреди тика команда — не раньше следующего тика (`NextCommandTick`).
- **История** (`ObservationHistory`) — кольцо 1200 тиков: записи журналов с номером тика и стадией барьера; видны только
  журналы, у которых в мире есть потребитель.
- **Узел наблюдения** (`ObservationHub`, у агента — `AgentHost.Observation`): история, наблюдения `watch.*`, одно условие
  остановки. Условие после тика — `TimeControl.Halt` на тике выполнения (живая игра — `ITickGate.StopAfterTick`); после барьера
  стадии (`time.break`, Headless) — точка обслуживания внутри тика (`SimulationLoop`). Headless подключает узел к каждой
  симуляции сеанса до первого тика.
- **Снимки** (`WorldSnapshot`) — копии байтов компонентов, ресурсов и описания участников (кроме `ecs`) в точке обслуживания;
  `SnapshotDiff` — было → стало, у чисел — разница и допуск. Мир из снимка не восстанавливается (раздел 5).
- **Прогон с наблюдением** (`ReplayObservation`, `replay.observe`) — реплей в отдельной симуляции с тем же узлом, строки — в `.jsonl`.

Номера тиков: у событий `tick` — тик, в котором запись сделана (как у `command.send` и команд реплея); у строк наблюдения,
условий и квитанций `tickId` — сыграно тиков. Посреди тика `tickId` — номер идущего.

### Инварианты

- **Контракт** (`IInvariant`, Runtime): `Id` (части из латиницы, цифр и `_` через точку, первой — строчная буква), `Cost`
  (`InvariantCost`: каждый тик, раз в N тиков, по запросу; `Heavy` — раз в 4 тика в живой игре), `Scope`, `After` — имя стадии,
  после барьера которой проверяется (`runtime.export` — конец тика). `Evaluate(ctx, ref sink)` только читает мир и пишет
  нарушения в `ViolationSink` (не больше 8 подробностей за проверку); без нарушений не выделяет памяти.
- **Регистрация**: базовые инварианты движка — Runtime в каждой симуляции; ядро и модули — `SimulationBuilder.Invariant(…)`
  (владелец — `core` или Id модуля); агент — условием (`invariant.define`, владелец `agent`). Без модуля нет и его инвариантов.
- **Проверка** (`SimulationInvariants`): после барьера своей стадии, до наблюдателей; исключение в проверке — нарушение, а не
  падение тика. Учёт: проверок, нарушений, среднее время, последнее нарушение; кольцо 256 нарушений; журнал — первые 5
  нарушений каждого инварианта.
- **Нарушение** — `InvariantViolation { Id, Tick, Stage, Entity?, Details }`, в `ObservationHistory` — рядом с записями
  журналов своего тика (`events.history`), в `replay.observe` — сводка и строки.
- **Режимы**: `sim.invariants` (по умолчанию `true`); «по запросу» сами не включаются; бенч кадра `Sword.exe --bench` —
  `sim.invariants=false`. Период кодового инварианта действует только в живой игре (`SimulationInvariants.LivePeriods`:
  Sword.exe без `--replay`); тесты, `feature.verify`, Headless (и `--agent`), `--replay` — каждый тик. Включение агентом
  переживает `session.start` и перемотку.
- **Остановка** (`time.breakOnInvariant`): Headless — посреди тика после нарушившего барьера, живая игра — после тика
  нарушения (на время ожидания периоды сняты — проверка каждый тик).
- **Инвариант агента** (`AgentInvariant`) — условие языка наблюдения: `condition` (мир) или `must` (каждая сущность под
  `where`), `after`, `every`; `for` — только при `every` 1. Переносится в новую симуляцию сеанса.

Базовые инварианты (инварианты фич — в их md):

| id | чей | когда | что держится |
|---|---|---|---|
| `ecs.finite` | engine | каждый тик (живая игра — раз в 4), конец тика | числа с плавающей точкой в компонентах живых сущностей и ресурсах-значениях конечны |
| `ecs.entityRefs` | engine | по запросу | поля-сущности указывают на живую сущность или пусты (ссылка на только что умершую бывает законной — поэтому совет) |
| `animation.finite` | core | каждый тик (живая игра — раз в 4), после Animation | у живых поз повороты конечны и единичной длины (‖q‖² − 1 ≤ 10⁻³), смещения конечны; модельные матрицы — производные, не проверяются (положения суставов держат капсулы — `physics.*`, всё — хеш `animation` и эталоны; поворотную часть — её читает только скиннинг — держат только тесты и хеши) |
| `animation.settled` | core | каждый тик, после Animation | очередь заданий пула пуста |
| `animation.pool` | core | каждый тик, после End | свободные слоты не повторяются и не живые, остальные живые, живых — `Count` |
| `animation.owners` | core | каждый тик, после End | у бойца есть поза, `PoseRef` указывает на живую позу, одна поза — у одной сущности |
| `animation.actions` | core (4г) | каждый тик, после End | у бойца не-`Agile` есть слой действий; вес в 0…1, числа конечны; клип задан ⇔ действие идёт; поворот — клипом поворота с растяжением 0,5…1,6; поза слоя живая, своя, не итоговая |
| `locomotion.poses` | locomotion | каждый тик, после End | позы слоя и снимка локомоции живые, свои у каждого бойца, не итоговая поза бойца |

### Приёмка и эксперименты

Логика — `Sword.Engine.Introspection` (`FeatureManifest`, `FeatureVerifier`, `Experiments`, `StageTimer`), инструменты —
`Sword.Engine.Agent` (`FeatureTools`, `ExperimentTools`), exe — `Sword.Headless --feature ID|all` и виды через `Sword.exe --replay`.

- **Манифест** `feature.json` рядом с md фичи (`format: sword-feature`, `version: 1`): `id`, `title`, `doc`, `sourceRoots`,
  `requiredModules`, `scenarios`, `invariants` (id или «префикс.*»), `metrics`, `views`, `budgets`, `checklist` — те же пункты,
  что «Что проверить в игре» md (тест `FeatureManifestsTests`). Разбор строгий: неизвестный ключ, тип, ссылка на
  несуществующий сценарий — ошибка с путём; комментарии `//` можно.
- **Сценарий** — реплей из репозитория (`replay`; хеши сверяются) или команды по тикам (`commands`: `{command, fields, from,
  to}`) на конфиге из кода; `set`, `ticks`. Играется в своей симуляции и записывается (`scenario-<id>.swreplay` в артефактах).
  Проверки `checks` — условия после каждого тика окна `from…to`: `always`, `never`, `eventually`, `atEnd`.
- **Инварианты манифеста** включаются явно (и «по запросу»); нарушение любого включённого — провал; инвариант, который ни разу
  не проверялся или которого нет, — провал.
- **Метрики** — своё число SWORD2 (замер, константа или формула) с допуском: поле сущности (`entity` + `field`; вектор — длина;
  вычисляемые поля игры — `Body.*`) или ресурса (`resource`) после тика `at` или `stat` (`min`/`max`/`mean`) по окну, против
  `expected ± tolerance`; `reference` — откуда ожидание. Ключи `source`, `trace`, `series` — ошибка разбора (решение 14).
- **Бюджеты** — отдельные прогоны сценария как бенч (без инвариантов, записи и сверки хешей, `repeats`, `warmup`): медиана мс
  на тик, мс стадий (`StageTimer`), байты на тик; время систем — отдельный прогон с профайлером (фича
  [«Профайлер»](../Profiler/README.md)). Время проверяется только в Release, байты — всегда.
- **Виды** — `Sword.exe --replay <запись сценария> --ticks-per-frame K --frames N --shot` (K — наибольший делитель тика до 8,
  окно 1280×720 без фокуса, `camera`, `hud`); App сверяет хеши с записью Headless — разошлись, вид провален.
- **Вердикт** — `ok` и провалы словами; отчёт — `report.json`. Мнения агента в нём нет; ослабить манифест можно только
  правкой файла с сообщением пользователю.
- **`experiment.fork`** — база и ветки параллельно, каждая в своей симуляции: `set` — конфиг ветки (с тика 0), `commands` — с
  тика развилки `at` (в том числе ручки — `TuningCommand`), `cut` — команды реплея после `at` не идут. Ветка записывается с
  хешем каждого тика и сравнивается с базой (`ReplayDiff`). **`experiment.compare`** — заголовки, команды, хеши и листья
  описаний разошедшихся участников. **`experiment.sweep`** — комбинации ключей по очереди, повторы: медиана и разброс мс на
  тик, стадии, байты, детерминизм повторов, первое резкое ухудшение масштабирования (реплей — без сверки хешей).

## Настройки

`sim.seed` — главное зерно ГСЧ, пишется в реплей (заголовок и конфиг).
`--hash-every K` у exe — хеш в реплее каждые K тиков (по умолчанию 1: расхождение — с точностью до тика).
`sim.invariants` — кодовые инварианты (по умолчанию `true`).

## Зависимости

`Sword.Engine.Runtime` (хеш, участник `ecs`, ГСЧ, реплеи, конфиг из реплея), `Sword.Engine.Ecs` (обход сущностей и
ячеек без копий — `WorldReader.EntityAt`, `TryRead`, `TryReadResource`), `Sword.Engine.Animation` (`PosePool.HandleAt`,
`FreeSlots`, `GenerationAt`), `Sword.Engine.Agent` (инструменты, `AgentSimulation`), exe (`--record`, `--replay`).

## Ограничения

- Хеш — только между тиками; посреди тика — с `time.break`. Внутреннее состояние систем не хешируется: системы его не
  держат, всё авторитетное — в компонентах, ресурсах или у участников. Очередь команд будущих тиков — вход, а не состояние.
- Стоимость хеша растёт с числом сущностей и поз (обход всех листьев); запись с хешем каждый тик — ≈0,2–0,3 % времени при
  120 тиках в секунду (замер 3б — история). Реплей начинается с тика 0: восстановления мира из снимка нет, перемотка назад —
  пересборка и повтор с начала, её цена растёт с тиком (0,1–0,3 мс на тик).
- Перемотка назад, `session.start`, `replay.check` и останов посреди тика (`time.break`) — только Headless; живая игра пишет
  реплей и играет его с начала (`Sword.exe --replay`). Одно условие остановки за раз; условие проверяется со следующего тика.
- История видит только журналы с потребителем (иначе — ошибка «журнала нет»); немедленные операции до тика 0 попадают в
  первую стадию тика 0.
- Поз без владельца ядро не ищет: модуль, берущий позы из пула, приносит свой инвариант утечки (`locomotion.poses`).
- `ecs.finite` считает NaN и бесконечность ошибкой в любом поле: законную бесконечность пока не выразить (нужна пометка поля).
- В живой игре тяжёлые инварианты — раз в 4 тика: нарушение, которое держится, видно не позже чем через 3 тика, короче 4 тиков
  — может не попасть в проверку (точность даёт Headless). Нарушения `invariant.run` — только в ответе.
- Ключ конфига ветки `experiment.fork` действует с тика 0; ключ, который симуляция не читает (`sim.maxTicksPerFrame`), ветку
  не меняет (тест `Fork_PrototypeReference_DivergesOnExpectedTick`). Ветки — потоки одного процесса: для замеров — `experiment.sweep`.
- Бюджеты: Debug только меряет время; проверка времени — `verify.ps1 -Configuration Release`.
- Виды `feature.verify` снимает Sword.exe той же конфигурации сборки, что Headless; Headless агента (`agent-headless.cmd`) App
  рядом не находит — `feature.verify {views:false}`. Картинки видов сравниваются глазами: эталонных снимков нет.
- Метрики и эталоны — свои числа SWORD2: намеренное изменение поведения — правка ожидания или перезапись эталона с сообщением
  пользователю. Реплей привязан к паку; сборка без модуля реплей с этим модулем не воспроизводит.

## Что проверить в игре

В игре этап почти ничего не меняет: проверяется, что живая игра записывается, запись повторяется без окна и в окне,
а агент (история, инварианты) игру не тормозит. Те же пункты — `checklist` в [feature.json](feature.json).

1. `Sword.exe --record my.swreplay` — побегать (WASD, шаг, взгляд мышью) 10–20 с, закрыть окно. В журнале —
   «записан …: N тиков, хешей N+1»; игра ведёт себя как без ключа (нет рывков и просадок).
2. `Sword.Headless --replay my.swreplay` — в журнале «реплей совпал: сверено хешей N+1», код выхода 0.
3. Поменять в `my.swreplay` одно число в строке команд в середине (например, `1` → `0.5` в `Move`) и повторить п. 2 —
   «расхождение после T тиков (последнее совпадение — после T−1): ecs …», код выхода 3.
4. `Sword.exe --agent` — побегать 10–20 с; движение, анимация и частота кадров — как без агента (агент после каждого
   тика снимает историю событий и проверяет инварианты); в журнале нет строк `[invariant] нарушен …`.
5. `Sword.exe --replay my.swreplay` (запись из п. 1) — Manny сам повторяет всё, что вы делали: клавиатура им не
   управляет, камера — как обычно; после конца записи стоит. В журнале при выходе — «реплей: сверено хешей …» без
   расхождения.

## Агентский доступ

| что | чем агент это видит и проверяет |
|---|---|
| хеш состояния, что участник хеширует | `state.hash`; `state.describe` (у `ecs` — части `slots`, `journal:…`, `system:…`; у `animation` — позы по суставам, `filter` `2v1:foot`; больше 60 тыс. знаков — в файл) |
| детерминизм без агента | `Sword.Headless --json` → `stateHash`; `verify.ps1 headless-smoke` гоняет прогон дважды |
| запись и воспроизведение | `replay.status`, `replay.save`, `session.start {replay, set}`, `replay.check`, `replay.diff {a, b}`; сеанс Headless пишется всегда |
| условие во времени | `time.runUntil {condition, maxTicks}`, `time.break {stage, condition}` (Headless) |
| как менялось, что произошло | `watch.add/list/remove`, `entity.history`, `events.history`, `world.snapshot`, `world.diff`, `world.query {where, aggregate}`, `replay.observe` |
| что должно держаться | `invariant.list` (с `livePeriods` и `every`), `invariant.enable`, `invariant.run`, `invariant.define`, `time.breakOnInvariant`; Headless `--json` → `invariants` |
| принять фичу, «что если» | `feature.list`, `feature.verify {id, views, budgets}` (без агента — `Sword.Headless --feature ID|all`, код 4 — провал); `experiment.fork`, `experiment.compare`, `experiment.sweep` |
| реплей глазами | `Sword.exe --replay FILE` (итог `--json` → `replay`) |
| вернуться назад | `time.seek {tick}` — то же состояние (`state.hash`) |

Рецепты — `docs/agent-playbook.md` («Проверить детерминизм», «Воспроизвести реплей и найти расхождение»); проверка —
`verify.ps1` `agent-smoke`.

## Решения и почему

- Язык условий — свой типизированный JSON, а не подмножество чужого формата: нужны узлы игры и стоимость.
- Хеш и описание — по полям (`FieldLayout`), а не по байтам: padding, `-0` и разные NaN не меняют хеш; файл реплея
  переживает перестановку полей.
- Реплей — только с тика 0 (мир из конфига): мир из снимка не восстанавливается (раздел 5 плана).
- Живая игра с агентом пишет реплей с хешем каждый тик: цена — ≈0,2–0,3 % времени при 120 тиках в секунду (замер 3б — история).
- Тяжёлые инварианты в живой игре — раз в 4 тика, всё остальное (тесты, приёмка, Headless, `--replay`) — каждый тик (решение
  пользователя после Пд: инварианты были ~40 % тика толпы — [история профайлера](../../../../docs/history/profiler.md)).
- Сравнения со SWORD сняты на 7а (решение 14): метрики — только свои числа SWORD2.
