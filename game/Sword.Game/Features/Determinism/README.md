# Детерминизм и реплеи (этап 3)

Симуляция воспроизводима: одни команды по тикам дают одно состояние бит в бит. Отсюда реплеи, сверка `Game.App` и
`Game.Headless`, эталоны SWORD2 для регрессий и эксперименты агента (раздел 7 и 8 плана). В игре этап ничего не меняет —
проверяется автоматически.

## Откуда логика

Новое: в SWORD реплеев и хеша состояния не было. Правила — раздел 7 плана («Детерминизм, реплеи, эталоны»).

## Устройство (3а)

- **Хеш** — `Simulation.HashState(parts)` между тиками, без выделения памяти: хеш каждого участника по Id и итог — хеш
  их хешей. Раунд — как у xxHash64.
- **Участник `ecs`** (Runtime) — всё, что мир переносит из тика в тик: живые сущности по возрастанию индекса (индекс
  и поколение), у каждой — компоненты по стабильному имени; ресурсы-значения по имени; слоты — поколения свободных и
  порядок свободных номеров (от них зависят номера будущих сущностей, как у пула поз); журналы по имени — записи
  последнего оборота тика с возрастом в барьерах (их ещё прочтут системы следующего тика); регистрации систем в
  порядке исполнения — включена ли и сколько записей каждого журнала не прочла. Номера записей и барьеров не входят:
  одинаковое состояние после разной истории даёт один хеш. Ресурсы со ссылками (пул поз, ассеты) не входят: их
  авторитетное состояние — у своих участников; у записи журнала со ссылками хешируется только возраст.
- **Поля, а не байты.** `FieldLayout` один раз на тип строит листья (примитивы, перечисления, `Entity`, встроенные
  массивы) со смещениями — их считает среда (метка в упакованной копии), не раскладка вручную. Хеш и описание идут по
  одним листьям: padding не участвует, `-0` → `+0`, любой NaN → один, bool → 0/1.
- **Участник `animation`** (`Sword.Game.Animation.AnimationState`): по слотам пула — поколение (у свободного — со знаком
  минус), у живой позы — локальные повороты, смещения и модельные матрицы; порядок свободных слотов (номера будущих
  поз), заданий в очереди. Регистрирует ядро (`GameCore.Configure`).
- **ГСЧ** — ресурс `SimRandom(Seed)`, зерно `sim.seed` (по умолчанию 1): число — чистая функция (зерно, поток, тик,
  сущность, выборка). Сейчас игра случайности не использует; первым пользователем будет ИИ врагов (этап 4).

## Устройство (3б)

- **Реплей** (`Replay`, Runtime) — сборка (версия с коммитом), кто записал, отпечаток пака, частота тиков, зерно,
  длина, итоговый конфиг запуска (`ConfigSet.Effective`), активные и выключенные модули, участники хеша, типы команд с
  листьями полей (`Move.X:f32`), команды по тикам и хеш по участникам на тике 0 и каждые `hashEvery` тиков.
- **Запись** (`Simulation.Record`, только с тика 0) берёт каждую *выданную* команду тика в `runtime.commands` — из
  очереди клиента, инструментов и реплея, любых зарегистрированных типов (игрок, арена, ручки, модули — без правок
  при появлении новых). Тики с одинаковым списком команд подряд — один отрезок: удержание клавиши — одна строка файла и
  ни байта памяти на команды. Память растёт только хешами: 8 байт на тик и на каждого участника раз в `hashEvery` тиков
  (при двух участниках и хеше каждый тик — 24 Б/тик); хранятся кусками до 64 КБ — без копирования при росте и мимо кучи
  больших объектов. Значения — листьями полей по `FieldLayout` (64 бита на лист), а не сырыми байтами: файл
  переживает перестановку полей, поле без значения — ноль и предупреждение.
- **Воспроизведение** (`Simulation.Play`, только с тика 0; симуляция собрана из `Replay.CreateConfig()` — только
  конфиг записи, без файлов и переменных этой машины). Команды реплея выдаются в тике первыми, команды клиента и
  инструментов того же тика — после: где действует последняя команда своего типа, команда агента перебивает реплей —
  ветвление. Хеши сверяются по участникам; первое расхождение — `ReplayDivergence`: после скольких тиков, последнее
  совпадение (расхождение возникло между ними; при хеше каждый тик — ровно в тике `tick − 1`), какие участники.
- **Файл** `.swreplay` — JSON в CRLF: заголовок, по строке на отрезок команд `[первый тик, тиков, [тип, поля…]…]` и
  на хеш `"тик хеш…"`. float — точной записью (`R`), `-0` и не-числа — битами `"0x…"`; запись → чтение → запись дают
  тот же текст. Файл без хешей и заголовка — сценарий: команды по тикам, конфиг — значения в коде; хеши ему даёт
  перезапись.
- **Таймлайн** (`Replay.Splice`) — перемотка назад во время воспроизведения: сыгранное — из записи, будущее — из файла.
- **Перемотка** (`time.seek`, `AgentSimulation.Seek`). Вперёд — тики подряд той же симуляцией; таймаут оставляет
  сыгранное (сеанс на паузе там, куда дошёл, — тик в ошибке; время сеанса выравнивается по симуляции). Назад — новая
  симуляция повторяет таймлайн: запись до прежнего тика (с командами агента) и дальше будущее воспроизводимого файла.
  Прежнее будущее после перемотки повторяется (свои команды его ветвят); команды агента на ещё не сыгранные тики
  остаются у прежней симуляции — сбрасываются. Таймаут назад — сеанс остаётся на прежнем тике.
- **Эталоны SWORD2** — `tests/reference/replays/prototype.swreplay` (бег, диагональ со взглядом, шаг, стоп, бег спиной,
  разворот на месте — 570 тиков), `animation.swreplay` (восемь направлений, бег ↔ шаг, развороты, старты и остановки,
  шаг со взглядом — 750 тиков), с приёмки этапа 4 `enemies.swreplay` (сценарий `sword-crowd` фичи «Враги»: толпа до 32
  врагов, команды арены по ходу — PageUp, PageDown, 16, R, 32; колонна — 3000 тиков) и с приёмки этапа 5 `bodies.swreplay`
  (сценарий `terrain` фичи «Физика и тела»: игрок один — склон, ступени вверх бегом и вниз шагом, стойка на ярусе, ухабы —
  2800 тиков) на эталонном паке, хеш каждый тик.
  Регрессию ловит тест `ReferenceReplaysTests` (тик и участник; все файлы папки). Намеренное изменение поведения — перезапись тех же команд с новыми хешами
  `Sword.Headless --replay tests/reference/replays/<файл> --record tests/reference/replays/<файл>` и запись причины в md
  фичи, которая поведение изменила. Перезаписи: точка 4а — новые регистрации ядра (команды арены), участник `animation`
  и траектория игрока совпали тик в тик, причина — [«Враги»](../Enemies/README.md), раздел «Эталоны и хеши»; точка 5а —
  новый участник `physics` и `BodyRef` у бойцов (все три эталона), участник `animation` и траектории всех бойцов совпали
  тик в тик со сборкой `41ed2dc` — [«Физика и тела»](../Bodies/README.md), раздел «Эталоны и хеши».

Ключи exe:

| exe | ключ | что |
|---|---|---|
| `Sword.exe` | `--record FILE`, `--hash-every K` | записать реплей живой игры (с агентом реплей пишется всегда — `replay.save`) |
| `Sword.Headless` | `--record FILE`, `--hash-every K` | записать прогон |
| `Sword.Headless` | `--replay FILE [--ticks N] [--set …]` | воспроизвести: итог (`--json` → `replay`) — совпал ли, сверено хешей, первое расхождение с участниками; код выхода 3 при расхождении; `--set` поверх — эксперимент (предупреждение) |
| `Sword.Headless` | `--replay A --record B` | перезапись: те же команды, новые хеши (эталон после намеренного изменения; хеши сценария) |

Перед воспроизведением Headless проверяет: модули реплея есть в сборке, пак тот же (иначе — ошибка); другая сборка —
предупреждение (хеши скажут, изменилась ли логика).

## Устройство (3в)

- **Язык условий** (`ObservationPredicate`, Introspection) — свой типизированный JSON (открытый вопрос плана решён: не
  подмножество чужого формата — нужны узлы игры и стоимость). Узлы: `all/any/not`; сущность — `component`, `entity`,
  `field` + сравнения; мир — `resource`, `sim` (`ticks`, `time`), `stage`, `event` (тип, `where` на поля записи,
  `atLeast`, `within` — окно тиков), `exists/none/count`, агрегаты `min/max/sum/mean`, `for` (держится N тиков подряд;
  серии всех окон обновляются каждое вычисление до корня — `all`/`any`, остановившиеся на соседнем узле, окно не
  пропускают, порядок узлов не важен; `replay.observe` вычисляет условие и до `from`).
  Сравнения: `equals`, `notEquals`, `lessThan`, `lessOrEqual`, `greaterThan`, `greaterOrEqual`, `between`, `isFinite`,
  `isNaN`; перечисление — именем, сущность — `12v3` или именем игры. Компиляция — в точке обслуживания, в дерево узлов,
  которые читают листья полей из байтов мира по смещениям `FieldLayout` (как хеш); ошибка — с путём в условии. Условие
  на сущность наверху — «есть такая сущность». Стоимость (`cost`) — узлы и перебор сущностей.
- **Наблюдатели симуляции** (Runtime): `Simulation.Observe` — после барьера каждой стадии и после тика; только владелец,
  только чтение, в хеш и реплей не входят (тест). Посреди тика команда — не раньше следующего тика (`NextCommandTick`).
- **История** (`ObservationHistory`) — кольцо 1200 тиков: после тика записи журналов этого тика (возраст 1…число
  стадий) с номером тика и стадией барьера. Без своего курсора и подписки — мир от неё не зависит; поэтому видны только
  журналы, у которых в мире есть потребитель.
- **Узел наблюдения** (`ObservationHub`, у агента — `AgentHost.Observation`): история, наблюдения `watch.*` (строки
  полей сущностей по `tickId`), одно условие остановки. Условие после тика — `TimeControl.Halt` на тике выполнения;
  живая игра спрашивает `ITickGate.StopAfterTick` после каждого тика кадра — встаёт на своём тике. Условие после
  барьера стадии (`time.break`, Headless) — точка обслуживания прямо внутри тика (`SimulationLoop`), пока время не
  разрешит идти дальше. Headless подключает узел к каждой симуляции сеанса до первого тика — и повтор перемотки назад
  попадает в историю.
- **Снимки** (`WorldSnapshot`): копии байтов компонентов, ресурсов и описания участников хеша (кроме `ecs`) в точке
  обслуживания; плоский вид `12v3/Transform/Position.X` — на потоке агента; `SnapshotDiff` — было → стало, у чисел —
  разница и допуск. Не сериализация: мир из снимка не восстанавливается (раздел 5).
- **Прогон с наблюдением** (`ReplayObservation`, `replay.observe`): реплей в отдельной симуляции с тем же узлом —
  события, строки наблюдения, переходы условия; строки — в `.jsonl`.

Номера тиков: у событий `tick` — тик, в котором запись сделана (как у `command.send` и команд реплея); у строк
наблюдения, условий и квитанций `tickId` — сыграно тиков (состояние после тика). Посреди тика `tickId` — номер идущего.

## Устройство (3г)

- **Контракт** (`IInvariant`, Runtime): `Id` (части из латиницы, цифр и `_` через точку, первой — строчная буква:
  `ecs.finite`, `fighter.deadNotKinematic`), `Cost` (`InvariantCost`: каждый тик, раз в N тиков, по запросу), `Scope`
  (сущность, система, подсистема, мир, клиент — для людей и агента), `After` — **имя стадии** (стадии мира — строки;
  отдельного `StageId` нет), после барьера которой проверяется; `runtime.export` — конец тика. `Evaluate(ctx, ref sink)`
  только читает мир (`InvariantContext`: мир, тик, стадия, шаг) и пишет нарушения в `ViolationSink` — не больше 8
  подробностей за проверку, остальные только считаются. Без нарушений проверка не выделяет памяти.
- **Регистрация**: Runtime заводит базовые инварианты движка в каждой симуляции, ядро и модули —
  `SimulationBuilder.Invariant(…)`/`Invariants(…)` (владелец — `core` или Id модуля); агент — условием
  (`invariant.define`, владелец `agent`). Без модуля нет и его инвариантов.
- **Проверка** (`SimulationInvariants`, `Simulation.Invariants`): после барьера своей стадии, до наблюдателей
  (`ISimulationObserver.OnViolation` получает нарушение до `AfterStage` этого барьера); хук барьера ставится, только если
  есть включённые инварианты или наблюдатели. Исключение в проверке — нарушение («исключение в проверке: …»), а не
  падение тика. Учёт: проверок, нарушений, среднее время проверки (`Stopwatch`), последнее нарушение; кольцо последних
  256 нарушений; журнал — первые 5 нарушений каждого инварианта (дальше — `invariant.list`, `events.history`).
- **Нарушение** — `InvariantViolation { Id, Tick, Stage, Entity?, Details }`: `Tick` — номер тика, в котором нарушено
  (как у событий). В `ObservationHistory` — рядом с записями журналов своего тика (`events.history`, тип
  `InvariantViolation`; посреди тика — и нарушения идущего тика), в `replay.observe` — сводка и строки.
- **Режимы**: `sim.invariants` (по умолчанию `true`) — кодовые инварианты включены; «по запросу» сами не включаются.
  Тесты, `verify` и игра — включены; бенч кадра `Sword.exe --bench` — `sim.invariants=false` (стоимость меряется
  отдельно, `--set` перекрывает). Включение агентом (`invariant.enable`) переживает `session.start` и перемотку.
- **Остановка** (`time.breakOnInvariant`, `ObservationHub.ArmInvariant`): Headless встаёт посреди тика после
  нарушившего барьера (та же точка обслуживания, что у `time.break`), живая игра — после тика нарушения. Одно условие
  остановки за раз, как у `runUntil`/`break`.
- **Инвариант агента** (`AgentInvariant`, Introspection) — условие языка 3в: `condition` (условие мира должно держаться)
  или `must` (условие на каждую сущность под `where`; без `where` — у кого есть компоненты из `must`), `after`, `every`.
  `for` — только при `every` 1. Переносится в новую симуляцию сеанса.

Базовые инварианты:

| id | чей | когда | что держится |
|---|---|---|---|
| `ecs.finite` | engine | каждый тик, конец тика | числа с плавающей точкой в компонентах живых сущностей и ресурсах-значениях конечны |
| `ecs.entityRefs` | engine | по запросу | поля-сущности указывают на живую сущность или пусты (ссылка на только что умершую бывает законной, пока система её не сняла, — поэтому совет, а не правило тика) |
| `animation.finite` | core | каждый тик, после Animation | у живых поз повороты конечны и единичной длины (‖q‖² − 1 ≤ 10⁻³), смещения и модельные матрицы конечны |
| `animation.settled` | core | каждый тик, после Animation | очередь заданий пула пуста: задание после `core.animation-tick` ждало бы тика |
| `animation.pool` | core | каждый тик, после End | свободные слоты не повторяются и не живые, остальные живые, живых — `Count` |
| `animation.owners` | core | каждый тик, после End | у бойца есть поза, `PoseRef` указывает на живую позу, одна поза — у одной сущности |
| `animation.actions` | core (4г) | каждый тик, после End | у бойца не-`Agile` есть слой действий (`AnimatorAction` и `ActionPoses`); вес в 0…1, числа конечны; клип задан ⇔ действие идёт; поворот — клипом поворота с растяжением 0,5…1,6; поза слоя живая, своя, не итоговая |
| `locomotion.poses` | locomotion | каждый тик, после End | позы слоя и снимка локомоции живые, свои у каждого бойца, не итоговая поза бойца |

## Устройство (3д)

Приёмка фичи (раздел 12 плана) — машинный манифест `feature.json` рядом с md фичи и `feature.verify`, эксперименты —
ветки реплея и перебор конфига. Логика — `Sword.Engine.Introspection` (`FeatureManifest`, `FeatureVerifier`,
`Experiments`, `StageTimer`), инструменты — `Sword.Engine.Agent` (`FeatureTools`, `ExperimentTools`), exe —
`Sword.Headless --feature ID|all` и виды через `Sword.exe --replay`.

- **Манифест** (`format: sword-feature`, `version: 1`): `id`, `title`, `doc`, `sourceRoots` (есть ли код), `requiredModules`
  (активны в сценариях), `scenarios`, `invariants` (id или «префикс.*»), `metrics`, `views`, `budgets`, `checklist` —
  те же пункты, что «Что проверить в игре» md (тест `FeatureManifestsTests`). Разбор строгий: неизвестный ключ, тип,
  ссылка на несуществующий сценарий — ошибка с путём. Комментарии `//` можно.
- **Сценарий** — реплей из репозитория (`replay`; хеши в нём — сверяются) или команды по тикам (`commands`:
  `{command, fields, from, to}` — как `command.send`, тики `from…to−1`) на конфиге из кода; `set` — ключи поверх, `ticks`.
  Каждый сценарий играется в своей симуляции построителя exe и **записывается** (`scenario-<id>.swreplay` в артефактах —
  его играет вид App и можно открыть `session.start`). Проверки `checks` — условия языка 3в после каждого тика в окне
  `from…to` (`tickId`): `always`, `never`, `eventually`, `atEnd`.
- **Инварианты**: инварианты манифеста включаются явно (и «по запросу»), нарушение **любого** включённого — провал
  сценария; инвариант манифеста, который ни разу не проверялся или которого нет, — провал.
- **Метрики** — значение поля сущности (путь к нескольким листьям — длина вектора: `RootVelocity.Value` — скорость) после
  тика `at` (по умолчанию последнего) или `min/max/mean` по окну, против `expected ± tolerance`; источник — `sword`
  (константа или трасса SWORD 2eab13b) или `sword2` (замер SWORD2 на момент манифеста). Ряд против трассы: `trace` —
  файл `{ticks:[{tick, ключ: число | [числа]}]}`, `series` — ключ трассы → поле; сравнение в float, допуск 0 — побитово.
- **Бюджеты** — отдельные прогоны сценария как бенч: без инвариантов, записи и сверки хешей (`Replay.Head(…, hashes:
  false)`), `repeats` раз, первые `warmup` тиков — прогрев; медиана мс на тик, мс стадий (`StageTimer`: от барьера до
  барьера — системы стадии, барьер и проверки после него; профайлера систем ещё нет), байты на тик. Время проверяется
  только в оптимизированной сборке (Release; в Debug — только замер), байты — всегда.
- **Виды** — `Sword.exe --replay <запись сценария> --ticks-per-frame K --frames N --shot` (K — наибольший делитель тика
  до 8, окно 1280×720 без фокуса, `camera` — неподвижный ракурс, `hud`); App сверяет хеши с записью Headless — вид
  провален, если они разошлись. Так «App и Headless на одном реплее дают одинаковые хеши» проверяется у каждой фичи.
- **Вердикт** — `ok` и провалы словами (что, где, значение); отчёт — `report.json`. Мнения агента в нём нет: только
  манифест, инварианты и эталоны; ослабить манифест можно только правкой файла с сообщением пользователю.
- **`Sword.exe --replay FILE`** — живая игра играет реплей: конфиг реплея (`--set` поверх), команды игрока — его
  (клиент своих команд игрока не ставит: `ArenaClient(playerCommands: false)`), камера управляется; хеши сверяются
  (итог `--json` → `replay`, в журнале при выходе — «реплей: сверено хешей …»). С `--move/--walk/--gaze/--hold` —
  ошибка.
- **`experiment.fork`** — база (реплей как есть) и ветки параллельно, каждая в своей симуляции до `ticks`: `set` —
  конфиг ветки (действует с тика 0: конфиг собирает симуляцию), `commands` — с тика развилки `at` и позже (перебивают
  команды реплея своего типа в своих тиках — как `command.send`), `cut` — команды реплея после `at` не идут
  (`Replay.Head`). Ветка записывается с хешем каждого тика и сравнивается с записью базы (`ReplayDiff`): команда тика
  `at` меняет состояние после `at+1` тиков. **`experiment.compare`** — два прогона: заголовки, команды, хеши и листья
  описаний (`state.describe`) разошедшихся участников на первом разошедшемся хеше. **`experiment.sweep`** — комбинации
  ключей по очереди, повторы: медиана и разброс мс на тик, стадии, байты, хеш итога и одинаков ли он у повторов,
  первое резкое ухудшение масштабирования (время растёт больше чем в 1,5 раза быстрее числового ключа). Реплей
  сценария играется без сверки хешей (`Replay.Head(…, hashes: false)`, как бюджеты): иначе в мс на тик попадал бы хеш
  каждого тика, и только у комбинации с конфигом реплея.

## Настройки

`sim.seed` — главное зерно ГСЧ, пишется в реплей (заголовок и конфиг).
`--hash-every K` у exe — хеш в реплее каждые K тиков (по умолчанию 1: расхождение — с точностью до тика).

## Зависимости

`Sword.Engine.Runtime` (хеш, участник `ecs`, ГСЧ, реплеи, конфиг из реплея), `Sword.Engine.Ecs` (обход сущностей и
ячеек без копий — `WorldReader.EntityAt`, `TryRead`, `TryReadResource`), `Sword.Engine.Animation` (`PosePool.HandleAt`,
`FreeSlots`, `GenerationAt`), `Sword.Engine.Agent` (инструменты, `AgentSimulation`), exe (`--record`, `--replay`).

## Ограничения

- Хеш — только между тиками (в точке обслуживания или владельцем симуляции); посреди тика — с `time.break` (3в).
- Внутреннее состояние систем (поля классов систем) не хешируется: правило — системы его не держат, всё авторитетное —
  в компонентах, ресурсах или у участников. Состояние самого мира помимо данных (свободные номера, журналы, курсоры,
  включённость систем) хешируется участником `ecs`. Очередь команд будущих тиков — вход, а не состояние: в реплей
  попадают выданные команды каждого тика.
- Стоимость хеша растёт с числом сущностей и поз (обход всех листьев); реплей хеширует каждые `--hash-every` тиков.
  Замер Release (Headless, игрок и пул поз, 20 000 тиков): без записи — 0,025 мс/тик и 0 Б/тик; запись с хешем
  каждый тик — +0,015…0,026 мс/тик (≈0,2–0,3 % времени при 120 тиках в секунду) и 23 Б/тик (сами хеши); с
  `--hash-every 8` — +0,009 мс/тик и ≈3 Б/тик (кусок 64 КБ раз в ~22 000 тиков). Поэтому живая игра с агентом пишет с хешем каждый тик.
- Реплей начинается с тика 0 (мир из конфига): восстановления мира из снимка нет (раздел 5 плана), поэтому перемотка
  назад — пересборка и повтор с начала, её цена растёт с тиком (0,1–0,3 мс на тик).
- Останов посреди тика (`time.break`) — только Headless: тик живой игры идёт внутри кадра рендера. `time.runUntil` с
  условием в живой игре встаёт на своём тике (между тиками).
- История видит только журналы с потребителем: событие, которое никто в мире не читает, журнала не имеет (записи не
  хранятся) — `events.history` и `{event:…}` для него ошибка «журнала нет». Команды игрока, `Added/Removed<Fighter>`
  (экспорт клиенту) видны. Немедленные операции перед тиком (наполнение мира до тика 0) попадают в первую стадию тика 0.
- Одно условие остановки за раз: новое `runUntil {condition}`, `time.break` или `time.breakOnInvariant` заменяет
  прежнее; условие проверяется, начиная со следующего тика (уже выполненное — не повод не играть).
- Поз без владельца ядро не ищет: модули держат свои позы в своих компонентах (`LegacyLocomotionState.Layer`/`From`),
  поэтому утечку позы ловит инвариант того, кто её взял (`locomotion.poses` — у локомоции). Модуль, берущий позы из
  пула, приносит такой инвариант сам.
- `ecs.finite` считает NaN и бесконечность ошибкой в любом поле: компонент, которому бесконечность нужна законно
  (например, «ещё не было»), пока так не выразить — понадобится пометка поля.
- `time.breakOnInvariant` в живой игре встаёт после тика нарушения, а не посреди тика (как `time.break`).
- Нарушения `invariant.run` — только в ответе: в кольцо, историю и счёт нарушений идут нарушения тиков.
- Стоимость инвариантов (Release, эталонный пак, игрок — 3 позы по 161 суставу): все включённые ≈10 мкс/тик
  (≈0,13 % секунды при 120 Гц; Headless 20 000 тиков — 0,028 → 0,03–0,037 мс/тик), 0 Б/тик. Из них `animation.finite`
  ≈8 мкс — чтение ≈11 тыс. чисел поз (векторный проход по битам экспоненты упирается в память), `ecs.finite` ≈1,5 мкс,
  остальные — меньше 0,6. Растёт с числом поз и сущностей: при десятках бойцов дорогие можно перевести в «раз в N
  тиков» или выключить конфигом. Итог Headless `--json` → `invariants.microseconds` — среднее по каждому.
- Перемотка назад, `session.start` и `replay.check` — только в Headless (симуляцию пересобирает `AgentSimulation` с
  построителем exe); живая игра пишет реплей (`replay.save`, `replay.status`) и играет его с начала
  (`Sword.exe --replay`), но не перематывает.
- Ручек (`TuningGroup`, изменение на ходу командой) ещё нет (этап 5): ветки `experiment.fork` отличаются командами и
  конфигом, а ключ конфига действует с тика 0 — «сменить ручку с тика T» пока нельзя. Ключ, который симуляция не
  читает (`sim.maxTicksPerFrame` — клиентский), ветку не меняет вовсе (тест `Fork_PrototypeReference_DivergesOnExpectedTick`).
- Ветки `experiment.fork` — потоки одного процесса (план: отдельные процессы): симуляции независимы, общие только
  неизменяемые ассеты; мс на тик веток мерится параллельно и для сравнения не годится — для замеров `experiment.sweep`
  (по очереди).
- Бюджеты фич: Debug только меряет время (сравнивать с пределом бессмысленно); проверка времени —
  `verify.ps1 -Configuration Release`. Время стадий — без профайлера систем: какой системе принадлежит время внутри
  стадии, не видно.
- Виды `feature.verify` снимает Sword.exe той же конфигурации сборки, что Headless (`game/Sword.Game.App/bin/<конфигурация>`);
  Headless агента, собранный `agent-headless.cmd` в свой каталог, App рядом не находит — виды проваливаются с причиной,
  `feature.verify {views:false}` — без них. Картинки видов сравниваются глазами: эталонных снимков нет.
- Метрики `sword2` — замер SWORD2 на момент манифеста: намеренное изменение поведения — правка ожидания в манифесте
  (с сообщением пользователю), как перезапись эталонного реплея.
- Реплей привязан к паку: запись на другом паке не воспроизводится (хеши бессмысленны). Сборка без модуля реплей с этим
  модулем не воспроизводит.

## Что проверить в игре

В игре этап почти ничего не меняет: проверяется, что живая игра записывается, запись повторяется без окна и в окне,
а агент (история, инварианты) игру не тормозит. Те же пункты — `checklist` в [feature.json](feature.json).

1. `Sword.exe --record my.swreplay` — побегать (WASD, шаг, взгляд мышью) 10–20 с, закрыть окно. В журнале —
   «записан …: N тиков, хешей N+1»; игра ведёт себя как без ключа (нет рывков и просадок).
2. `Sword.Headless --replay my.swreplay` — в журнале «реплей совпал: сверено хешей N+1», код выхода 0.
3. Поменять в `my.swreplay` одно число в строке команд в середине (например, `1` → `0.5` в `Move`) и повторить п. 2 —
   «расхождение после T тиков (последнее совпадение — после T−1): ecs …», код выхода 3.
4. `Sword.exe --agent` — побегать 10–20 с; движение, анимация и частота кадров — как без агента (агент после каждого
   тика снимает историю событий и проверяет инварианты); в журнале нет строк `[invariant] нарушен …`.
5. `Sword.exe --replay my.swreplay` (запись из п. 1) — Manny сам повторяет всё, что вы делали: клавиатура им не
   управляет, камера — как обычно; после конца записи стоит. В журнале при выходе — «реплей: сверено хешей …» без
   расхождения.
