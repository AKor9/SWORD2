# Детерминизм и реплеи

Симуляция воспроизводима: одни команды по тикам дают одно состояние бит в бит. Отсюда реплеи, сверка `Game.App` и
`Game.Headless`, эталоны SWORD2 для регрессий, инварианты (разделы 7 и 12 плана). В игре фича ничего не меняет — проверяется автоматически. История — перезаписи
эталонов, замеры, анализ — [docs/history/determinism.md](../../../../docs/history/determinism.md).

## Откуда логика

Новое: в SWORD реплеев и хеша состояния не было. Правила — раздел 7 плана («Детерминизм, реплеи, эталоны»).

## Устройство

### Хеш состояния и ГСЧ

- **Хеш** — `Simulation.HashState(parts)` между тиками, без выделения памяти: хеш каждого участника по Id и итог — хеш
  их хешей. Раунд — как у xxHash64.
- **Участник `ecs`** (Runtime) — всё, что мир переносит из тика в тик: живые сущности по возрастанию индекса (индекс,
  поколение, компоненты по стабильному имени); ресурсы-значения; слоты — поколения свободных и порядок свободных номеров;
  журналы — записи последнего оборота тика с возрастом в барьерах; регистрации систем — включена ли и сколько записей каждого
  журнала не прочла. Номера записей и барьеров не входят: одинаковое состояние после разной истории даёт один хеш. Ресурсы со
  ссылками (пул поз, ассеты) не входят — их состояние у своих участников.
- **Поля, а не байты.** `FieldLayout` один раз на тип строит листья (примитивы, перечисления, `Entity`, встроенные массивы)
  со смещениями, которые считает среда. Хеш и описание идут по одним листьям: padding не участвует, `-0` → `+0`, любой NaN →
  один, bool → 0/1.
- **Участник `animation`** (`Sword.Game.Animation.AnimationState`, регистрирует `GameCore.Configure`): по слотам пула —
  поколение (у свободного — со знаком минус), у живой позы — повороты, смещения и модельные матрицы; порядок свободных слотов,
  задания в очереди. Участник `physics` — фича [«Физика и тела»](../Bodies/README.md).
- **ГСЧ** — ресурс `SimRandom(Seed)`, зерно `sim.seed` (по умолчанию 1): число — чистая функция (зерно, поток, тик,
  сущность, выборка). Потоки игры: `arena.spawn`, `ai.attack`, `combat.hit-react`, `combat.player-pick`.

### Реплеи

- **Реплей** (`Replay`, Runtime) — сборка (версия с коммитом), кто записал, отпечаток пака, частота тиков, зерно, длина,
  итоговый конфиг запуска (`ConfigSet.Effective`), активные и выключенные модули, участники хеша, типы команд с листьями полей
  (`Move.X:f32`), команды по тикам и хеш по участникам на тике 0 и каждые `hashEvery` тиков.
- **Запись** (`Simulation.Record`, только с тика 0) — каждая *выданная* команда тика в `runtime.commands` (из очереди клиента,
  инструментов и реплея, любых зарегистрированных типов). Тики с одинаковым списком команд подряд — один отрезок. Память
  растёт только хешами (8 байт на тик и участника раз в `hashEvery` тиков; куски до 64 КБ). Значения — листьями полей (64 бита
  на лист): файл переживает перестановку полей, поле без значения — ноль и предупреждение.
- **Воспроизведение** (`Simulation.Play`, только с тика 0; симуляция из `Replay.CreateConfig()` — только конфиг записи).
  Команды реплея выдаются в тике первыми, команды клиента — после. Первое расхождение — `ReplayDivergence`: после скольких тиков, последнее совпадение, какие участники. Сведения реплея
  (`SimulationBuilder.ReplayFact`: производное контента и конфига вне хеша — отпечаток базы Motion Matching `locomotion.base`) — в
  заголовке (`facts`; нет сведений — ключа нет, заголовок прежний); другое значение при воспроизведении — предупреждение и вероятная
  причина в расхождении (`ReplayDivergence.Cause`).
- **Файл** `.swreplay` — JSON в CRLF: заголовок, по строке на отрезок команд `[первый тик, тиков, [тип, поля…]…]` и на хеш
  `"тик хеш…"`; float — точной записью (`R`), `-0` и не-числа — битами `"0x…"`; запись → чтение → запись — тот же текст. Файл
  без хешей и заголовка тоже читается (хеши ему даёт перезапись).
- **Эталоны SWORD2** — `tests/reference/replays/` на паке игры `Content.swpak` (пекарня; в заголовке — его хеш контента), хеш каждый тик: `prototype.swreplay` (бег, диагональ со
  взглядом, шаг, стоп, бег спиной, разворот — 570 тиков), `animation.swreplay` (восемь направлений, бег ↔ шаг, развороты,
  старты и остановки — 750), `enemies.swreplay` (фича «Враги»: толпа до 32 врагов, команды арены
  по ходу — 3000), `bodies.swreplay` (фича «Физика и тела»: склон, ступени, ухабы — 2800). Регрессию
  ловит `ReferenceReplaysTests` (тик и участник; все файлы папки). Намеренное изменение поведения — перезапись тех же команд
  `Sword.Headless --replay tests/reference/replays/<файл> --record tests/reference/replays/<файл>` и запись причины в md фичи,
  которая поведение изменила.

Ключи exe:

| exe | ключ | что |
|---|---|---|
| `Sword.exe` | `--record FILE`, `--hash-every K` | записать реплей живой игры |
| `Sword.exe` | `--replay FILE` | живая игра играет реплей: конфиг реплея (`--set` поверх), команды игрока — его (`ArenaClient(playerCommands: false)`), камера управляется; хеши сверяются (`--json` → `replay`); с `--move/--walk/--gaze/--hold` — ошибка |
| `Sword.Headless` | `--record FILE`, `--hash-every K` | записать прогон |
| `Sword.Headless` | `--replay FILE [--ticks N] [--set …]` | воспроизвести: итог (`--json` → `replay`) — совпал ли, сверено хешей, первое расхождение с участниками; код выхода 3 при расхождении; `--set` поверх — эксперимент (предупреждение) |
| `Sword.Headless` | `--replay A --record B` | перезапись: те же команды, новые хеши (эталон после намеренного изменения) |

Перед воспроизведением Headless проверяет: модули реплея есть в сборке, пак тот же (иначе — ошибка); другая сборка —
предупреждение (хеши скажут, изменилась ли логика).

### Инварианты

- **Контракт** (`IInvariant`, Runtime): `Id` (части из латиницы, цифр и `_` через точку, первой — строчная буква), `Cost`
  (`InvariantCost`: каждый тик или раз в N тиков; `Heavy` — раз в 4 тика в живой игре), `Scope`, `After` — имя стадии,
  после барьера которой проверяется (`runtime.export` — конец тика). `Evaluate(ctx, ref sink)` только читает мир и пишет
  нарушения в `ViolationSink` (не больше 8 подробностей за проверку); без нарушений не выделяет памяти.
- **Регистрация**: базовые инварианты движка — Runtime в каждой симуляции; ядро и модули — `SimulationBuilder.Invariant(…)`
  (владелец — `core` или Id модуля). Без модуля нет и его инвариантов.
- **Проверка** (`SimulationInvariants`): после барьера своей стадии; исключение в проверке — нарушение, а не
  падение тика. Учёт: проверок, нарушений, среднее время, последнее нарушение; кольцо 256 нарушений; журнал — первые 5
  нарушений каждого инварианта.
- **Нарушение** — `InvariantViolation { Id, Tick, Stage, Entity?, Details }`: кольцо последних нарушений и журнал; итог
  Headless `--json` → `invariants`.
- **Режимы**: `sim.invariants` (по умолчанию `true`); бенч кадра `Sword.exe --bench` —
  `sim.invariants=false`. Период кодового инварианта действует только в живой игре (`SimulationInvariants.LivePeriods`:
  Sword.exe без `--replay`); тесты, Headless, `--replay` — каждый тик.

Базовые инварианты (инварианты фич — в их md):

| id | чей | когда | что держится |
|---|---|---|---|
| `ecs.finite` | engine | каждый тик (живая игра — раз в 4), конец тика | числа с плавающей точкой в компонентах живых сущностей и ресурсах-значениях конечны |
| `animation.finite` | core | каждый тик (живая игра — раз в 4), после Animation | у живых поз повороты конечны и единичной длины (‖q‖² − 1 ≤ 10⁻³), смещения конечны; модельные матрицы — производные, не проверяются (положения суставов держат капсулы — `physics.*`, всё — хеш `animation` и эталоны; поворотную часть — её читает только скиннинг — держат только тесты и хеши) |
| `animation.settled` | core | каждый тик, после Animation | очередь заданий пула пуста |
| `animation.pool` | core | каждый тик, после End | свободные слоты не повторяются и не живые, остальные живые, живых — `Count` |
| `animation.owners` | core | каждый тик, после End | у бойца есть поза, `PoseRef` указывает на живую позу, одна поза — у одной сущности |
| `animation.actions` | core | каждый тик, после End | у бойца не-`Agile` есть слой действий; вес в 0…1, числа конечны; клип задан ⇔ действие идёт; поворот — клипом поворота с растяжением 0,5…1,6; поза слоя живая, своя, не итоговая |
| `locomotion.poses` | locomotion | каждый тик, после End | позы слоя и снимка локомоции живые, свои у каждого бойца, не итоговая поза бойца |

## Настройки

`sim.seed` — главное зерно ГСЧ, пишется в реплей (заголовок и конфиг).
`--hash-every K` у exe — хеш в реплее каждые K тиков (по умолчанию 1: расхождение — с точностью до тика).
`sim.invariants` — кодовые инварианты (по умолчанию `true`).

## Зависимости

`Sword.Engine.Runtime` (хеш, участник `ecs`, ГСЧ, реплеи, конфиг из реплея), `Sword.Engine.Ecs` (обход сущностей и
ячеек без копий — `WorldReader.EntityAt`, `TryRead`, `TryReadResource`), `Sword.Engine.Animation` (`PosePool.HandleAt`,
`FreeSlots`, `GenerationAt`), exe (`--record`, `--replay`).

## Ограничения

- Хеш — только между тиками. Внутреннее состояние систем не хешируется: системы его не
  держат, всё авторитетное — в компонентах, ресурсах или у участников. Очередь команд будущих тиков — вход, а не состояние.
- Стоимость хеша растёт с числом сущностей и поз (обход всех листьев); запись с хешем каждый тик — ≈0,2–0,3 % времени при
  120 тиках в секунду (замер — история). Реплей начинается с тика 0: восстановления мира из снимка нет; живая игра пишет
  реплей и играет его с начала (`Sword.exe --replay`).
- Поз без владельца ядро не ищет: модуль, берущий позы из пула, приносит свой инвариант утечки (`locomotion.poses`).
- `ecs.finite` считает NaN и бесконечность ошибкой в любом поле: законную бесконечность пока не выразить (нужна пометка поля).
- В живой игре тяжёлые инварианты — раз в 4 тика: нарушение, которое держится, видно не позже чем через 3 тика, короче 4 тиков
  — может не попасть в проверку (точность даёт Headless).
- Эталоны — свои хеши SWORD2: намеренное изменение поведения — перезапись эталона с сообщением пользователю. Реплей привязан к паку; сборка без модуля реплей с этим модулем не воспроизводит.

## Что проверить в игре

В игре этап почти ничего не меняет: проверяется, что живая игра записывается, запись повторяется без окна и в окне.

1. `Sword.exe --record my.swreplay` — побегать (WASD, шаг, взгляд мышью) 10–20 с, закрыть окно. В журнале —
   «записан …: N тиков, хешей N+1»; игра ведёт себя как без ключа (нет рывков и просадок).
2. `Sword.Headless --replay my.swreplay` — в журнале «реплей совпал: сверено хешей N+1», код выхода 0.
3. Поменять в `my.swreplay` одно число в строке команд в середине (например, `1` → `0.5` в `Move`) и повторить п. 2 —
   «расхождение после T тиков (последнее совпадение — после T−1): ecs …», код выхода 3.
4. `Sword.exe --replay my.swreplay` (запись из п. 1) — Manny сам повторяет всё, что вы делали: клавиатура им не
   управляет, камера — как обычно; после конца записи стоит. В журнале при выходе — «реплей: сверено хешей …» без
   расхождения.

## Решения и почему

- Хеш и описание — по полям (`FieldLayout`), а не по байтам: padding, `-0` и разные NaN не меняют хеш; файл реплея
  переживает перестановку полей.
- Реплей — только с тика 0 (мир из конфига): мир из снимка не восстанавливается (раздел 5 плана).
- Реплей с хешем каждый тик (`--hash-every` 1 по умолчанию): цена — ≈0,2–0,3 % времени при 120 тиках в секунду (замер — история).
- Тяжёлые инварианты в живой игре — раз в 4 тика, всё остальное (тесты, Headless, `--replay`) — каждый тик (решение
  пользователя: инварианты были ~40 % тика толпы — [история профайлера](../../../../docs/history/profiler.md)).
- Сравнения со SWORD сняты (решение 14): эталоны — только свои хеши SWORD2.
